## 1. 本書の目的

### 1.1 目的

本書は、システム要求仕様「性能・品質・耐久性」を基本設計へ展開し、Tank_Robot全体に共通する性能配分、評価条件、資源余裕、長時間・繰返し動作、機械・電気・熱・ソフトウェア耐久性、評価結果の管理および未確定値の扱いを定める。

### 1.2 対象範囲

本書では、次を基本設計段階で明確にする。

- システム全体の時間性能および測定区間
- 複数機能が同時動作した場合の性能維持方針
- CPU、RAM、stack、通信buffer、message queue、Security固定資源等の余裕
- 使用環境、標準評価条件、走行路面、転倒・軽微衝突等の評価条件
- 長時間動作および繰返し動作の利用モデル
- 走行、砲塔・砲身、電源、通信、永続データ、OTA、工場初期化の耐久評価基準
- 指挟み、巻込み、鋭利部、小部品脱落を含む機械安全の評価方針
- software concurrency、invalid input、評価用buildを含む堅牢性評価
- 実機評価で確定する値の管理方法
- 評価結果、不合格、再試験および基本設計へのフィードバック方法

詳細なtest procedure、治具、測定器型式、試験データ様式、個別test caseの全件展開は後続の評価仕様・テスト設計で定める。

本書は各機能固有の制御値・安全判定値を重複して所有しない。走行制御値は走行制御基本設計、砲塔・砲身制御値と安全可動範囲は砲塔・砲身制御基本設計、停止・緊急停止および操作指令タイムアウトは停止・緊急停止管理基本設計、電気安全値はバッテリー・電気安全監視基本設計、表示反映値は状態表示・利用者通知基本設計、時刻trustは時刻管理基本設計に従う。機能ごとの一連の更新処理は、それぞれのデータ管理機能が管理する。本書は、それらを組み合わせた**システム全体の合否条件、評価条件、資源余裕、耐久回数、測定品質および基本設計へのフィードバック規則**を横断的に管理する。

本書で定める標準評価条件、性能配分、CPU/RAM/stack/queue余裕、長時間利用モデル、試作耐久回数、測定精度、機械安全の初期評価条件、バッテリー駆動・待機目標等は、公開要求値そのものではない場合でも評価確定待ちを含む基本設計で管理する値である。実機評価で変更が必要な場合は詳細な試験仕様だけで変更せず、本書または値を管理する関連基本設計へ結果を戻す。

実機・結合・耐久評価による成立確認および一部物理条件の数値確定は未完了である。

### 1.4 関連する基本設計と本書の責任分界

本書が他基本設計の値を評価条件として引用しても、値の意味・変更責任は引用元の基本設計へ残す。

例として、状態表示・利用者通知のSafety表示50 ms、走行制御/砲塔・砲身制御の10 ms制御、停止・緊急停止管理の300 ms操作指令timeout、バッテリー・電気安全監視の電気安全threshold、セキュリティ管理のSecurity resource上限は本書で評価するが、本書だけで値を変更しない。

停止については、停止・緊急停止管理の`T_CTRL_*`を制御側停止取引の管理元で定める値として引用し、本書は車体実速度零までの`T_PHYS_*`と停止距離の初期評価基準を所有する。走行制御は減速率・停止方式を所有する。同じ数値であっても測定終了点が異なるmetricを同一視しない。

## 2. 性能値の管理区分

性能値は次の4区分で管理する。

| 区分 | 意味 | 変更方法 |
| --- | --- | --- |
| 上位要求値 | 公開用システム要求仕様「22. 性能・品質・耐久性」または他の公開要求で規定済みの値 | 基本設計だけで変更しない。必要なら公開要求へ正式feedback |
| 関連基本設計で管理する値 | 停止・緊急停止管理/走行制御/砲塔・砲身制御/セキュリティ管理/状態表示・利用者通知等が具体化・所有する値 | 本書は横断評価に使用するが、変更はその事項を定める基本設計へ戻す |
| 本書の基本設計初期値 | 公開用システム要求仕様「22. 性能・品質・耐久性」が後続具体化を求め、本書が試作開始条件として採用する値 | 実機不成立時は詳細試験だけで緩和せず本書を改訂 |
| 評価確定待ち | 質量、重心、機構寸法、部品定格等の現物情報が必要な値 | 根拠取得後に本書またはその事項を定める基本設計へ反映するまで未確定 |

過去の作業用要求値を、現在の公開要求値として復活させない。本書が採用する試作値は、公開要求が具体化を求めた項目に対する基本設計初期値として扱う。

## 3. 性能・品質の優先原則と最大想定負荷

### 3.1 Safety優先

公開用システム要求仕様「22. 性能・品質・耐久性」に従い、安全監視、操作指令timeout、停止、E-STOP、電源保護、SystemMonitorおよび異常時Safety処理を、ログ、通常表示、Wi-Fi、VPS、診断、設定、OTA、暗号等の非Safety関連処理より優先する。

最大負荷で通常性能を維持できない場合もSafety期限を遅らせて通常機能を維持しない。非Safety処理を延期、抑制、Backpressureまたは中止し、Safety処理の時間・資源を確保する。

### 3.2 最大想定負荷の初期組合せ

単一機能の軽負荷だけで合格としない。少なくとも次の競合を評価する。

- 走行＋砲塔旋回＋砲身上下＋BLE継続操作
- 上記＋状態表示／STATUS_SUMMARY
- Wi-Fi/VPS通信＋TLS/暗号＋ログ保存＋状態表示
- 設定機能側での更新確定または永続書込み＋通常操作
- OTA download/hash/OSPI/MRAM＋Safety/Control
- OWNER/GENERAL登録時の認証用の証明データ＋通常Safety監視
- BatterySafety＋Drive/Turret＋SystemMonitor＋通信burst
- 通常停止／E-STOP／危険電気事象と非Safety処理の同時発生
- low-power復帰中のBLE wake＋Safety監視＋表示復帰

最大想定負荷の詳細scenarioはテスト設計で固定するが、Safety/Controlと重いService処理を分離した軽い条件だけへ置換しない。

## 4. 使用環境および標準評価条件

### 4.1 上位要求値

通常使用環境は屋内、水濡れなし、結露なし、著しい粉じんなしとする。

公開用システム要求仕様「22. 性能・品質・耐久性」の暫定要求範囲を使用する。

- 周囲温度：10 ℃以上35 ℃以下
- 相対湿度：20 %RH以上80 %RH以下
- 結露なし

これらは暫定要求範囲であり、本書だけで狭めない。

### 4.2 標準評価条件

比較基準として次を使用する。

- 周囲温度：23 ℃±5 ℃
- 相対湿度：30 %RH以上70 %RH以下
- 結露なし
- 走行床面：乾燥した水平かつ平坦な木質床、樹脂系床または同等の屋内硬質床面
- 段差：5 mm以下を初期通常使用評価範囲
- 傾斜：5°以下を初期通常使用評価範囲

5 mmまたは5°を超える条件は、実機評価で範囲を改訂するまで通常使用性能の成立範囲として扱わない。

### 4.3 機体質量・搭載物・重心

`M_STD`、`M_MAX`、`PAYLOAD_MAX`、`CG_ENVELOPE`は現物情報なしに推測しない。完成構成の実測質量、battery/PCB/motor/servo/外装配置、搭載物、転倒・制動・旋回・傾斜・servo動作時の安定性、最大負荷を取得後に基本設計へ戻して確定する。

未確定の間、最大質量条件での停止距離、傾斜、耐久、熱を最終保証済みとしない。

### 4.4 合理的に予見可能な転倒・軽微衝突の初期条件

公開用システム要求仕様「22. 性能・品質・耐久性」 `SYS-QUAL-123`および22.15項目3を無条件にテスト設計へ先送りしないため、試作開始時の初期評価条件を次とする。

**転倒**
- 標準機体構成、battery搭載、可動部を通常許可範囲内とする。
- 平坦な標準評価床上で、通常静置姿勢から前・後・左・右の各方向へ自重で倒れる代表条件を評価する。
- 高所から落下させる試験とはしない。

**軽微衝突**
- 標準評価床上で0.20 m/s ±10 %を初期衝突速度とする。
- 前面および左右代表方向を、鋭利部のない固定平面障害物へ接触させる。
- 完成機の通常最低／最高速度または質量条件から0.20 m/sが「軽微」として不適切であることが判明した場合、本書へ評価結果を戻して条件を改訂する。

転倒・軽微衝突後は、外観だけで合格とせず、battery固定、配線、電源、E-STOP、主電源、drive/servo output禁止、通常起動、Safety監視、走行停止および可動部を再確認する。

階段、机、棚その他の高所からの落下は通常使用として保証せず、当該場所で使用しないことを利用上の制限として維持する。

## 5. 通常操作・表示および操作指令監視

### 5.1 総合操作応答

公開用システム要求仕様「22. 性能・品質・耐久性」の上位要求値を合否基準とする。

- smartphone上の有効な走行・砲塔旋回・砲身上下操作開始 → 対応アクチュエータ出力更新開始：150 ms以内
- 利用者が連続操作終了 → 当該操作終了をアクチュエータ出力へ反映：150 ms以内

総合時間はsmartphone入力、BLE送受信・認証検証、本体dispatch、制御周期待ち、出力反映を含む。

走行制御の本体内走行応答、砲塔・砲身制御の10 ms制御／20 ms PWM等の機能内値を用い、全体150 msを侵食しないことを結合評価する。走行指令のvalidated ingressはBLE接続・認証経由であるが、本体制御の受付・出力判断は走行制御が担当する。

### 5.2 継続操作指令

停止・緊急停止管理で確定した現行値を使用する。

- 走行継続指令：基本送信周期50 ms
- 砲塔旋回継続指令：基本送信周期50 ms
- 操作指令timeout：最後の有効受信から300 ms

300 msの最終判定主体は、停止・緊急停止管理とする。無効、旧、重複、未認証、権限不足のメッセージ、または対象の制御機能が有効指令として受理しなかったメッセージによって、タイムアウト監視を延長しない。

### 5.3 状態表示・通知の横断性能

状態表示・利用者通知の現行基本設計で管理する値を結合評価する。

| 対象 | 現行値 |
| --- | ---: |
| 通常本体RGB/7seg | 提供元での情報確定→論理表示出力更新開始 200 ms以内 |
| power danger / E-STOP本体表示 | 提供元での情報確定→論理表示出力更新開始 50 ms以内 |
| 認証済みBLE STATUS_SUMMARY | 提供元での情報確定→送信開始 500 ms以内 |
| スマートフォンアプリの現在状態のデータモデル | 正常接続条件で提供元での情報確定→App反映 1.0 s以内 |

表示は実際の停止・電源保護より低優先であり、表示完了をSafety成立条件にしない。一方、実際のSafety処理と同時発生した場合でも状態表示・利用者通知の表示上限を満たすかを最大負荷試験で確認する。

## 6. 停止性能

### 6.1 上位要求値

| 対象 | 測定区間 | 上位要求値 |
| --- | --- | ---: |
| 通常停止・安全停止 | 本体が有効な停止要求／条件を検出 → 走行停止出力更新開始 | 100 ms以内 |
| 本体E-STOP | 本体側E-STOP入力変化検出 → 走行停止出力または駆動出力無効化開始 | 50 ms以内 |
| smartphone E-STOP | 利用者のE-STOP操作 → 本体の走行停止出力または駆動出力無効化開始 | 150 ms以内（暫定要求値） |
| 本体受信後E-STOP | 本体が有効なE-STOP要求受信 → 走行駆動出力無効化開始 | 50 ms以内 |

### 6.2 試作評価用の初期停止基準

停止・緊急停止管理で定める制御側停止処理の評価指標を、比較・相関のため次に引用する。

| 制御側の評価指標 ID | 開始点 | 終了点 | 停止・緊急停止管理の所有値 |
| --- | --- | --- | ---: |
| `T_CTRL_NORMAL_STOP_TX_MAX` | 停止・緊急停止管理が有効な通常停止要求を受け付け、通常停止取引を開始 | 停止・緊急停止管理が必要な制御側局所結果を集約して通常停止取引を完了 | 500 ms |
| `T_CTRL_SAFE_STOP_TX_MAX` | 停止・緊急停止管理が安全停止条件を確定し、安全停止取引を開始 | 停止・緊急停止管理が走行および砲塔・砲身の必要な制御側局所結果を集約して安全停止取引を完了 | 300 ms |
| `T_CTRL_ESTOP_TX_MAX` | 停止・緊急停止管理が有効な緊急停止要求の成立を確定し、緊急停止取引を開始 | 停止・緊急停止管理が必要な制御側局所結果を集約して緊急停止取引を完了 | 300 ms |
| `T_CTRL_COMMAND_TIMEOUT_TO_TX_MAX` | 最後の有効な操作指令のBLE受信 | 操作指令timeout成立後、停止・緊急停止管理が安全停止取引を完了 | 600 ms |

上表は出力零、driver反映、旧非零要求不存在、PWM停止等の制御側証拠を集約する期限であり、車体実速度零の実測時間ではない。値の意味および変更責任は停止・緊急停止管理に残す。

本書は、車体走行の物理停止について次の独立した初期評価metricを所有する。

| 物理停止の評価指標 ID | 開始点 | 終了点 | 初期合否値 |
| --- | --- | --- | ---: |
| `T_PHYS_NORMAL_STOP_MAX` | 走行制御が有効な中立・通常停止指令を受け付けて通常減速を開始、または停止・緊急停止管理が通常停止取引を開始 | 外部測定で車体の対地実速度零を確認 | 500 ms以内 |
| `T_PHYS_SAFE_STOP_MAX` | 停止・緊急停止管理が安全停止条件を確定し、安全停止取引を開始 | 外部測定で車体の対地実速度零を確認 | 300 ms以内 |
| `T_PHYS_BODY_ESTOP_STOP_MAX` | 本体側E-STOP入力変化 | 外部測定で車体の対地実速度零を確認 | 300 ms以内 |
| `T_PHYS_RX_ESTOP_STOP_MAX` | 本体で有効なBLE緊急停止要求の成立を確定 | 外部測定で車体の対地実速度零を確認 | 300 ms以内 |
| `T_PHYS_COMMAND_TIMEOUT_STOP_MAX` | 最後の有効な操作指令のBLE受信 | 操作指令timeoutによる安全停止後、外部測定で車体の対地実速度零を確認 | 600 ms以内 |

物理停止の終了は、映像、外部変位・速度計測その他の本体制御出力から独立した測定によって判定する。左右出力零、motor driver応答、独立出力禁止read-backまたは停止・緊急停止管理の停止取引完了だけでは、`T_PHYS_*`の終了としない。測定分解能、実速度零と判定する許容範囲および観測時間は試験前にtest procedureで固定し、結果確認後に合格側へ変更しない。本項は製品本体へのencoderその他の速度sensor追加を要求しない。

停止・緊急停止管理の`T_CTRL_*`と本節の`T_PHYS_*`は、開始点および数値が同じ場合も終了点・対象・合否判定が異なる。一方の合格を他方の合格へ読み替えない。停止・緊急停止管理の安全停止・緊急停止取引は走行と砲塔・砲身の制御側結果を対象とするが、本節の`T_PHYS_*`は車体走行の物理停止だけを対象とする。砲塔・砲身の機械的安全性は砲塔・砲身制御および該当する実機評価で別に確認する。

実測最高速度が0.4 m/s以下である条件では、各物理停止の評価指標の開始点における車体位置から実速度零を確認した位置までを停止距離とし、初期基準を次とする。

- 通常停止：200 mm以内
- 安全停止：120 mm以内
- E-STOP：100 mm以内

`U_MAX=300`を0.4 m/sへ換算したものではない。実速度を外部測定して適用条件を確認する。

停止時間・停止距離は、第4章の標準評価条件に加え、完成機体の質量、搭載物、重心、床面、傾斜、battery状態、track状態、走行方向および停止方式を記録して評価する。急停止で転倒、著しい滑り、track脱落、過電流または機構破損が起きる場合は停止距離だけを短縮せず、最大走行出力、減速、安全停止方式および基準については、それらを定める基本設計へ戻して見直す。

## 8. 処理負荷・実行基盤・資源余裕

### 8.1 システム資源の基本設計初期値

最大想定負荷における資源余裕の初期基準を次とする。

| 資源 | 初期基準 |
| --- | --- |
| CPU使用率 | 通常定常60 %以下。最大想定負荷では短時間peakを除き80 %以下 |
| 静的RAM総使用量 | 利用可能RAMの75 %以下を設計目標 |
| stack最大使用量 | 割当て容量の70 %以下 |
| communication buffer / message queue | 最大負荷で割当て容量の80 %を継続して超えない |
| log・未送信情報等の可変記憶領域 | 通常運用で20 %以上の空き、または同等の整理・上書き余裕 |

No-RTOS本体では通常Processごとの独立Task stackはないため、stack 70 %はMain call stack、nested ISRおよびlibraryを含むworst-case実測peakへ適用する。

通常本体処理では`malloc/free`を使用しない。外部library内部の動的確保が避けられない場合は最大量・失敗動作・fragmentation有無を採用前に評価し、unbounded allocationを許可しない。

### 8.2 07本体ソフトアーキテクチャの実行時間条件

本体ソフトアーキテクチャ基本設計で確定した次を横断性能条件として評価する。

- Process連続CPU占有：通常0.5 ms以下を目標
- Process連続CPU占有：原則1.0 ms以下を共通上限
- BatterySafety / Drive / Turret-Barrel / SystemMonitor：10 ms基本周期
- SystemMonitor：10 ms周期
- 10 ms重要ProcessがMONITORED中30 ms以上正常完了更新なし：処理の進行停止による異常候補

1.0 msは強制timeoutではないがNo-RTOS非preemptive blocking boundを構成する基本設計で管理する値である。平均CPU使用率を満たしていても、単一Processの長時間占有によってP0/P1 deadlineを侵害する場合は不合格とする。

P0/P1 READY→Process開始までのworst latency、ISR占有、higher-priority backlog、critical sectionを合わせて評価する。

### 8.3 Security固定資源

セキュリティ管理/セキュリティ横断設計/本体ソフトアーキテクチャ基本設計の現行初期値を最大負荷評価へ含める。

- Security request descriptor：8 slot固定
- active registration security context：1 transaction
- small crypto input copy：最大256 byte
- secure transient aggregate：96 byte固定
- raw long-term key export API：0

不足時はsecret保護を弱めたりheapへ無制限退避したりせず、Busy/Backpressure/FSM分割または基本設計見直しで対処する。

### 8.4 Safety資源

Safety Event、Stop、BatterySafety、SystemMonitor等を通常通信・Log・TLS・OTAと同じ枯渇可能Queueだけへ依存させない。容量不足でSafety requestをsilent dropした時点で不合格とする。

### 11.2 power-cut/reset injection

公開用システム要求仕様「22. 性能・品質・耐久性」 `SYS-QUAL-110/111`および22.15項目18に加え、後続基本設計で増えたrollback-sensitive transactionも含める。

少なくとも次の各主要commit境界で**5試行以上**power cutまたはresetを注入する。

- 所有者・操作端末管理/セキュリティ管理のcredential CANDIDATE → App receipt → `ownerDataRevision` → ACTIVE
- Wi-Fi接続のWi-Fi credential protected store / key epoch・revision
- 設定管理の`CONFIG_COMMIT_PENDING` → CONFIG_STORE → `highestCommittedGeneration` → finalize
- OTA更新/固定ブート・復旧の`INSTALL_REQUESTED` / `PRIMARY_OVERWRITE_STARTED` / `TRIAL_ARMED` / `trialAttempted` / `TRIAL_BOOT_VALIDATED` / settlement
- 製品情報管理のProduct Data candidate write/readback/verify → `PRODUCT_DATA_COMMIT_PENDING` → candidate commit marker → `highestCommittedProductDataRevision` → finalize
- 時刻管理の`TIME_UPDATE_PREPARED` → RTC set/readback → Trusted Time Record → finalize
- 永続データ管理のgeneric physical A/B record write/verify/switch points
- 起動・終了・再起動管理／電源・省電力管理／固定ブート・復旧によるIWDT更新責任の移管について、確定前・確定時・確定後

製品情報管理のProduct Dataについては、上記の各保存確定の境界の直前・直後で電源断・リセットを発生させ、製品情報管理基本設計 §13.3の復旧規則に従って、旧版と新版のどちらを採用するかが一意に決まることを確認する。`highestCommittedProductDataRevision`が新版へ進んだ後は、旧スナップショットへ自動的に戻さないことを必須の確認結果とする。

本書は、電源断・リセットを発生させる境界と合否の評価条件を定める。Product Dataの更新手順は製品情報管理、記憶媒体への保存方法は永続データ管理がそれぞれ定める。

復帰後に、失効済みの認証情報、古い設定世代・Product Data・時刻信頼情報、試行起動の再実行、IWDT更新責任の重複等が復活しないことを確認する。

## 12. 温度・電気・機械安全・試験中止条件

### 12.1 温度・電気の基本設計初期基準

- 一般操作者が継続接触する可能性がある外装表面：45 ℃以下を初期目標
- battery表面：45 ℃以下を通常動作初期目標
- battery 50 ℃以上、膨張、異臭、発煙、液漏れ：直ちに試験中止
- motor、servo、motor driver、power回路、wire、connector：各部品定格を超えない
- 温度定格と測定部位を対応付けられる部品：通常最大温度から定格まで10 ℃以上の余裕を初期目標

10 ℃余裕を機械的に適用できない部品は、仕様、保護、測定誤差、実機評価から同等の安全余裕を個別定義する。

温度が安定せず上昇継続、保護不作動、絶縁劣化、変色、溶融、異臭を確認した場合は予定時間を待たず中止する。

電圧・電流・温度の異常判定と保護開始条件はバッテリー・電気安全監視が定め、本書の耐久・熱目標によって緩和しない。

### 12.2 最大負荷thermal評価

05電源・ハードウェアと整合し、5分最大負荷は初期thermal screeningに限定する。最終成立は、負荷が継続し得るuse caseでは熱平衡まで、少なくとも標準session 30分または最大連続利用2時間の該当条件まで確認する。

短時間5分で問題がないことだけを理由に長時間thermal成立としない。

### 12.3 指挟み・巻込み

公開用システム要求仕様「22. 性能・品質・耐久性」 `SYS-QUAL-125`に対し、通常操作全可動範囲および合理的に予見可能なmanual handlingで、次を確認する。

- track、wheel、gear相当部、砲塔旋回部、砲身上下部、link、外装間に一般操作者が容易に触れる危険なpinch pointを残さない。
- hair、衣服、紐状物が通常使用で容易に巻き込まれる露出回転・移動部を残さない。
- software可動範囲だけへ依存して危険箇所を隠さず、power off/manual datum操作時も評価する。

人体そのものを試験probeとして使用しない。具体probe、模擬hair/clothing、接触力は後続test procedureで定めるが、危険箇所が存在した場合に「注意表示だけ」で無条件合格としない。

### 12.4 鋭利端部・突出部

公開用システム要求仕様「22. 性能・品質・耐久性」 `SYS-QUAL-126`に対し、通常接触可能な外装、board edge露出、cutout、砲身端、connector周辺、fastener周辺を組立完成状態で確認し、人身傷害につながるsharp edge、burr、危険な突出を残さない。

試作加工後だけでなく耐久・転倒・軽微衝突後にも再確認する。

### 12.5 小部品脱落

公開用システム要求仕様「22. 性能・品質・耐久性」 `SYS-QUAL-127`に対し、screw、cover、protective part、label/fixture等が通常振動、走行耐久、転倒・軽微衝突で脱落しないことを確認する。

脱落した部品が誤飲その他の危険につながり得る場合は、単に機能が継続できることだけで合格としない。

### 12.6 転倒・軽微衝突後の合否

第4.4節の試験後、少なくとも次がすべて成立すること。

- batteryが移動・露出・膨張・損傷しない。
- power wiring、高電流connector、E-STOP、主電源操作部に危険な損傷がない。
- enclosureにsharp edge、割れ、危険な隙間を新たに生じない。
- turret/barrel/track周辺のpinch・entanglement riskが増加しない。
- power-on時にunexpected actuator motionを生じない。
- E-STOP、通常停止、BatterySafetyおよび基本操作の再確認に合格する。

## 13. 評価試行数・software robustness・合否判定

### 13.1 定量的時間性能

操作応答、停止応答、起動、終了その他の定量時間性能は、各代表条件で30試行以上測定し、**全試行が上位要求または該当基本設計の最大許容値を満たすこと**を初期合否基準とする。

平均値やp95だけで最大応答要求の合否を判定しない。

### 13.2 Safety関連処理

E-STOP、安全停止、操作指令timeout、電源保護その他Safety処理は、代表的各条件で100試行以上実施し、次を1回でも発生させない。

- 必要Safety処理の不実行
- Safety state／E-STOP等の誤解除
- 停止前または失効済みold commandの再実行
- Safety requestのresource shortageによるsilent drop

### 13.3 耐久試験前後

耐久前後の最大速度、動作時間、停止時間、停止距離、消費電流の変化は原則10 %以内を初期許容範囲とする。

ただしSafety上限、部品定格、使用制限、上位要求またはその事項を定める基本設計値を超える場合は10 %以内でも不合格とする。温度は単純10 %変化で判定せず第12章を使用する。

### 13.4 ソフトウェア再現性・非同期事象の競合

公開用システム要求仕様「22. 性能・品質・耐久性」`SYS-QUAL-130/131`に対し、同じ有効な入力順序、初期状態、設定および同等条件で、安全上の結果・操作結果が理由なく変動しないことを確認する。

#### 競合させる事象

少なくとも次の組合せについて、発生順序を意図的に変えて評価する。

- 操作指令とStop／E-STOP
- BLE切断と操作指令タイムアウト
- 異常発生とシステム状態遷移
- 設定・永続データの保存確定とリセット／電源要求
- 低消費電力状態への移行とBLE接続要求／安全関連の復帰要因
- OTA／再起動と未完了の永続データ更新取引
- `TIME_TRUSTED`喪失とVPS要求

#### 発生させてはならない結果

事象の発生順序によってEventの記録順に許容範囲の差が生じる場合はある。
ただし、Single Writer、transaction ID、generation、fixed priorityの既存契約を外れて、次を発生させてはならない。

- 本来成立しない状態への遷移
- デッドロック
- 意図しないアクチュエータ動作

これらを発生させないことを合否条件とする。

### 13.5 外部からの不正入力に対する検証

公開用システム要求仕様「22. 性能・品質・耐久性」`SYS-QUAL-132`に対し、次の代表ケースを用いて不正入力への耐性を評価する。
ここで示す項目間の全組合せを新たに要求するものではない。

#### 対象インターフェース

- BLE
- Wi-Fiモジュールから受け取るイベント
- HTTP／設定データ
- OTAメタデータ
- 永続レコード
- 保守入力

#### 与える不正入力

少なくとも次を代表例とする。

- 必要な長さより短い、または上限を超えたデータ
- 未定義の種別
- 同じ要求・データの重複
- 古い世代番号・古い連番
- 規定と異なる順序
- 許容範囲外の値
- 未対応の版
- CRC、MACまたは署名の検証に失敗するデータ

#### 発生させてはならない結果

いずれの不正入力でも、次を発生させないことを合否条件とする。

- メモリ破壊
- 資源使用量の際限のない増加
- 安全監視の停止
- 検証に失敗した入力を受け入れ、本来禁止すべき動作を許可すること（fail-open）

不正入力が大量に発生した場合も、P0/P1のDeadlineを維持する。
具体的なファジング用データの件数・バイトパターンは、試験設計で定める。

### 13.6 NORMAL_OPERATIONビルドの確認

公開用システム要求仕様「22. 性能・品質・耐久性」`SYS-QUAL-133`に対し、`NORMAL_OPERATION`のビルド／プロファイルでは、評価・開発専用機能が意図せず有効になっていないことをリリース前に確認する。

#### 通常運用ビルドで有効にしてはならないもの

少なくとも次を確認する。

- 評価用の障害注入（fault injection）
- 試験用認証情報
- デバッグ用の裏口経路
- Safety／Securityの確認処理を迂回する機能
- 任意のメモリ読出し・書込み機能
- 署名されていないイメージや設定を許可する機能

#### DEVELOPMENT／EVALUATIONビルドの確認

`DEVELOPMENT`／`EVALUATION`ビルドで使用するトレースや障害注入についても、通常のSafety Deadlineを壊さない範囲で使用する。

また、これらの評価・開発専用機能が`NORMAL_OPERATION`プロファイルへ混入しないことを確認する。

## 14. 測定点・測定精度・時刻・トレーサビリティ

### 14.1 時間測定の原則

性能値は開始点と終了点を明記する。通常操作応答では少なくとも次を区別する。

1. smartphone input成立
2. smartphone送信投入
3. 本体BLE受信完了
4. 認証・形式・権限・機能受付完了
5. 本体control更新開始
6. motor driver requestまたはPWM比較値反映

停止評価では、少なくとも次のeventを同一timelineへ相関する。

1. 有効な中立・停止要求の受付、安全停止条件成立、本体側E-STOP入力変化、BLE緊急停止成立または最後の有効操作指令受信
2. 走行制御による停止側出力更新開始または独立出力禁止開始
3. 左右出力零およびmotor driver反映
4. 停止・緊急停止管理の制御側停止取引完了
5. 外部測定による車体実速度零

本体側E-STOPはsoftware eventより先にhardware経路が作動し得るため、物理入力変化を独立して記録する。異なる装置の時計を同期なしに直接減算せず、end-to-endおよび物理停止は共通測定器、相関Event、映像、logic analyzer等を使用する。

### 14.2 測定精度の初期基準

公開用システム要求仕様「22. 性能・品質・耐久性」 22.15項目23を具体化し、試作評価では次を初期基準とする。

- 50 ms以上のend-to-end時間要求：1 ms以下の表示／記録分解能を持つ測定系を使用する。
- 本体ソフトアーキテクチャ基本設計の0.5/1.0 ms Process占有やISR/critical section：10 µs以下の分解能を持つtrace/timer/logic measurementを使用する。
- voltage/current/temperature等のreference measurement：評価対象の許容誤差または判定marginに対し、原則3:1以上のTest Uncertainty Ratioを確保する。困難な場合は測定不確かさを結果へ明示し、境界値を無条件合格にしない。
- 時刻同期を用いる複数装置測定では、同期誤差を測定値へ加味しても要求上限を満たすこと。

測定器の具体型式、校正状態、sample rate、probe負荷、映像frame rate等はtest procedureへ記録する。

### 14.3 評価用Trace

Trace有効時もSafety deadlineおよび通常操作性能を維持する。Trace ON/OFFでCPU、RAM、stack、communication、storage、時間性能を比較し、観測機能自身が不適合を隠したり発生させたりしないことを確認する。

### 14.4 要求トレーサビリティ

各system test itemは少なくとも次を対応付ける。

- 対象`SYS-QUAL-*`
- 関連機能要求
- 対象基本設計章／設計判断
- 評価条件、機体構成、FW、configuration、security profile
- measurement start/end、方法、精度
- 合否基準
- result/evidence

## 15. 不合格・再試験・設計変更

評価結果は`PASS / FAIL / CONDITIONALLY_VALID / NOT_VERIFIED`を区別する。

FAIL時は閾値や待ち時間を単に緩めてPASSへ変更せず、原因を次へ分類する。

- 上位要求値の実現困難
- 基本設計方式／基本設計初期値の不成立
- 詳細設計・実装不良
- hardware/mechanism/part selection不良
- test condition／measurement不備

基本設計値の変更が必要ならその事項を定める基本設計または本書を改訂して関連文書を再整合し、その後再試験する。上位要求値変更が必要なら公開要求へ正式feedbackする。

CONDITIONALLY_VALIDは条件を明示し、その条件外をPASS扱いしない。未評価条件を含む製品保証と試作評価PASSを混同しない。

## 16. 現時点の評価確定待ち事項

### 16.1 機体質量・重心

`M_STD`、`M_MAX`、`PAYLOAD_MAX`、`CG_ENVELOPE`は完成構成の実測および機構評価後に確定し、本書へ戻す。

### 16.2 砲塔・砲身の安全可動範囲

`Tmin/Tmax/Bmin/Bmax`は機構寸法、servo取付角、配線、掃引領域、安全marginを確認して砲塔・砲身制御へ確定する。`03_機能別基本設計/00_懸案事項.md`の`BD-ISSUE-002`を継続する。

### 16.3 停止完了・停止距離

第6.2節の`T_PHYS_NORMAL_STOP_MAX`、`T_PHYS_SAFE_STOP_MAX`、`T_PHYS_BODY_ESTOP_STOP_MAX`、`T_PHYS_RX_ESTOP_STOP_MAX`、`T_PHYS_COMMAND_TIMEOUT_STOP_MAX`および停止距離は、車体走行に対する試作初期基準である。実機前の正式保証値ではない。

完成機体の質量、最高実速度、床面、傾斜、battery、trackおよび走行制御の停止方式を組み合わせ、第14.1節のevent相関と外部速度・変位測定によって評価する。`T_CTRL_*`の制御側合格だけで`T_PHYS_*`または停止距離を合格としない。

物理停止基準が成立しない場合は、まず走行制御の最大走行出力、減速率、零出力時動作および安全停止方式を見直す。停止・緊急停止管理の制御側停止取引上限または本書の物理停止初期値自体を変更する必要がある場合は、該当事項を定める文書を個別に改訂し、同じ数値であることだけを理由に両方を連動変更しない。

### 16.4 部品固有の熱・耐久上限

servo、motor、motor driver、power part、wire、connector等の正式上限は採用品datasheetと実機温度分布を対応付けて確定する。

### 16.5 転倒・軽微衝突の最終条件

第4.4節の0.20 m/s等は試作開始用の基本設計初期条件である。`M_STD/M_MAX`、重心、実速度、外装形状、通常利用model確定後に、合理的に予見可能な転倒・軽微衝突として妥当かを再評価し、本書へ最終条件を戻す。

## 17. 基本設計としての確定事項

1. 性能値を上位要求、関連基本設計で管理する値、本書初期値、評価確定待ちに分離する。
2. Safety性能・Safety資源を非Safety処理より優先する。
3. 公開用システム要求仕様「22. 性能・品質・耐久性」の150/100/50 ms、起動・終了・省電力・OTA、BLE距離・時間、温湿度等を本書だけで変更しない。

15. 基本設計値変更を詳細設計・test procedureだけで行わない。
16. 上位要求変更が必要なら要求仕様へ正式feedbackする。
17. 試作評価PASSと量産寿命保証・第三者認証を混同しない。

## 18. バッテリー駆動・待機性能の初期評価目標

公開用システム要求仕様「22. 性能・品質・耐久性」が後続具体化を求める駆動・待機性能について、次を本書の基本設計初期目標とする。

| 項目 | 初期目標 |
| --- | --- |
| 標準利用patternでの1充電駆動時間 | 60分以上を最低目標、120分以上を設計目標 |
| BLE接続待機 | 12時間以上。平均消費電流150 mA以下を評価目安 |
| low-power state | 72時間以上を最低目標、168時間以上を設計目標。平均消費電流10 mA以下を評価目安 |
| 主電源OFF時の主battery待機電流 | 100 µA以下を目標 |
| `PWR_AON` | 50 µA以下を05電源・ハードウェアのsub-budget目標 |
| RTC VBATT backup branch | 5 µA以下を目標 |

本書では、主電源OFF時の主battery待機電流100 µA以下を、AON外の漏れ電流および逆給電を含むシステム総量の評価目標として定める。回路別sub-budgetと成立方法は電源・ハードウェア基本設計に従い、RTC VBATT backup branch 5 µA以下は`PWR_AON` 50 µA以下の内数とする。

これらは公開要求へ新しい保証値を追加するものではなく、battery/power設計と試作評価の開始基準である。

評価ではbattery実容量、放電終止、劣化、温度、機体質量、走行負荷、servo利用率、BLE advertising/connection、Wi-Fi/VPS頻度、状態表示条件を記録する。

標準利用patternは無負荷放置ではなく、第9章の30分sessionを基準に走行、砲塔・砲身、communication、display、待機を含めてtest designで固定する。

30日以上使用しない長期保管では主batteryを本体から取り外すことを基本とする。

初期目標が不成立なら単に待機機能や測定条件を緩和せず、power architecture、battery capacity、low-power方式、communication設定、利用modelへfeedbackする。
