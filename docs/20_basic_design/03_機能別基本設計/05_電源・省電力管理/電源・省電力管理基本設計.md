# Tank_Robot 電源・省電力管理基本設計

## 1. 本書の目的

### 1.1 目的

本書は、Tank_Robot本体における電源・省電力管理機能の基本設計を定義する。

電源・省電力管理機能は、現在のシステム状態、各機能の使用状況、安全条件および復帰要因に基づいて、本体内の制御部、BLE通信部、Wi-Fi通信部、走行駆動部、サーボ駆動部、状態表示部およびその他の周辺回路の電力状態を管理する。

また、長時間未操作の監視、低消費電力状態への移行、低消費電力状態中の機能維持、復帰要因に応じた選択的な復帰、および電力状態変更の失敗時処理を定義する。

### 1.2 対象範囲

本書の対象範囲を以下に示す。

- 本体内の省電力対象機能に対する論理電力状態の管理
- 電力状態の変更要求、変更中状態、完了結果および失敗結果の管理
- 認証済み操作端末からの最終有効操作時点と長時間未操作条件の管理
- 低消費電力状態への移行条件、移行順序および完了条件
- 低消費電力状態中に維持する機能および監視
- BLE接続要求、通常終了要求、緊急停止要求および異常検出による復帰
- 復帰要因に応じた必要機能のみの選択的な復帰
- 電力状態変更、低消費電力移行および復帰の監視と失敗時処理
- ログ、診断および状態表示へ提供する情報

次の事項は本書の対象外とし、関連する基本設計で定義する。

| 項目 | 主たる管理機能 |
| --- | --- |
| システム状態の決定および状態遷移の確定 | システム状態管理機能 |
| 主電源投入後の起動、通常終了および再起動の全体シーケンス | 起動・終了・再起動管理機能 |
| 通常停止、安全停止および緊急停止の成立判断と安全処理 | 停止・緊急停止管理機能 |
| 電圧、電流、温度その他の電気的異常の成立判断 | バッテリー・電気安全監視機能 |
| 異常識別、異常処置、異常停止および復旧可否の判断 | 異常管理機能 |
| 強制電源遮断の実行 | 電源部のハードウェア経路 |
| 物理電源ツリー、各電源domainとrailの対応、電源回路、電源スイッチ、保護回路、read-back信号および端子の電気的基本構成 | 電源・ハードウェア基本設計（H01） |
| 個別部品、回路定数、pin、PCB layoutその他の具体的な実装 | ハードウェア詳細設計 |
| MCU低消費電力モードのレジスタ設定、個別ドライバおよび具体的な実装 | ソフトウェア詳細設計 |

本書または関連する機能別基本設計で、Tank_Robotの正常利用または定義された異常ユースケースとして発生し得る電力状態変更、低消費電力移行、復帰、失敗、縮退、再試行および安全処理について、開始・完了・失敗条件、処理の優先順位、利用可否、再試行可否、縮退継続可否または利用者・他機能から見た時間上限を決定する。これらの振る舞いを変更しないレジスタ設定、端子割付け、タイマ実装、排他・同期、データ構造、内部チェックポイントその他の実装方法は詳細設計で定めてよい。正常なユースケースでは到達しない内部状態矛盾、デッドロックその他の実装上の防御も、基本設計で定めた安全側方針を変更しない範囲で詳細設計の対象とする。

### 1.4 用語

| 用語 | 定義 |
| --- | --- |
| システム状態 | 起動処理状態、BLE接続待機状態、操作可能状態、低消費電力状態など、本体全体の動作状態 |
| 電力状態 | 個々の機能または電源系統が、停止、待機、通常動作、低消費電力、変更中または異常のいずれにあるかを表す論理状態 |
| 低消費電力移行 | BLE接続待機状態から低消費電力状態へ遷移するために、各機能を安全な電力状態へ変更する処理 |
| 通常復帰 | BLE接続要求を契機として、低消費電力状態からBLE接続待機状態へ戻るための復帰 |
| 選択的復帰 | 復帰要因の処理に必要な機能だけを復帰させ、不要な機能を低消費電力状態のまま維持する処理 |
| 低消費電力移行コミット | 低消費電力移行の全事前処理完了後に、システム状態の確定とMCU低消費電力モード移行を不可分に実行する処理 |
| 最終有効操作時点 | 認証および権限確認を完了し、妥当な利用者操作として受け付けた最新の時点 |
| 長時間未操作条件 | 最終有効操作時点または未操作監視開始時点から、規定の未操作時間が経過した状態 |
| 必須省電力処理 | 失敗した場合に安全監視、アクチュエータ停止または復帰能力を保証できず、低消費電力状態への移行を中止する処理 |
| 任意省電力処理 | 失敗しても安全監視、アクチュエータ停止および復帰能力を維持でき、消費電力の増加を許容して移行を継続できる処理 |
| 低消費電力安全監視世代 | 1回の周期復帰から、その周期で必要な監視値および保護状態の取得・妥当性確認が完了するまでを、他の周期と区別する単位 |
| 低消費電力監視期限監視 | 周期復帰経路とは独立したクロックおよびハードウェアによって、低消費電力安全監視世代の正常完了が規定期限内に更新されないことを検出する監視 |

## 2. 基本設計方針

### 2.1 システム状態と電力状態の分離

システム状態管理機能は、本体全体の現在状態および状態遷移を一元管理する。

電源・省電力管理機能は、システム状態管理機能から通知された現在状態と処理要求に従い、各機能の目標電力状態を決定し、電力状態の変更を実行する。

電源・省電力管理機能が管理する移行中、復帰中および電力状態変更中は内部状態であり、新たなシステム状態として扱わない。

低消費電力状態への移行および低消費電力状態からの復帰は、次の役割分担とする。

1. システム状態管理機能が状態移行処理の開始可否と移行予定先を決定する。
2. 電源・省電力管理機能が、MCU低消費電力モード移行を除く電力状態変更シーケンスを実行する。
3. 電源・省電力管理機能が低消費電力移行コミット可能結果または失敗を返し、コミット可能時に縮退が存在する場合は縮退情報をあわせて提供する。
4. システム状態管理機能がすべての必須条件を確認し、低消費電力移行コミットを許可する。
5. システム状態管理機能による低消費電力状態の確定と、電源・省電力管理機能によるMCU低消費電力モード移行を、一つの不可分なコミット処理として実行する。

コミット処理が正常に成立するまで、現在のシステム状態はBLE接続待機状態のままとする。MCU低消費電力モード移行に失敗した場合は、外部から低消費電力状態を観測可能にする前に状態確定を取り消し、低消費電力状態を有効にしない。具体的なコミット処理は第6.3節に定める。

### 2.2 単一管理主体

#### 電力状態の管理と物理回路の設計

電源・省電力管理機能は、各電源系統について次の状態を一元管理する。

- 目標電力状態
- 実際の電力状態を論理的に表した状態（論理実電力状態）
- 電力状態を変更中であること

論理実電力状態は、「電源・ハードウェア基本設計」で定める電源良好信号（power-good）、異常信号（fault）、その他の状態確認信号（read-back）から確定する。
`PWR_DRIVE`、`PWR_SERVO`その他の電源系統について、関連機能へ提供する現在の論理電力状態の確定・更新は、電源・省電力管理機能が担当する。

物理的な電源系統、電源回路および状態確認信号の電気的な成立条件は、「電源・ハードウェア基本設計」で定める。
物理信号そのものと、その信号から電源・省電力管理機能が確定した論理電力状態は区別する。

#### 個別機能の処理結果との区別

各機能は、自身が担当する出力停止、保留中指令の破棄、内部スリープ、復帰、初期化および電力変更準備を実行する。
その結果は、当該機能が確認できる範囲の局所結果として返す。
この局所結果を、電源系統の実電力状態または電源状態変更の完了へ読み替えない。

走行制御および砲塔・砲身制御の物理的な停止が必要な場合は、停止・緊急停止管理機能が停止目的、停止要求識別子および要求元の相関識別情報を管理し、対象機能から局所停止結果を集約する。
電源・省電力管理機能は、同じ物理停止を走行制御または砲塔・砲身制御へ別経路から重複要求しない。

個別機能は、異常時のハードウェア保護動作を除き、他機能の電力状態を直接変更しない。
局所停止・電力変更準備が成立した後、電源・省電力管理機能が電源部を通じて実際の電源系統を変更し、その実状態を確認する。

### 2.3 安全優先

省電力効果よりも安全状態の維持を優先する。

次の機能は、低消費電力状態への移行および低消費電力状態中であっても失われてはならない。

- 走行駆動部および砲塔・砲身の停止状態の維持
- 緊急停止操作および通常終了操作の検出
- 強制電源遮断操作のハードウェア経路
- 継続が必要なバッテリー・電気安全監視および異常検出
- BLE接続要求その他の定義された復帰要因の検出

より深い低消費電力モードを選択するとこれらを維持できない場合は、消費電力が増加しても、必要な監視と復帰が可能な浅い低消費電力モードを使用する。

### 2.4 安全な順序と完了確認

電源投入、電源停止、スリープ移行および復帰は、要求送信だけで完了とみなさない。

対象機能からの局所準備・初期化結果、電源部のハードウェア状態入力、ドライバ状態または安全な代替確認手段によって必要な条件を確認し、実際の電源系統の変更後は電源・省電力管理機能が実電力状態を確認して現在電力状態を更新する。

アクチュエータ系の電源を停止するときは、操作禁止、停止、出力無効化およびPWM停止を先に行う。これらの停止処理は停止・緊急停止管理機能が停止取引として集約し、電源・省電力管理機能はその完了結果を使用してから対象電源系統を変更する。電源供給を再開するときは、出力禁止状態を先に確立し、電源・省電力管理機能が電源安定を確認した後に対象機能の初期化結果を取得する。電源が復帰したこと、対象機能の初期化が正常完了したこと、およびシステム状態管理機能が通常操作を許可したことは、それぞれ別の条件として扱う。

### 2.5 復帰後の自動再開禁止

低消費電力状態への移行前に存在した走行指令、走行速度、砲塔位置指令、砲身位置指令、通信処理または未実行操作を、復帰後に自動再開しない。

通常復帰の遷移先はBLE接続待機状態とし、操作可能状態へ直接遷移しない。通常操作は、BLE接続、認証、操作権限およびシステム状態の条件を改めて満たした後に許可する。

### 2.6 外部通信からの独立

低消費電力移行、復帰、安全監視および異常処理は、Wi-Fi、インターネットまたはVPSへの接続を前提としない。

通常復帰だけを理由としてWi-Fi通信部を復帰させない。復帰後にログ送信、設定取得、診断またはOTA更新などの処理が必要になった時点で、電源・省電力管理機能がWi-Fi通信部を個別に復帰させる。

### 2.7 優先順位

電力状態変更中に複数の要求が成立した場合は、次の優先順位で処理する。

1. 強制電源遮断
2. 緊急停止
3. 通常動作の継続を禁止する異常への対応
4. 通常終了
5. BLE接続要求による通常復帰
6. 低消費電力状態への移行
7. 通常の省電力状態変更

強制電源遮断は電源部のハードウェア経路が直ちに実行し、ソフトウェア処理の完了を待たない。

上記の優先順位は、緊急停止要因と電気的保護要因のいずれも失わず、必要な安全処理を並行して開始することを妨げない。短絡・重大過電流のハードウェア即時保護は本順位を待たない。ソフトウェアで検出した危険過電流について、停止後も過電流が継続する条件または停止失敗が成立し、バッテリー・電気安全監視機能から対象系統遮断要求を受けた場合は、緊急停止処理の開始、復帰または完了を待たずに対象系統遮断を開始する。緊急停止処理は、電源が維持され実行可能な範囲で並行して継続する。

## 3. 電力状態管理

### 3.1 電源・省電力管理機能の内部状態

| 内部状態 | 内容 |
| --- | --- |
| 通常管理中 | 現在のシステム状態および使用要求に従って個別機能の電力状態を管理している |
| 低消費電力移行中 | 低消費電力状態への移行シーケンスを実行している |
| 低消費電力維持中 | 低消費電力状態で必要な機能と監視だけを維持している |
| 復帰中 | 復帰要因に応じた選択的復帰シーケンスを実行している |
| 移行中断・復元中 | 優先要求または移行失敗により、途中まで変更した機能を安全な状態へ復元している |
| 管理異常 | 現在電力状態を確定できない、または安全に必要な電力状態を確立できない |

内部状態ごとに、処理世代を識別する移行識別子、開始要因、開始時刻、対象機能、完了済み処理、失敗処理および割込み要因を管理する。遅延して到着した前回処理の完了通知は、現在の処理結果として使用しない。

内部状態の遷移を以下に示す。

| 現在内部状態 | 条件またはイベント | 次内部状態 | 主な処理 |
| --- | --- | --- | --- |
| 通常管理中 | システム状態管理機能から低消費電力移行開始要求を受け付ける | 低消費電力移行中 | 移行識別子を発行し、第6章の事前処理を開始する |
| 低消費電力移行中 | 全必須処理が完了し、低消費電力移行コミットが成立する | 低消費電力維持中 | 低消費電力状態で必要な監視と復帰入力だけを維持する |
| 低消費電力移行中 | システム状態管理機能から移行中断要求または復元要求を受け付ける | 移行中断・復元中 | 低消費電力移行を中断し、要求された遷移先または遷移元状態を安全に維持するために必要な機能を復元する |
| 移行中断・復元中 | 必要機能の復元が正常に完了する | 通常管理中 | 中断結果または移行失敗結果を関連機能へ通知する |
| 移行中断・復元中 | 必要機能の復元に失敗する | 管理異常 | 利用可能な機能と失敗情報を異常管理機能へ通知する |
| 低消費電力維持中 | 復帰要因を検出する | 復帰中 | 復帰要因を保持し、第8章の選択的復帰を開始する |
| 復帰中 | 復帰処理が正常に完了し、システム状態管理機能が遷移先を有効にする | 通常管理中 | 遷移先状態に対応する通常の電力状態管理へ戻る |
| 復帰中 | 復帰の必須処理が失敗する | 管理異常 | 通常操作禁止と安全状態を維持して異常管理機能へ通知する |
| 管理異常 | 異常管理機能が当該異常について許可した明示的な復旧、または当該異常の基本設計で自動復旧を明示的に許可した再初期化が正常に完了し、全対象の電力状態を再確認できる | 通常管理中 | 全対象の電力状態を再確認し、異常管理およびシステム状態管理の結果に従って通常の電力状態管理を再開する |
| 各内部状態 | 電力状態を確定できず、安全な管理を継続できない | 管理異常 | 対象機能を使用不可とし、安全側の処理へ連携する |

`管理異常`からの復旧可否、自動復旧の許可およびシステム全体の通常操作再開可否は、電源・省電力管理機能が独自に決定しない。特に低消費電力復帰失敗は、異常管理基本設計で定めた処置・復旧方針に従い、電源・省電力管理機能だけの判断による再初期化で異常停止または通常操作禁止を解除しない。原因となった個別機能について自動復旧が許可されている場合も、その機能固有の復旧結果を異常管理機能へ提供し、必要な復旧条件と最終結果を確認してから管理異常を解除する。

高優先度要求によって低消費電力移行または通常復帰を中断した場合は、その中断を省電力処理自体の異常と区別する。

電源・省電力管理機能が高優先度要求または必須処理失敗を検出した場合は、安全上直ちに必要な出力禁止を実行して要因をシステム状態管理機能へ通知する。状態遷移としての中断および遷移元状態への復元は、システム状態管理機能から当該移行識別子を指定した中断要求または復元要求を受けて実行する。

### 3.2 省電力対象機能の論理電力状態

電源・省電力管理機能が管理する電力状態は、対象機能への電源供給、低消費電力化および電力状態変更の状態を表す。

BLE接続状態、アドバタイズ状態、Wi-Fi接続状態、通信状態、アクチュエータ停止状態、表示内容および監視状態などの各機能固有状態は、それぞれを担当する機能が管理する。

電源・省電力管理機能は、これらの機能固有状態のうち、電力状態変更の開始条件または完了条件として必要な情報を関連機能から取得する。

| 対象 | 電源・省電力管理機能が管理する論理電力状態 | 低消費電力時に担当機能へ要求する機能状態 |
| --- | --- | --- |
| 制御部 | 電源供給停止、通常電力、低消費電力、変更中、不明 | RAM保持、定義された割込み復帰および必要な安全監視を両立する |
| BLE通信部 | 電源供給停止、通常電力、低消費電力、変更中、不明 | 接続可能な低頻度アドバタイズを継続し、接続要求を制御部へ通知する |
| Wi-Fi通信部 | 電源供給停止、通常電力、低消費電力、変更中、不明 | Wi-Fi・VPS通信を終了し、モジュールをスリープ状態にする |
| 走行駆動部 | 電源供給停止、通常電力、変更中、不明 | 左右モータ停止と駆動出力無効を維持する |
| サーボ駆動部 | 電源供給停止、通常電力、変更中、不明 | 機構安全を確認し、サーボPWM出力を停止する |
| 状態表示部 | 電源供給停止、通常電力、低消費電力、変更中、不明 | 電源LEDによる低消費電力表示だけを維持し、不要な表示を停止する |
| 電気安全監視 | 監視用電源停止、通常監視用電力、低消費電力監視用電力、変更中、不明 | 継続対象の監視と重大異常に対するハードウェア保護を維持する |
| その他周辺回路 | 電源供給停止、通常電力、低消費電力、変更中、不明 | 復帰、安全監視およびデータ整合性に不要な機能を停止する |

ここで定義する状態は論理状態である。同じ電源系統を共有する機能は、個別に電源遮断できない場合がある。その場合も、個別機能のクロック停止、スリープ、出力無効化またはアクセス禁止を組み合わせ、論理状態を実現する。

### 3.3 電源ドメイン構成

#### 本書で定める範囲

本節では、電力状態を管理する単位を「電源ドメイン」と呼ぶ。
各電源ドメインの名称、論理的な役割、低消費電力状態での目標状態、および独立して状態を変更する必要性は、本書で定める。

各電源ドメインへの給電、分配、遮断および監視を実現する物理的な電源系統と回路は、「電源・ハードウェア基本設計」で定める。
以下の表に含まれる物理的な供給元や配置の説明は、本書の論理状態管理が前提とする同基本設計の要約であり、別の物理電源構成を定義するものではない。

本体は、一つの2S LiPoバッテリーを電源入力とし、以下の電源ドメインを論理的な管理単位とする。

| 電源ドメイン | 主な供給対象 | 低消費電力状態の基本方針 | 独立制御の基本方針 |
| --- | --- | --- | --- |
| `VBAT_MAIN` | バッテリーコネクタ直後の生電源入力 | バッテリー接続中は存在する | 電源・省電力管理機能の制御対象外とし、逆接続保護、過電圧保護および過放電保護より上流の境界とする |
| `VBAT_PROTECTED` | 固定入力保護を通過したバッテリー電源 | バッテリー接続中かつハードウェア保護未作動時に存在する | 逆接続、過電圧、過放電および必要な過電流保護の後段、主電源制御の前段とし、`PWR_AON`を分岐する |
| `VBAT_SWITCHED` | 主電源制御を通過した本体主電源 | 主電源ON中に維持し、通常終了または強制遮断で停止する | `VBAT_PROTECTED`から主電源スイッチ回路を介して生成し、制御・通信・表示・走行・サーボ各系統の上流電源とする |
| `PWR_AON` | 主電源操作検出、強制電源遮断経路、復帰要因の保持（ラッチ）、バッテリー保護状態の保持・通知 | 主電源OFFを含めて必要な回路だけを極低消費電力で維持する | `VBAT_PROTECTED`から独立した低待機電流の回路として構成し、ソフトウェアによる停止対象としない |
| `PWR_CTRL` | RA8M2、不揮発メモリ、最低限の状態保持 | 電源供給を維持し、RA8M2および不要な周辺機能を低消費電力化する | `VBAT_SWITCHED`から生成する、走行・サーボ負荷から分離した3.3 V制御系電源とし、通常終了完了後の主電源遮断まで維持する |
| `PWR_BLE` | RYZ012A1 BLE通信部 | 電源供給を維持し、低消費電力アドバタイズを行う | `PWR_CTRL`の3.3 V電源から独立ロードスイッチを介して供給し、BLE単位で電源停止、リセットおよび復帰通知が可能な構成とする |
| `PWR_WIFI` | DA16200MOD Wi-Fi通信部 | Wi-Fi・VPS通信を停止し、モジュールをスリープ状態にする | `PWR_CTRL`の3.3 V電源から独立ロードスイッチを介して供給し、Wi-Fi単位でスリープ、復帰、リセットおよび電源遮断が可能な構成とする |
| `PWR_DRIVE` | DPC-XGL1-JP走行駆動部および左右DCモータ | 駆動出力無効後に電源供給を停止する | `VBAT_SWITCHED`から分岐し、`PWR_CTRL`から独立して出力無効化および電源遮断可能とする |
| `PWR_SERVO` | DS3218サーボ2基およびサーボ用電源変換部 | PWM停止と機構安全確認後に電源供給を停止する | `VBAT_SWITCHED`から専用5 V電源変換部を介して供給し、`PWR_CTRL`および`PWR_DRIVE`から独立して電源遮断可能とする |
| `PWR_DISPLAY` | RGB LED、7セグメント表示およびその他の状態表示負荷 | 電源LED以外を停止または低消費電力化する | `PWR_CTRL`から独立ロードスイッチまたは出力ドライバを介して供給し、不要な表示負荷を一括停止可能とする。電源LEDは`PWR_CTRL`から供給する |
| `PWR_SAFETY` | バッテリー電圧、走行・サーボ電流、バッテリー温度、モータドライバ温度の監視回路 | 継続監視に必要な回路だけを維持する | `PWR_CTRL`と物理電源を共有し、低消費電力状態で停止するロードスイッチの下流へ配置しない |

#### 独立制御と給電維持の条件

`VBAT_MAIN`、`VBAT_PROTECTED`および`VBAT_SWITCHED`に対応する物理的な電源境界は、「電源・ハードウェア基本設計」に従う。
本書では、それぞれを異なる論理状態管理単位として区別する。

論理電力状態の変更では、次の機能条件を満たすこと。

- `PWR_DRIVE`と`PWR_SERVO`を、制御・安全機能を維持したまま個別に遮断できること。
- `PWR_WIFI`を、少なくともモジュール単位でスリープ・復帰できること。
- `PWR_BLE`が、低消費電力状態中も復帰通知を出力できること。

`PWR_BLE`、`PWR_WIFI`、`PWR_DISPLAY`および`PWR_SAFETY`の物理的な生成元、ロードスイッチ配置および給電経路は、「電源・ハードウェア基本設計」に従う。
電源・省電力管理機能は、これらを本節の電源ドメイン単位で要求・確認できることを前提とする。
低消費電力状態中も、`PWR_SAFETY`に必要な給電を維持できることを前提条件とする。

#### 電源回路と主電源制御との関係

電源の分配構成、FET、ロードスイッチ、レギュレータ、EN端子、電源監視IC、状態確認信号その他の電気的基本構成は、「電源・ハードウェア基本設計」で定める。
具体的な部品および回路定数は、ハードウェア詳細設計で決定する。
これらの設計では、本書で定める独立した状態変更の条件、安全監視、逆給電防止および使用前の完了確認の意味を変更しない。

電源部は、物理的な電源供給と保護を実行する。
電源・省電力管理機能は、電源部および各機能へ目標電力状態を要求し、その結果を管理する。
主電源の投入、通常終了後の主電源遮断および強制電源遮断は、起動・終了・再起動管理基本設計に従う。

### 3.4 MCU低消費電力方式

#### MCU低消費電力モードの選択

RA8M2の低消費電力方式は、低消費電力移行時に残る監視処理に応じて、次のいずれかを選択する。
選択結果を「選択済みMCU低消費電力モード」と呼び、低消費電力移行コミット可能結果に含める。

| 選択済みMCU低消費電力モード | 適用条件 | 基本動作 |
| --- | --- | --- |
| 標準モード | `PWR_DRIVE`および`PWR_SERVO`を停止でき、1秒周期の電気安全監視を一時起動で実行できる | RA8M2のSoftware Standbyモードを使用し、AGT1による周期復帰と独立IWDTによる監視期限監視を維持する |
| 通電維持監視モード | 縮退により`PWR_DRIVE`または`PWR_SERVO`への電源供給を継続し、第7.1節に定める対象別監視を通常監視周期で継続する必要がある | RA8M2のSleepモードを使用し、必要なタイマ、A/D変換および監視処理を動作可能にする |

通常は標準モードを選択する。
通電維持監視モードは、次の条件がすべて成立する場合だけ選択する。

- アクチュエータ出力を禁止したまま、対象電源系統を安全に遮断できない。
- 通常監視周期を維持することで、低消費電力状態を安全に成立させられる。

必要な監視を維持できず、対象電源系統も安全に遮断できない場合は、低消費電力状態へ移行しない。

Deep Software Standbyモードは、初期設計では採用しない。
保持情報、10秒以内の復帰、BLE接続要求、通常終了、緊急停止および安全監視のすべてを満たすことを優先するためである。

通電維持監視モードに使用するSleepモードでは、必要な監視周期を満たす範囲で、停止可能なクロックと周辺機能を停止する。
別のMCU低消費電力モードへ変更する必要が生じた場合は、詳細設計だけで変更せず、消費電力と監視成立性を評価して本基本設計を改訂する。

#### 周期復帰と独立した期限監視

標準モードでは、RA8M2のAGT1をLOCOで動作させ、AGT1アンダーフローをSoftware Standbyの復帰要因として1秒周期で復帰する。
周期復帰後に、その周期で必要な測定・判定をまとめて行う処理を、本節では「監視バースト」と呼ぶ。

AGT1、LOCO、周期復帰割込みまたは監視処理自体が動作しない場合を、同じ経路で監視してはならない。
このため、低消費電力監視期限監視は、AGT1とは異なるIWDTCLKで動作するRA8M2の独立ウォッチドッグ（IWDT）ハードウェアが担当する。
IWDTはSoftware Standby中もカウントを継続し、規定期限を超過した場合は、NMI通知だけに依存せずMCUリセットを発生させる。

AGT1は周期的に復帰するために使用し、IWDTは監視が期限内に正常完了しているかを独立して監視するために使用する。
通常時の監視処理更新期限と低消費電力時の監視期限は、異なる論理監視として管理する。

#### IWDTの更新条件と実行主体

##### 更新命令を実行する機能

IWDTはOFSによるオートスタート方式を基本とし、リセット直後から低消費電力中および復帰後まで連続して動作させる。

固定ブート・復旧の実行中は、固定ブート・復旧機能が自身の正当性確認済みコードからIWDTを更新する。
更新できるのは、署名・完全性確認その他の必須段階について、後続の固定ブート・復旧設計で定める正常進行確認が完了した場合だけとする。

本体アプリケーションで電源・省電力管理機能を確立した時点で、更新実行権を同機能へ一回だけ移管する。
それ以後は、電源・省電力管理機能だけがIWDT更新命令を実行する。
各制御機能、監視対象タスクまたは異常管理機能が、個別にIWDTを直接更新することを許可しない。

##### 更新実行権と更新許可根拠の違い

「IWDT更新実行権の移管」は、更新命令を実行する担当機能を引き継ぐことを示す。
一方、「IWDT更新許可根拠の移管」は、監視モードの切替えに伴い、更新してよいと判断する根拠を切替先の正常監視結果へ切り替えることを示す。
監視モードを切り替えても、更新命令を実行する機能が別の機能へ変わるわけではない。

##### 起動中および通常監視確立後の更新条件

起動中は、起動・終了・再起動管理機能が提供する起動段階の正常進行確認を使用する。

本体アプリケーションの通常監視確立後は、システムアーキテクチャで重要周期処理として定める監視対象について、正常進行確認結果をIWDT更新許可の必須条件とする。
この結果は、監視対象自身とは独立したシステム監視経路が、次の情報を集約して確定する。

- チェックポイント（処理の通過点）
- 生存カウンタ、または同等の進行情報
- それらに基づき、必要な処理区間を正常完了したことの確認結果

次の事実だけを、IWDT更新の根拠としない。

- タスクが起動されたこと。
- 割込みが発生したこと。
- 一つの機能から生存通知を受け取ったこと。

電気安全監視の初期化後は、通常監視、通電維持縮退監視および復帰中のいずれでも、次の両方を使用してIWDT更新可否を決定する。

- バッテリー・電気安全監視機能が提供する、当該モードの最新正常監視世代。
- システム監視経路が提供する、現在状態で必要な重要処理の正常進行確認結果。

##### 標準低消費電力監視中の更新条件

標準低消費電力監視では、周期復帰ごとに電源・省電力管理機能が、現在の移行識別子と単調増加する低消費電力安全監視世代を発行する。
両者を含む開始要求を、バッテリー・電気安全監視機能へ提供する。

同機能から受け取る`LP_MON_START`、`LP_MON_COMPLETE`または失敗結果は、移行識別子および監視世代が同じ処理に対応していることを確認する。
識別子が一致しない結果や旧世代の結果を、現在の監視完了およびIWDT更新の根拠として使用しない。

IWDTを更新するには、次の条件をすべて満たすこと。

- バッテリー・電気安全監視機能が、当該世代で必須とする監視値および保護状態の取得・妥当性確認をすべて正常完了した結果を提供している。
- 電源・省電力管理機能が、移行識別子および低消費電力安全監視世代の一致を確認し、対応する`LP_MON_COMPLETE`を受理している。
- 当該システム状態で必要なシステム監視条件が成立している。

AGT1アンダーフロー、周期復帰割込みまたは監視バーストの開始だけでは、IWDTを更新しない。
低消費電力状態で意図的に停止している通常周期処理は更新条件へ含めず、その状態で動作が要求される監視処理だけを対象とする。

##### 終了中の更新条件

終了中も、電気安全監視およびシステム監視が使用可能な間は、現在状態で必要な正常進行条件を使用する。
監視不能となった後、または強制電源遮断へ切り替えた後は、正常終了を成立させる目的でIWDTを更新し続けない。

#### IWDT更新実行権の引継ぎ

##### 引継ぎに使用する情報と手順

IWDT更新実行権の移管には、単調増加するIWDT更新実行権移管識別子と、現在の更新主体を示す保持情報を使用する。
移管は、次の順序で行う。

1. 固定ブート・復旧機能は、直前の更新取引が完了していることを確認する。その後、移管識別子、現在主体および最終更新結果を保持し、移管を要求する。
2. 電源・省電力管理機能は、現在主体が固定ブート・復旧であること、移管識別子と最終更新結果が一致すること、および未完了の更新取引がないことを確認する。
3. 前項の条件をすべて満たす場合に限り、一つの論理的なコミット処理で現在主体を電源・省電力管理へ変更し、移管正常完了を返す。

コミット前は固定ブート・復旧機能だけが更新でき、コミット後は電源・省電力管理機能だけが更新できる。
具体的な共有領域、排他および原子的コミット方法は後続設計で定める。

##### 引継ぎが成立しない場合

次の場合は、移管を成立させない。

- 結果が否定または不明である。
- 結果を受領していない。
- 識別子が一致しない。
- 必要な情報の保持に失敗した。

移管が成立しない場合は、保持上の現在主体を固定ブート・復旧のままとし、電源・省電力管理機能はIWDTを更新しない。
起動正常完了および負荷側電源投入も禁止する。

固定ブート・復旧機能は、自身の正常進行条件が成立する期間を超えて更新を継続せず、IWDTリセットへ移行する。

##### 固定ブート・復旧機能が更新前に保持する情報

固定ブート・復旧機能も、各更新命令の直前に、本節のIWDT更新取引と同等の次の情報を保持する。
保持先は、リセット後に取得可能な領域とする。

- 更新取引識別子
- 更新元区分
- 起動段階識別子
- 更新状態
- 実行時刻
- 異常通知取引識別子
- 予約済み異常識別子
- 主通知状態

#### 監視モード切替え時の更新許可根拠

監視モードを切り替える場合は、切替先の最初の正常監視世代を受理した時点で、更新許可根拠を切替元から切替先へ一回だけ移管する。
次の情報は、同じ切替点に対応付けて保持する。

- 低消費電力監視中情報
- 選択済みMCU低消費電力モード
- 移行識別子
- 最終正常監視世代
- システム監視の進行世代
- 現在の更新許可根拠

標準低消費電力への切替えでは、初期`LP_MON_COMPLETE`を受理した後、かつ低消費電力移行コミットの前に、保持情報を成立させる。

通常監視への復帰では、次の両方を受理するまで、低消費電力監視中情報を解除しない。

- 切替先の最初の正常監視世代。
- 現在状態で必要なシステム監視条件の成立結果。

#### IWDT更新取引の管理

##### 更新命令の直前に保持する情報

本節では、更新前の情報保持、更新命令の実行、および関係機能による結果の受領確認を対応付けて管理する単位を「IWDT更新取引」と呼ぶ。

電源・省電力管理機能は、IWDT更新命令を実行する直前に、次の情報をIWDTリセット後に取得可能な状態で保持する。

- 更新取引識別子
- 更新元区分
- 更新許可根拠の識別情報
- 移行識別子または起動段階識別子
- 監視モードおよび監視世代
- システム監視の進行世代
- 更新試行時刻
- 異常通知取引識別子
- 予約済み異常識別子
- 主通知状態

更新状態は、少なくとも次の4種類を区別する。

- 更新命令実行直前
- 更新命令正常完了・受付結果受領確認待ち
- 完了
- 失敗

情報の保持が完了する前に、IWDT更新命令を実行しない。
また、完了または失敗が確定していない更新取引を、次の更新試行で上書きしない。

##### 更新結果と受領確認

1. IWDT更新命令が正常に戻った場合は、更新状態を「更新命令正常完了・受付結果受領確認待ち」とする。
2. 更新許可根拠を提供した関係機能から、同じ更新取引識別子に対応する受領確認を取得する。
3. この受領確認を取得した後にだけ、更新状態を「完了」とする。

更新受付結果を受領できない場合、受領結果が否定または不明である場合、または相関情報が一致しない場合は、完了としない。

##### 異常通知識別子の保持と使用

各IWDT更新取引では、異常通知取引識別子および予約済み異常識別子を、更新取引識別子とその適用対象へ対応付ける。
主通知状態は「通知待機（事象未確定）」として保持する。

適用対象には、次のうち当該取引に必要な情報を含める。

- 更新元区分
- 更新許可根拠
- 移行識別子または起動段階識別子
- 監視モードおよび監視世代
- 必要なシステム監視の進行世代

更新取引が正常完了した場合は、主通知状態を「通知不要（更新正常完了）」へ確定する。
この識別子群を、後から発生した更新制御失敗または監視期限超過に使用しない。

更新制御失敗が確定した場合だけ、主通知状態を「未通知」へ移し、同じ識別子群を用いて主通知する。
周期復帰未起動のように、新しい更新取引自体が存在しない事象にも、直前の正常完了取引の識別子群を流用しない。

#### IWDT更新失敗時の扱い

##### 更新済みとして扱わない条件

次のいずれかに該当する場合は、独立監視期限を更新済みとして扱わない。

- 更新許可根拠の世代、システム監視の進行世代または相関識別子が一致しない。
- 必要なシステム監視対象の正常進行を確認できない。
- IWDT更新命令が正常完了しない。
- 許可された更新ウィンドウ外となった。
- 更新受付結果を関係機能が確認できない。

##### リセット前に失敗を検出した場合

電源・省電力管理機能は、保持済みの異常通知取引識別子および予約済み異常識別子を使用して、異常管理機能へ主通知する。
同じ通知取引に対する受付結果と確定異常識別子を取得した場合だけ、通知完了とする。

通知完了を確認できた場合は、電源・省電力管理機能をIWDT更新制御失敗の主通知元とする。
再入眠およびアクチュエータ出力を禁止したまま、IWDTによるリセット経路へ移行する。
ここでいう「再入眠」は、一時的に動作したMCUを再び低消費電力モードへ移行させることを示す。

通知結果を確認できない場合も、主通知未完了として保持し、同じリセット経路へ移行する。
更新受付結果の通知失敗を、追加のIWDT更新で補わない。

#### IWDTリセット後の原因分類と引継ぎ

##### 前回の情報の保全と、今回の更新処理との分離

IWDT更新命令の実行中、または更新受付結果の受領確認待ちにIWDTリセットが先行した場合は、リセット前のソフトウェア通知完了を前提としない。

リセット後は、次の前回情報を原因分類用の保持情報として保全する。

- 更新主体および移管識別子
- 更新取引情報
- 監視情報
- システム監視の最終正常進行情報
- 異常識別子および主通知状態

この保全は、最初のIWDT更新、現在主体の初期化または監視世代の更新によって前回情報が失われる前に行う。
固定ブート・復旧機能または起動初期処理を含め、保全前に前回情報を今回の更新情報で上書きしない。

今回のIWDT更新処理は、前回の原因分類用情報とは分離して初期化する。
現在の起動に対応する更新実行権、起動段階、監視世代、システム監視進行世代および更新取引として管理する。

前回の未完了または失敗取引を正常完了へ読み替えず、前回の更新実行権を今回の実行権として流用しない。
今回の実行権は、固定ブート・復旧機能から電源・省電力管理機能への、本節で定めた移管手順で確立する。

##### 原因の分類

次回起動時の原因分類は、電源・省電力管理機能が担当する。
IWDTリセット要因と、次の保持情報を照合する。

- 更新主体および移管識別子
- 更新取引情報
- 低消費電力監視中情報
- 最終`LP_MON_START`および最終正常監視世代
- システム監視の最終正常進行情報
- 主通知状態および異常識別子

照合結果から、次のいずれかの分類を確定する。

- IWDT更新制御失敗（リセット先行）
- 周期復帰未起動
- 低消費電力監視バースト未完了
- 通常監視更新停止
- 重要処理進行停止
- 識別不能

##### 起動・終了・再起動管理機能へ提供する情報

分類結果と、その判断に使用した根拠情報を、起動・終了・再起動管理機能へ提供する。
照合結果には、次の情報を含める。

- 分類結果
- 根拠情報
- 更新主体および更新実行権移管識別子
- 更新元区分および更新状態
- 更新取引識別子、移行識別子、起動段階識別子、監視モード、監視世代およびシステム監視進行世代を含む相関識別情報
- 現在の更新許可根拠
- 最終`LP_MON_START`および最終正常監視世代
- 主通知状態
- 異常通知取引識別子
- 予約済みまたは確定済みの異常識別子
- 識別子群の適用対象
- リセット時の選択済みMCU低消費電力モード
- 取得不能・矛盾項目

起動・終了・再起動管理機能は、結果を取得できたか、および相関情報が整合しているかを確認し、安全側の起動処理と必要な主通知を実行する。
原因分類を重複して判定せず、照合結果を取得できない場合、または相関が矛盾する場合だけ、識別不能として扱う。

リセット前の主通知完了を同じ異常識別子で確認できる場合は、重複して主通知せず、今回のリセット情報を補足する。

#### IWDTリセット後に復旧を待つ間の更新

##### 現在の起動で使用する更新許可根拠

IWDTリセット後に起動失敗状態で明示的復旧を待つ期間も、IWDT更新命令は電源・省電力管理機能が実行する。
この期間の更新許可根拠には、次の両方を使用する。

- 現在の起動で通常監視を実行し、全必須測定・診断が有効に完了した、新しい正常監視世代。
- 現在状態で必要なシステム監視対象の正常進行確認結果。

これらは、起動・終了・再起動管理基本設計の第4.7節に定める待機条件を満たす範囲で使用する。
復旧待ちであること、単なる生存通知、過去の正常監視世代または前回の更新結果を、更新根拠としない。

##### 前回の未復旧異常と現在の監視結果の区別

前回の電源安全監視異常が未復旧であることと、現在の起動で監視処理およびIWDT更新経路が正常に動作していることを区別する。
前回異常を保持していることだけでは、現在の正常監視世代および正常進行確認結果に基づくIWDT更新を禁止しない。

一方、現在の次の異常を、前回異常の保持に伴うものとして無視しない。

- 必須測定・診断の失敗
- システム監視の進行停止
- 世代不一致
- 更新取引失敗
- 結果確認不能

##### 待機可否の判断前と、待機条件を維持できない場合

起動・終了・再起動管理機能が待機可否を判断する前でも、現在の起動に適用される正当な更新条件が成立している場合は、IWDTを更新できる。
待機許可を最初のIWDT更新の前提条件としない。

新しい正常監視世代および必要なシステム監視条件に対応する更新取引の正常完了結果を、待機可否の確認に使用できるよう提供する。

現在の起動で、待機に必要な正常監視世代、システム監視の正常進行条件または正常な更新経路を確立・維持できない場合は、その失敗または確認不能の結果を起動・終了・再起動管理機能へ提供する。
復旧待ちを継続するための追加更新は行わず、同基本設計の第4.7節、第6.3節および第7.5節に従う遮断経路へ引き継ぐ。

#### 遮断できない電源系統を通電維持監視へ切り替える条件

遮断要求後も`PWR_DRIVE`または`PWR_SERVO`がONである場合、直ちに通電維持監視モードへ読み替えない。
次の条件をすべて確認した場合だけ、目標を「既知ON・出力禁止の通電維持縮退」へ明示的に再設定する。

- 電源良好信号その他の独立した確認手段によって、実状態が既知のONであることを確認できる。
- 出力禁止が成立している。
- 電流が零点許容範囲内である。
- 必要な監視およびハードウェア保護が成立している。
- バッテリー・電気安全監視機能から、成立した通電維持縮退情報を取得している。

実状態が矛盾または不明である場合は、通電維持縮退へ移行せず、第9.5節の電力状態不明として移行を失敗させる。
通電維持縮退は電力状態とは別の縮退属性として管理し、実電力状態は通常電力として保持する。

#### 保持情報と復帰要因

低消費電力状態では、`PWR_CTRL`の供給を維持し、高速クロック、通常タスクおよび不要な周辺機能を停止する。
次の情報は、復帰後に参照できるRAM領域へ保持する。

- 現在のシステム状態
- 電源・省電力管理機能の内部状態
- 移行識別子
- 復帰要因
- 安全関連事象
- 有効な設定世代

RA8M2の復帰要因は、以下を基本とする。

- RYZ012A1からのBLE接続要求通知
- 主電源操作部からの通常終了要求
- 本体側緊急停止入力
- 電気安全監視回路からの通常動作禁止異常通知
- バッテリー電圧および温度監視のためのAGT1アンダーフロー

#### 一次資料による確認範囲と後続の評価

RenesasのRA8M2対応FSP一次資料により、LOCOを使用するAGT、AGT1アンダーフローによるSoftware Standby復帰、独立クロックで動作するIWDT、IWDTの低消費電力時停止制御および期限超過時のリセット機能が提供されることは確認済みである。

これは、採用する基本方式に必要な機能の存在確認である。
具体的なOFS設定、許容差を含む期限、最終基板上の出力安全化および実機動作を検証済みとするものではない。

具体的なレジスタ設定、クロック停止範囲、割込み番号および端子割付けは、ソフトウェア・ハードウェア詳細設計で定め、第12章に従って評価する。

### 3.5 システム状態ごとの基本電力方針

| システム状態または処理 | 制御・通信 | アクチュエータ | 表示 | 安全監視・復帰 |
| --- | --- | --- | --- | --- |
| 起動処理状態 | 制御部とBLEを順次起動。Wi-Fiは必要時だけ起動 | 出力禁止のまま初期化し、安全確認後も操作許可まで有効化しない | 起動処理表示 | 通常監視を優先して確立 |
| BLE接続待機状態 | 制御部は通常動作、BLEは接続可能アドバタイズ、Wi-Fiは必要時のみ | 走行出力無効、サーボPWM停止。不要な駆動電源は停止可能 | BLE接続待機表示 | 通常監視を継続 |
| 操作可能状態 | 制御部とBLEは通常動作、Wi-Fiは処理要求に応じて起動 | 使用前に電源状態と安全条件を確認し、許可された機能だけ使用可能 | 操作可能表示 | 通常監視を継続 |
| OTA更新状態 | 制御部とWi-Fiを更新処理に必要な状態へ維持 | 走行出力無効、サーボPWM停止、駆動電源は停止 | OTA更新表示 | 通常監視を継続 |
| 低消費電力移行中 | 制御部はシーケンス完了まで動作、BLEを低頻度化、Wi-Fiを停止・スリープ | 安全停止確認後に出力無効化、PWM停止、電源停止・低減 | 移行中情報を提供 | 監視と復帰入力を先に確立 |
| 低消費電力状態 | 制御部は低消費電力、BLEは低頻度アドバタイズ、Wi-Fiは原則スリープ。第7.3節の縮退条件成立時だけ覚醒通電待機 | 停止状態と出力無効を維持 | 必要最小限の低消費電力表示 | 省電力監視、復帰入力およびハードウェア保護を維持 |
| 復帰中 | 復帰要因に必要な制御・通信だけを復帰。通常復帰ではWi-Fiを起動しない | 停止、出力無効およびPWM停止を維持 | 復帰中情報を提供 | 通常監視を先に復帰 |
| 終了処理状態 | 保存と終了に必要な機能を維持し、不要な通信を停止 | 安全確認後に駆動電源を停止 | 終了処理表示 | MCU停止可能となるまで監視を継続 |
| 緊急停止・異常停止・起動失敗状態 | 処置、通知および診断に必要な機能だけを維持 | 原則として停止、出力無効およびPWM停止 | 上位優先度の安全表示 | 対象異常に必要な監視を継続 |

### 3.6 同一システム状態内の電力状態変更

同一のシステム状態であっても、Wi-Fi通信、VPS通信、ログ送信、設定取得、診断またはその他の処理要求に応じて、対象機能の電力状態を変更できる。

機能を使用する側は、電源・省電力管理機能へ使用要求を通知し、使用可能結果を取得してから処理を開始する。使用要求を取り下げた場合、電源・省電力管理機能は、他の使用主体が存在しないことと、処理中データの整合性を確認してから対象機能を待機、スリープまたは停止へ変更する。

複数機能が同じ電源系統を共有する場合は、使用中の機能が一つでも存在する間は当該電源系統を維持する。論理的な使用要求は、参照カウント等の利用要求管理によって管理し、要求元の異常終了による解放漏れを診断可能とする。

低消費電力移行に伴う走行・砲塔・砲身の停止準備は、電源・省電力管理機能から停止・緊急停止管理機能へ現在の移行識別子および停止目的を付けて要求する。停止・緊急停止管理機能は、必要な停止要求識別子を管理して走行制御および砲塔・砲身制御へ同じ停止取引を展開し、局所結果を集約して返す。電源・省電力管理機能は、同じ物理停止を走行制御または砲塔・砲身制御へ別途要求しない。すでに必要な局所停止状態が成立している場合は、新たな物理停止を重複実行せず、既存の停止状態を当該移行の準備結果として相関して扱う。

電源・省電力管理機能は、停止・緊急停止管理機能から同じ移行識別子に対応する受付結果および正常完了結果を取得するまでアクチュエータ停止準備を完了とせず、失敗、中止または識別子不一致を低消費電力移行条件の成立に使用しない。停止・緊急停止管理機能が返す結果は、走行出力無効、PWM停止、保留指令破棄その他の局所停止・電力変更準備の集約結果であり、`PWR_DRIVE`または`PWR_SERVO`の実電力状態ではない。実際の対象系統のON/OFFおよびその確認は電源・省電力管理機能が行う。

電気安全監視の監視モード変更では、電源・省電力管理機能が監視モード変更要求識別子、要求監視モード、対象電源系統の要求状態・実状態を指定し、低消費電力処理中は移行識別子、未確定候補確認では候補事象識別子を追加して変更を要求する。バッテリー・電気安全監視機能が監視条件の成立を判断して変更を実行し、同じ要求識別子により監視モード変更完了・失敗、実監視モード、監視利用可否、継続監視条件、切替後最初の正常監視世代および通電維持縮退情報を返す。電源・省電力管理機能は、対応する完了結果と切替後最初の正常監視世代を受け取る前に監視モードが切り替わったものとして扱わない。監視継続要求、安全要因による復帰要求または電気安全事象は、監視モード変更結果とは別の高優先度情報として受け付ける。

低消費電力安全監視世代には、移行識別子、単調増加する監視世代、開始時刻、完了時刻および結果を対応付ける。開始結果だけ、必須測定の一部だけ、前世代の遅延完了または無関係な処理の生存確認を、独立監視期限の更新根拠として使用しない。監視バースト失敗、未完了、前世代または移行識別子不一致の場合は独立監視期限を更新しない。有効な測定によって警告・危険・異常候補を検出した世代は、一致する`LP_MON_COMPLETE`を受理し、当該低消費電力状態で必要なシステム監視条件を満たした時点で一度だけ更新した後、監視継続要求または安全要因による復帰要求に従って再入眠を禁止する。監視継続要求または安全要因による復帰要求は、成立済みの正常完了世代を取り消さない。

低消費電力移行コミット許可は、システム状態管理機能による低消費電力状態への状態移行処理開始要求の最終段階として扱い、独立したシステム状態遷移要求とはしない。

「通常操作に必要な電源条件」は、`PWR_CTRL`、`PWR_BLE`および通常安全監視が使用可能であり、走行駆動部とサーボ駆動部の電力状態が既知で、必要時に安全に使用可能状態へ変更でき、通常操作を禁止する電力状態異常がない場合に成立とする。Wi-FiおよびVPSの利用可否は、この条件に含めない。

「低消費電力状態への移行条件」は、現在状態がBLE接続待機状態であり、第6.1節の条件がすべて成立し、電源・省電力管理機能が他の排他的な電力状態変更を実行中でない場合に成立とする。

## 4. 個別機能の電力状態変更

### 4.1 電力状態管理情報

省電力対象機能ごとに、少なくとも次の情報を管理する。

- 現在電力状態
- 目標電力状態
- 変更中か否か
- 使用要求元
- 変更開始時刻
- 直近の変更理由
- 直近の変更結果
- 電力状態を確認した時刻
- 失敗回数および連続失敗の有無

現在状態を確認できない場合は「使用可能」とみなさず、電力状態不明として異常管理機能へ通知する。

### 4.2 電源投入・復帰の共通順序

個別機能を停止またはスリープから使用可能へ変更するときは、次の順序を基本とする。

1. 対象機能への通常処理要求を禁止する。
2. 出力許可信号、PWM、通信送信許可その他の能動出力を安全側へ固定する。
3. 必要な電源系統、クロックまたはモジュールを起動する。
4. 電源・省電力管理機能が電源良好信号その他の確認手段によって実電力状態と規定の安定条件を確認する。
5. 対象機能へ初期化または復帰処理を要求し、通信、ドライバ、安全出力その他の局所診断結果を取得する。
6. 電源系統の実状態と対象機能の局所結果を分離して管理し、必要な条件が成立した場合に電力状態を使用可能へ更新して要求元へ完了結果を返す。
7. システム状態と操作許可が別途成立した場合に限り、対象機能の使用を許可する。

電力状態が使用可能となったこと、対象機能の初期化・局所診断が正常であること、および通常操作が許可されたことを分離する。特に走行駆動部とサーボ駆動部は、電源復帰だけで駆動出力を有効にしない。走行制御または砲塔・砲身制御が返す初期化・利用可否結果を、`PWR_DRIVE`または`PWR_SERVO`の実電力状態へ読み替えない。

電気安全監視の初期化後に投入する`PWR_DRIVE`、`PWR_SERVO`、`PWR_BLE`、`PWR_WIFI`および`PWR_DISPLAY`の実効Enableは、電源・省電力管理機能の投入要求と、バッテリー・電気安全監視機能による当該系統の安全許可信号との論理積とする。

`PWR_DRIVE`および`PWR_SERVO`は、次の規則で扱う。

1. OFFからONへ切り替える場合、ならびに保護後に再投入する場合は、通常操作開始可能を安全許可の必須条件とする。これが不成立または不明の間は、投入要求があっても有効化しない。
2. 対象系統が既知のONである間は、通常操作開始可能だけが不成立となったことを理由として実効Enableを直ちに解除しない。
3. 通常操作継続可能が不成立となった場合は、新規出力禁止と原因別の安全停止を開始し、停止後に定めた遮断または終了処理へ進む。
4. 危険低電圧、ハードウェア即時保護、監視不能その他、本設計で即時遮断を定める条件では、停止完了を待たず安全許可信号の解除による強制OFFを受け入れる。
5. 対象系統がOFFとなった後の再投入には、通常操作開始可能を改めて確認する。

限定復旧に使用する`PWR_BLE`、表示その他の非アクチュエータ系統は、通常操作開始可能とは分離する。当該系統の電気安全条件と、システム状態管理機能による限定復旧処理の状態上の実行許可が成立した場合に限り投入できる。

安全許可信号が不成立または不明の場合は、投入要求を出力中であっても当該系統を有効化しない。一方、電気安全監視機能が単独で安全許可を成立させても、投入要求がなければ当該系統を有効化しない。

`PWR_CTRL`および`PWR_SAFETY`の初期投入は、このソフトウェア安全許可ゲートの対象外とする。`PWR_AON`上の独立入力保護が逆接続、過電圧、低電圧および主保護の未作動を確認し、起動・終了・再起動管理の起動経路が主電源投入を要求した場合に両系統を先に確立する。両系統の確立後にバッテリー・電気安全監視機能を初期化し、その正常結果と安全許可信号を確認してから負荷側電源系統を投入する。

### 4.3 電源停止・スリープ移行の共通順序

個別機能を使用可能から停止またはスリープへ変更するときは、次の順序を基本とする。

1. 新規の使用要求を禁止する。
2. 実行中処理を規定時間内に正常終了または安全に中断する。
3. アクチュエータ、通信出力および書込み処理を安全な状態へ移行する。
4. 出力無効、PWM停止、通信停止またはデータ整合性を確認する。
5. 電源・省電力管理機能が対象機能をスリープへ移行するか、対象電源系統の供給を停止・低減する。
6. 電源良好信号、端子状態その他の確認手段によって対象電源系統の実状態、逆給電および共有電源系統への影響がないことを確認する。
7. 変更後の電力状態を更新し、要求元へ完了結果を返す。

走行駆動部またはサーボ駆動部についてステップ1から4の停止・出力無効化が必要な場合は、停止・緊急停止管理機能が停止取引として対象機能へ展開し、局所結果を集約する。電源・省電力管理機能は、その集約結果を受けてステップ5以降の実電力状態変更を担当し、同じ物理停止を対象機能へ直接重複要求しない。対象機能の局所準備完了を電源供給停止の完了とは扱わず、ステップ6で実電力状態を確認した後に電源状態変更を完了とする。

個別機能がタイムアウトした場合でも、待機を無期限に継続しない。安全に中断できない処理は低消費電力移行を阻止し、安全に中断できる処理は中断結果を記録して次へ進む。

本節の通常の停止順序は、危険低電圧、危険過電流、短絡、重大な異常発熱、停止失敗その他の電気的保護を理由とする対象系統遮断には適用しない。バッテリー・電気安全監視機能または異常管理機能から`PWR_DRIVE`もしくは`PWR_SERVO`の対象系統遮断要求を受け付けた場合は、対象系統の新規使用要求を直ちに禁止し、既に成立している出力禁止を維持したまま、要求された系統のソフトウェア制御可能な遮断を開始する。危険過電流については、電気安全監視機能が停止後の過電流継続または停止失敗を確認して遮断を要求するため、電源・省電力管理機能は緊急停止処理の開始・復帰・完了、通常処理の完了、通信応答、ログ記録または異常管理機能の追加判断を待たずに遮断する。

対象系統遮断後は、電源良好信号その他の独立した確認手段によって実状態を確認し、電力状態変更要求識別子、電気安全事象識別子または異常識別子、対象系統、受付時刻、遮断開始時刻、実状態、遮断結果および失敗理由を要求元と異常管理機能へ提供する。遮断に失敗した場合、または実状態を確認できない場合は成功と扱わず、利用可能な独立保護を妨げない。電気的保護を目的として必要と確定した遮断の失敗結果は、電気安全監視機能が本体電源遮断必要を判断するための直接入力とする。電源・省電力管理機能は本体電源遮断必要の中継主体とはならず、電気安全監視機能から起動・終了・再起動管理機能への直接要求を待ち合わせまたは妨げない。

### 4.4 ハードウェアとの境界

電源・省電力管理機能は、H01が定める電源制御信号、電源状態信号および保護状態を使用し、要求した論理状態とread-backから確認した論理実電力状態を管理する。

電源domain名、独立して論理状態変更する必要がある範囲および低消費電力状態の基本方針は第3.3節を正本とする。物理電源ツリー、個々の電源スイッチ、立上り・立下り時間、逆給電防止回路、プルアップ電源、通信端子のHi-Z化、電源断中の端子許容条件およびread-back信号の電気的成立はH01を正本とし、具体部品・回路定数・pinはハードウェア詳細設計で確定する。

重大な過電流、危険な過放電その他の即時保護は、MCUの動作状態に依存しないハードウェア保護を使用する。電源・省電力管理機能は、その保護を解除、迂回または省電力のために停止しない。

短絡または重大過電流に対するハードウェアの即時電流制限・遮断は、第4.3節のソフトウェア要求受付、停止結果または対象系統遮断処理を待たずに作動する。電源・省電力管理機能は、保護作動後に取得できる保護状態および実電力状態を関係機能へ提供するが、ハードウェア保護の開始主体とはならない。

## 5. 長時間未操作の管理

### 5.1 未操作時間の管理

未操作時間は、単調増加する内部時刻を用いて管理し、壁時計の設定変更やネットワーク時刻の有無に依存させない。

起動後にBLE接続待機状態が有効となった時点、および通常復帰によりBLE接続待機状態が有効となった時点で、未操作監視の基準時点を初期化する。その後、未操作時間を更新する有効な操作を受け付けるたびに最終有効操作時点を更新する。

長時間未操作判定に用いる時間を `T_LONG_IDLE` とし、工場出荷時の基本値を10分とする。

`T_LONG_IDLE`は電源・省電力設定として設定パッケージに含めることができ、製品で許可する設定範囲を5分以上60分以下、設定単位を1分とする。0による低消費電力移行の無効化は許可しない。開発・評価時に使用する短縮値は製品設定と分離し、通常の設定パッケージでは指定できないようにする。

設定管理機能は、`T_LONG_IDLE`の値域、設定パッケージの正当性・完全性および適用条件を確認し、正常に確定した有効値を電源・省電力管理機能へ提供する。電源・省電力管理機能は設定値を独自に補正せず、無効な値を受け付けた場合は直前の正常値を維持し、直前の正常値も使用できない場合は工場出荷値10分を使用する。

新しい`T_LONG_IDLE`は、設定パッケージの適用完了後、BLE接続待機状態で未操作監視の基準時点を再設定した時点から使用する。設定値の短縮によって、適用直後に過去の経過時間を用いて低消費電力移行を開始しない。

### 5.2 未操作時間を更新する操作

| 受信内容 | 未操作時間の更新 | 理由 |
| --- | --- | --- |
| 認証済みかつ操作権限を持つ端末から受け付けた走行操作 | 更新する | 有効な利用者操作である |
| 認証済みかつ操作権限を持つ端末から受け付けた砲塔・砲身操作 | 更新する | 有効な利用者操作である |
| 認証済み端末から受け付けた停止操作 | 更新する | 利用者が明示した有効な操作である |
| 認証済み端末から受け付けた所有者管理、設定変更または診断開始 | 更新する | 利用者が明示して開始した有効な処理である |
| 通常終了要求または緊急停止要求 | 更新対象外 | 未操作時間より高い優先度で直ちに処理する |
| BLE接続、認証処理または定期的な状態取得だけ | 更新しない | 通常操作の実施を示さない |
| Keep Alive、Ack、再送または重複メッセージ | 更新しない | 通信維持または同一操作の再処理である |
| 妥当性確認に失敗した操作、未認証・権限なし端末の操作 | 更新しない | 有効な操作として受け付けていない |
| 受信失敗、CRC不一致、形式不正または期限切れの操作 | 更新しない | 実行対象とならない |

BLE接続・認証機能が、認証、権限、形式、範囲、鮮度および重複を確認した後に発行する「有効操作受付」だけを更新契機とする。

### 5.3 操作指令タイムアウトとの分離

操作指令タイムアウトは、操作可能状態で安全停止を開始するための短時間監視であり、長時間未操作はBLE接続終了と低消費電力移行を開始するための長時間監視である。両者は異なるタイマ、判定結果およびログ要因として管理する。

操作指令タイムアウトによる安全停止が成立しても、それだけを理由として低消費電力状態へ移行しない。最終有効操作時点から `T_LONG_IDLE` が経過したときに、長時間未操作条件を成立させる。

### 5.4 長時間未操作成立後の連携

操作可能状態で長時間未操作条件が成立した場合、電源・省電力管理機能は、BLE接続・認証機能へ長時間未操作による接続終了要求を提供するとともに、システム状態管理機能へ長時間未操作条件の成立を通知する。

BLE接続・認証機能は、接続終了処理を実行し、その結果およびBLE接続状態を関連機能へ提供する。

システム状態管理機能は、長時間未操作条件の成立およびBLE接続終了結果に基づいて、BLE接続待機状態への遷移を管理する。

長時間未操作を理由として操作可能状態からBLE接続待機状態へ遷移した場合は、低消費電力移行判断に使用する未操作時間を初期化しない。電源・省電力管理機能は、BLE接続待機状態となり、かつ第6.1節の移行開始条件が成立した時点で、低消費電力状態への移行条件成立をシステム状態管理機能へ通知する。

BLE接続・認証、走行制御および砲塔・砲身制御の各機能は、長時間未操作により接続または通常操作が終了した場合、受信済みの未実行操作を破棄し、その完了結果を関連機能へ提供する。電源・省電力管理機能は、各機能の完了結果を確認するが、各機能の操作キューを直接管理しない。

## 6. 低消費電力状態への移行

### 6.1 移行開始条件

通常の未操作を理由とする低消費電力移行は、現在状態がBLE接続待機状態であり、かつ次の条件をすべて満たす場合に開始する。

- 長時間未操作条件が成立している。
- 走行駆動部が停止し、駆動出力が無効である。
- 砲塔および砲身が定義された安全状態にあり、サーボPWMを安全に停止できる。
- 実行中の通常操作が存在しない。
- 緊急停止要求が成立していない。
- 通常終了要求が成立していない。
- OTA更新状態ではなく、OTA更新開始処理も実行中でない。
- 通常動作の継続を禁止する異常が成立していない。
- BLE接続、認証、端末登録または所有者管理が実行中でないか、規定時間内に安全に完了または中断できる。
- 設定データ、不揮発データ、ログまたはファームウェアの整合性に影響する処理が実行中でないか、安全に完了または中断できる。
- Wi-Fi・VPS処理が完了済みであるか、規定時間内に安全に完了または中断できる。
- 必要な安全監視と復帰入力を低消費電力状態で維持できる。

条件が成立していない場合は、低消費電力状態へ遷移しない。待機可能な処理については完了または安全な中断を要求するが、Wi-Fi・VPS上の管理処理だけを理由として無期限に移行を延期しない。

### 6.2 移行シーケンス

| 順序 | 処理 | 完了確認 |
| --- | --- | --- |
| 1 | システム状態管理機能からの移行開始を受け付け、移行識別子と理由を確定する | 現在状態、優先要求および移行条件が有効 |
| 2 | 状態移行処理中情報に基づき、BLE接続・認証、走行制御および砲塔・砲身制御が通常操作の受付・実行を禁止し、未実行指令を破棄する | 各担当機能からの操作禁止状態と指令破棄結果 |
| 3 | 停止・緊急停止管理機能へ、移行識別子と停止目的「低消費電力移行準備」を伴うアクチュエータ停止・電力変更準備を要求する。停止・緊急停止管理機能が走行制御および砲塔・砲身制御へ必要な停止取引を展開する | 同じ移行識別子に対応する準備受付・正常完了結果、走行の局所停止・出力無効結果、砲塔・砲身のPWM停止・局所準備結果 |
| 4 | 整合性に影響する保存、設定および更新処理を完了または安全に中断する | 各処理の完了・中断結果 |
| 5 | Wi-Fi・VPS通信を正常終了または安全に中断し、Wi-Fi通信部をスリープへ移行する。スリープ失敗時は第7.3節の縮退条件を確認する | 通信終了・中断結果、Wi-Fiの実状態および自動再接続禁止状態 |
| 6 | ステップ3の局所準備成立後、電源・省電力管理機能が走行駆動部とサーボ駆動部の制御可能な電源を停止または低減する | 電源・省電力管理機能が確認した`PWR_DRIVE`、`PWR_SERVO`の実電力状態。局所準備結果だけでは電源OFF完了としない |
| 7 | 残存するBLE接続・認証処理を安全に終了し、BLE通信部を接続可能な低頻度アドバタイズへ切り替える | BLE切断結果、アドバタイズ状態と接続要求通知経路 |
| 8 | 状態表示部へ低消費電力表示への切替を要求する | 表示要求の受付結果。表示完了自体は安全上の遷移条件にしない |
| 9 | 電源系統の実状態に対応する監視モードへの変更をバッテリー・電気安全監視機能へ要求し、通常終了、緊急停止、異常およびBLE接続要求の検出経路を有効にする | 監視モード変更完了、実監視モード、監視利用可否、継続監視条件、有効な復帰入力および安全監視状態 |
| 10 | 移行理由、処理結果および縮退情報を保持し、可能な範囲で記録する | 保持結果。ログ記録失敗だけでは移行を阻止しない |
| 11 | 残存する監視負荷に応じて第3.4節のMCU低消費電力モードを選択する。標準モードではAGT1周期復帰、IWDT独立期限監視、期限超過リセットおよびリセット時出力禁止を設定し、コミット直前の初期安全監視世代と当該状態で必要なシステム監視条件を実行して有効性を確認する。その後、コミット可能結果、選択済みモードおよび縮退情報を通知する | 第6.3節のコミット可能条件 |
| 12 | システム状態管理機能が他の必須結果と優先要求を再確認し、低消費電力移行コミットを許可する | コミット許可と移行識別子の一致 |
| 13 | システム状態の確定、状態移行処理中情報の解除、移行正常完了結果の確定および制御部の選択済みMCU低消費電力モードへの移行を不可分にコミットする | 低消費電力状態の成立。詳細は第6.3節 |

電源・省電力管理機能は、各担当機能へ処理を要求して完了結果を確認するが、各担当機能の操作キュー、通信状態または内部停止処理を直接管理しない。アクチュエータの同一物理停止は停止・緊急停止管理機能を経由して一つの停止取引として扱い、電源・省電力管理機能から重複して開始しない。

システム状態管理機能が低消費電力移行コミットを許可するまでの間、現在のシステム状態はBLE接続待機状態であり、状態移行処理中情報によって通常処理を禁止する。

### 6.3 移行完了条件およびコミット

次の条件をすべて満たした場合に、電源・省電力管理機能は低消費電力移行をコミット可能と判断する。

- 通常操作の受付と実行が禁止されている。
- 未実行のアクチュエータ操作が残っていない。
- 停止・緊急停止管理機能から同じ移行識別子に対応する低消費電力移行準備の正常完了結果を取得し、走行の局所停止・出力無効および砲塔・砲身のPWM停止・局所準備が成立している。
- `PWR_DRIVE`および`PWR_SERVO`について、電源・省電力管理機能が移行方針に対応する実電力状態を確認できている。停止管理または各制御機能の局所結果だけを実電力状態の確認に使用しない。
- 整合性に影響する処理が完了または安全に中断されている。
- BLE接続・認証処理が終了し、接続可能なアドバタイズへ移行している。
- BLE接続要求を復帰要因として検出できる。
- 通常終了要求、緊急停止要求および必要な安全関連事象を検出できる。
- バッテリー・電気安全監視機能から監視モード変更正常完了結果を取得し、電源系統の実状態に必要な電気安全監視が有効である。
- 標準モードでは、AGT1がLOCOを用いた1秒周期で動作し、Software Standbyの復帰要因として有効である。また、IWDTがAGT1とは独立したクロックでSoftware Standby中も継続し、監視期限超過時にMCUをリセットする設定が有効である。
- コミット直前に、第7.1節と同じ必須監視対象および完了条件を用いた初期低消費電力安全監視世代を実行し、正常完了として確定するとともに、当該低消費電力状態で必要なシステム監視条件が成立している。監視世代が未初期化、失敗、更新期限超過、不一致または必要なシステム監視結果が未成立の場合はコミット可能としない。
- MCUリセット時に走行出力許可、サーボPWM許可その他のアクチュエータ能動出力がハードウェア初期値で安全側となり、起動処理が安全条件を再確認するまで有効化されない。
- 第3.4節に従ってMCU低消費電力モードが選択され、当該モードに必要な保持、クロック・周辺機能の停止範囲、監視処理および復帰要因の設定が完了している。
- 必須省電力処理に失敗がない。

Wi-Fiスリープ、BLE低頻度化、状態表示またはログ保存の一部に失敗しても、安全監視、アクチュエータ停止および復帰能力が維持される場合はコミット可能とする。ただし、Wi-Fiスリープ失敗を許容する条件は、第7.3節の覚醒通電待機縮退条件をすべて満たす場合に限る。この場合は正常完了結果に移行識別子と対応付けた縮退情報を付加し、縮退した対象を電力状態異常として保持して、復帰後に異常管理および診断へ通知する。縮退を独立した状態遷移結果として扱わない。

低消費電力移行コミットは、次の規則で実行する。

1. 電源・省電力管理機能がコミット可能結果を提供した後、システム状態管理機能が当該移行の全必須結果、移行識別子および上位優先要求の不存在を確認する。
2. システム状態管理機能がコミットを許可し、通常タスクおよび低優先度イベントの実行を停止する。安全関連入力と復帰入力は、割込み禁止によって失われないようハードウェアまたは保持領域へラッチする。
3. 一つのクリティカル区間内で、システム状態管理機能による現在状態の低消費電力状態への更新および状態移行処理中情報の解除、電源・省電力管理機能による移行正常完了結果の確定、ならびにRA8M2の選択済みMCU低消費電力モードへの移行命令を連続して実行する。この間に通常タスク、状態参照要求または低優先度イベントを実行しない。ただし、通電維持監視モードで必要な安全監視タスクは、モード移行後に定めた周期で実行する。
4. 選択済みMCU低消費電力モードへの移行命令後は、標準モードでは定義された復帰要因が成立するまで通常の命令実行を継続せず、通電維持監視モードでは安全監視以外の通常処理を実行しない。定義された復帰要因によって直ちに復帰した場合は、低消費電力状態が成立した後に復帰要因が成立したものとして第8章の復帰処理へ進む。
5. 選択済みMCU低消費電力モードへ移行せず、定義された復帰要因もないまま当該モードで禁止した通常処理が継続した場合は、同じクリティカル区間内で現在状態の更新と移行正常完了結果を取り消し、状態移行処理中情報の解除を取り消す。外部へ低消費電力状態を通知せず、低消費電力移行失敗として第9章に従う。

MCU低消費電力モードの成立は、単なる移行命令の呼出しではなく、RA8M2が当該命令を受理し、選択済みモードに従って通常命令の実行を停止または制限した時点とする。命令直前にコミット保留時刻を保持領域へ書き、次に通常命令を実行した時点で、低消費電力状態遷移ステータスおよび復帰要因を確認する。選択済みモードへの実移行を確認できた場合だけ保留時刻を移行正常完了時刻として有効化する。定義された復帰要因なしに命令が継続実行へ戻った場合、または実移行を確認できない場合は、移行正常完了として扱わずステップ5のロールバックを行う。消費電流、クロックおよび周辺機能状態による実モード成立性は第12.3節の評価で確認する。

このコミット処理により、MCU低消費電力モード移行より先に低消費電力状態だけが外部から有効に見える期間を設けない。システム状態管理機能が低消費電力状態を有効にする時点と、電源・省電力管理機能が選択済みMCU低消費電力モードへ移行する時点を、論理上の同一コミット点として扱う。

### 6.4 移行中の割込み

移行中に上位優先度の要求を検出した場合は、新たな省電力処理を開始せず、要因、移行識別子、完了済み処理および現在の電力状態をシステム状態管理機能へ通知する。状態遷移としての中断および復元は、システム状態管理機能から中断要求または復元要求を受けた後、次のように処理する。ただし、強制電源遮断および安全上直ちに必要な出力禁止は要求を待たずに実行する。

停止・緊急停止管理機能へ要求した低消費電力移行準備が未完了である場合は、同じ移行識別子を伴う中止要求を提供する。中止結果の待機によって高優先度の安全処理を遅延させず、受け取った中止結果は当該移行の後処理完了確認に使用する。

| 割込み要因 | 処理 |
| --- | --- |
| 強制電源遮断 | ソフトウェア完了を待たず、ハードウェア経路で電源を遮断する |
| 緊急停止 | 安全上必要な出力禁止を直ちに維持し、状態管理からの中断要求に従って緊急停止処理に必要な制御機能を維持または復帰させる |
| 通常動作禁止異常 | 安全上必要な処置を直ちに開始し、状態管理からの中断要求に従って異常処置に必要な機能を維持または復帰させる |
| 通常終了 | 状態管理からの中断要求に従って低消費電力移行を中断し、終了処理に必要な機能を維持または復帰させる |
| BLE接続要求 | 必須安全処理の途中でなければ、状態管理からの中断・復元要求に従ってBLE接続待機状態に必要な機能を復元する |

中断時も、アクチュエータ停止、駆動出力無効およびサーボPWM停止を維持する。移行中に受信した通常操作は復帰後へ引き継がない。

### 6.5 移行時間

システム要求上の低消費電力移行時間は、システム状態管理機能が低消費電力状態への状態移行処理を開始した時点から、第6.3節のコミットによって低消費電力状態が成立し、RA8M2が実際に選択済みMCU低消費電力モードへ移行した論理コミット点までとする。

移行時間には、アクチュエータ停止、通信終了・中断、各電源ドメインの変更、監視モード変更、MCU低消費電力モード選択、復帰要因設定、移行命令の受理および実モード成立までを含める。命令直前のコミット保留時刻は、第6.3節の実移行確認に成功した場合だけ正常完了時刻として確定し、移行失敗時は使用しない。

目標完了時間を5秒以内、許容最大時間を10秒以内とする。表示完了、任意ログの永続化または外部通信の応答を待つことによって、許容最大時間を超えてはならない。

## 7. 低消費電力状態中の管理

### 7.1 維持する機能

低消費電力状態中は、次の機能を維持する。

- 左右モータ停止および走行駆動出力無効状態の維持
- 砲塔・砲身の安全状態およびサーボPWM停止状態の維持
- BLEの接続可能な低頻度アドバタイズ
- BLE接続要求の検出と制御部への復帰通知
- 通常終了操作および緊急停止操作の検出
- バッテリー電圧、必要な温度およびその他の継続が必要な電気安全監視
- 通常動作を禁止する異常の検出
- 低消費電力状態であることを識別できる必要最小限の表示
- 復帰要因と安全関連事象を失わずに引き継ぐための保持

#### 安全監視のための一時動作と通常復帰の区別

安全監視のために周期的な内部起動が必要な場合は、必要な測定と判定だけを実行して低消費電力モードへ戻る。
この内部起動は、システム状態の復帰とは扱わない。
通常操作、Wi-Fi通信、VPS通信、OTA更新または安全性に影響する設定適用を開始しない。

一時的に動作したMCUを、再び低消費電力モードへ移行させることを「再入眠」と呼ぶ。
監視継続要求または安全要因による復帰要求がある場合は、内部監視が終わったことだけを理由に再入眠せず、以下の規則に従う。

#### 標準モードでの周期的な安全監視

##### 監視周期と正常完了の確認

低消費電力状態中のソフトウェア安全監視周期を表す基本値を`T_LP_SAFETY_MONITOR`とし、1秒とする。
LOCOで動作するAGT1によって少なくとも1秒ごとに制御部を一時起動し、バッテリー電圧、バッテリー表面温度およびモータドライバ温度を更新する。

標準モードでは、次の順序で監視結果を確認する。

1. AGT1アンダーフローによる周期復帰ごとに、新しい低消費電力安全監視世代を開始する。
2. バッテリー・電気安全監視機能から、同じ世代の`LP_MON_START`開始結果を受け取る。
3. 同機能から、当該世代で必須とするバッテリー電圧、バッテリー表面温度、モータドライバ温度および保護状態について、取得・妥当性確認がすべて正常完了した結果を受け取る。
4. 低消費電力状態で動作が必要なシステム監視対象について、正常進行を確認する。

必要な結果と条件をすべて確認できた場合だけ、その世代を正常完了としてIWDTを更新する。
移行識別子と監視世代の照合およびIWDT更新取引の完了確認は、第3.4節に従う。
低消費電力状態で意図的に停止している通常周期処理は、更新条件へ含めない。

##### 警告・危険・異常候補を検出した場合

警告・危険・異常候補を有効な測定で検出した世代も、一致する`LP_MON_COMPLETE`と必要なシステム監視条件を、一度だけIWDT更新の根拠に使用する。
ただし、監視継続要求または安全要因による復帰要求に従って、再入眠しない。

監視が正常に完了したことと、再入眠してよいことは区別する。

##### 監視処理が失敗した場合

監視バーストが起動しても、次のいずれかが失敗した場合は、正常完了として扱わずIWDTを更新しない。

- 測定、ADCまたはDMA
- 割込み
- 妥当性確認
- 必須状態の取得
- 必要なシステム監視

失敗時に維持する機能および通知先は、本節の「監視結果を確認できない場合の安全処理と通知」に従う。

#### 通電を維持する電源系統の監視

縮退によって`PWR_DRIVE`または`PWR_SERVO`の電源供給を継続する場合は、次の出力状態と監視を維持する。

| 通電を継続する系統 | 維持する出力状態 | 必須の監視・保護 |
| --- | --- | --- |
| `PWR_DRIVE` | アクチュエータ出力禁止 | 走行駆動系電流を1 ms周期、モータドライバ温度を100 ms周期で監視する |
| `PWR_SERVO` | サーボPWM停止 | サーボ駆動系電流を1 ms周期、バッテリー表面温度を100 ms周期で監視する。サーボ用5 V電源変換部の内蔵過温度保護および保護状態入力を有効にする |

この場合は、第3.4節の通電維持監視モードを選択し、必要な監視処理を実行できる浅いMCU低消費電力モードで動作させる。

低消費電力移行前にこの監視を成立させられない場合は、当該電源系統を安全に遮断する。
遮断もできない場合は、低消費電力状態を成立させない。

通電維持縮退中に監視を喪失した場合は、安全要因として直ちに復帰処理と当該系統の遮断を開始する。
遮断に失敗した場合は、電気安全監視機能による本体電源遮断必要の直接要求へ進む。

#### 監視継続要求を受けた場合

##### 通常監視を維持し、変更を要求する

バッテリー・電気安全監視機能から監視継続要求を受けた場合は、周期起動を内部監視だけで完了したものとして再入眠しない。
通常監視周期に必要なクロック、A/D変換および安全監視タスクを維持する。

未確定候補の確認を目的とする監視継続要求では、受信から10 ms以内に候補事象識別子を保持する。
現在の移行識別子および新しい監視モード変更要求識別子とともに、バッテリー・電気安全監視機能へ通常監視モードへの変更を要求する。

同機能による通常周期監視および安全処理の開始は、この要求または変更完了待ちによって遅延させない。

##### 更新許可根拠を通常監視へ切り替える

電源・省電力管理機能は、次のすべてを確認した時点で、IWDT更新許可根拠を低消費電力安全監視世代から通常監視世代へ一回だけ移管する。

- 要求した通常監視モード、監視モード変更要求識別子、移行識別子および候補事象識別子に対応する、監視モード変更正常完了を受理している。
- 切替後最初の正常監視世代を受理している。
- 通常監視モードで必要なシステム監視条件が成立している。

以後、候補の成立または解除が確定するまでは、次の両方だけをIWDT更新許可根拠として使用する。

- 通常監視モードで継続して提供される正常監視世代。
- システム監視の正常進行結果。

候補を検出した`LP_MON_COMPLETE`または過去の正常監視世代を再使用しない。

変更正常完了、最初の正常監視世代または必要なシステム監視結果を確認できない場合は、IWDTを更新せず、再入眠およびアクチュエータ出力を禁止する。
この一時的な監視モード変更だけでは、システム状態を低消費電力状態から変更しない。

#### 標準低消費電力監視へ戻して再入眠する場合

##### 再移行の前提条件

次の両方を確認した後に限り、現在のシステム状態に対応するMCU低消費電力モードへ再移行する。

- 監視継続要求が解除されていること。
- 監視継続中に成立・解除した電気安全事象の引継ぎが完了していること。

##### 標準モードへの再入眠手順

1. バッテリー・電気安全監視機能へ、標準低消費電力監視への変更を要求する。要求には、新しい監視モード変更要求識別子、現在の移行識別子および必要な候補事象識別子を含める。
2. 次の結果と条件をすべて確認する。
   - 同じ要求識別子および移行識別子に対応する監視モード変更正常完了。
   - 実監視モードが標準低消費電力監視であること。
   - 切替後最初の新しい監視世代の`LP_MON_START`および`LP_MON_COMPLETE`。
   - 低消費電力状態で必要なシステム監視条件の成立。
3. 確認した新しい監視世代へ、IWDT更新許可根拠を一回だけ移管する。
4. 同世代によるIWDT更新正常完了結果を提供し、関係する更新許可根拠の提供元から、同じ更新取引識別子の受領確認を取得して更新取引を完了する。
5. 低消費電力監視中の保持情報を当該世代へ切り替える。その後にのみ、Software Standbyへ移行する。

##### 再入眠できない場合

次のいずれかに該当する場合は、通常監視、再入眠禁止およびアクチュエータ出力禁止を維持する。

- 監視モードの変更に失敗した。
- 識別子が一致しない。
- 期限を超過した。
- 必要なシステム監視が成立していない。
- IWDT更新取引が完了していない。

以前の正常完了世代を再使用して、再入眠の条件が成立したものとして扱わない。

#### 監視結果を確認できない場合の安全処理と通知

##### 再入眠を禁止する条件と維持する機能

次のいずれかに該当する場合も、監視継続要求が成立した場合と同様に再入眠を禁止する。

- 監視バースト失敗結果を受けた。
- 周期復帰後に、当該世代の正常完了結果を確認できない。
- 低消費電力状態で必要なシステム監視対象の正常進行を確認できない。

電源・省電力管理機能は、通常監視に必要なクロックと安全監視処理を維持する。
走行出力許可およびサーボPWM許可は、安全側に維持する。

##### 異常を通知する機能

監視バースト開始後の測定・診断失敗は、バッテリー・電気安全監視機能が、電源安全監視異常として異常管理機能へ主通知する。

重要処理の進行停止は、システム監視経路が異常管理機能へ通知する。
IWDTリセットより早い停止・出力禁止が必要な場合は、異常管理機能の処置判断完了を待たず、安全関連経路へ要求する。

電源・省電力管理機能は、再入眠禁止、IWDT更新未実施および電源状態を、対応する異常識別子へ補足結果として提供する。
同一事象を重複して新規異常登録しない。

監視処理が停止し、失敗結果自体を提供できない場合は、第7.5節のIWDT期限監視を最終的な独立検出経路とする。

#### IWDT更新制御の失敗をリセット前に検出した場合

次のいずれかをリセット前に検出した場合、電源・省電力管理機能は「IWDT更新制御失敗」または関係する監視異常を、異常管理機能へ主通知する。

- 世代、システム監視進行世代または相関識別子の不一致
- 必要な重要処理の進行停止
- IWDT更新命令失敗
- 更新ウィンドウ違反
- 更新受付結果の通知失敗

主通知には、異常通知取引識別子と予約した異常識別子を含める。
同じ通知取引に対する受付結果および確定異常識別子を確認できた場合だけ、主通知完了とする。

IWDTを更新したものとは扱わず、再入眠を禁止して出力禁止を維持する。
追加更新を試みず、IWDTリセットへ移行する。

IWDTリセットが主通知完了より先行した場合は、第3.4節に従って、次回起動時に起動・終了・再起動管理機能が主通知する。
バッテリー・電気安全監視機能およびシステム監視経路は、同じ事象を別の異常として重複通知しないよう、異常通知取引識別子または対応する相関情報を使用する。

### 7.2 BLE通信部

BLE通信部は、通常のBLE接続待機状態より長い間隔の接続可能アドバタイズを行い、接続要求を復帰要因として制御部へ通知できる状態を維持する。

低頻度アドバタイズ間隔は1,022.5 msを基本設計値とする。RYZ012A1への具体的な設定方法を詳細設計で定め、実機で消費電力および操作端末からの発見時間を確認する。使用モジュールの制約によって基本設計値を使用できない場合は、詳細設計だけで値を変更せず、本基本設計を改訂する。

接続要求による復帰通知経路を維持できない場合は、低消費電力状態を安全に継続できない異常として扱う。低頻度化だけに失敗し、通常頻度の接続可能アドバタイズと復帰通知を維持できる場合は、消費電力の増加を許容して縮退継続する。

### 7.3 Wi-Fi通信部

Wi-Fi通信部は、原則としてスリープまたは同等の低消費電力状態に維持し、Wi-Fiアクセスポイント接続およびVPS通信を行わない。

Wi-Fi通信部をスリープへ移行できない場合でも、Wi-Fi・VPS通信を安全に終了または中断済みであり、Wi-Fi通信部の実状態が既知で、送受信、自動再接続および意図しないアクセスポイント接続を禁止でき、電源容量、電気安全監視および復帰能力を維持できる場合に限り、覚醒通電待機の縮退状態で低消費電力移行を許可する。この縮退状態ではWi-Fiを使用可能と扱わず、実状態、電源良好および保護状態を監視し、採用モジュールの覚醒時最大消費電力を電源容量および待機時間の電力収支へ算入する。縮退情報は移行識別子と対応付けて保持する。いずれかの条件を維持できない場合は、低消費電力状態を成立させない。

低消費電力状態中のログ送信、設定取得、診断または定期通信を理由としてWi-Fi通信部を復帰させない。これらの要求は、緊急性のないものは復帰後へ保留し、安全またはデータ整合性に関係するものはローカルで処理する。

### 7.4 アクチュエータ

低消費電力状態中は、アクチュエータ操作指令を受け付けず、実行しない。

走行駆動部は左右モータ停止と駆動出力無効を維持し、サーボ駆動部はPWM停止を維持する。サーボPWM停止後も自重、振動または外力によって危険な状態へ移動しないことは、砲塔・砲身制御基本設計および機構設計の成立条件とする。

電源系統を停止している間も、制御端子からの逆給電、不定出力および電源再投入時のパルスによってアクチュエータが動作しないようにする。

### 7.5 安全監視と電気保護

低消費電力状態でも必要な安全監視を論理的に継続する。ソフトウェア監視は`T_LP_SAFETY_MONITOR`に従った周期起動で実行する。危険低電圧は、作動範囲の下限がソフトウェア危険低電圧しきい値6.4 Vと一致する常時有効なハードウェア危険低電圧検出によって50 ms以内に出力許可を無効化し、電圧低下が継続する場合は公称6.2 Vのハードウェア低電圧遮断へ接続する。周期監視では間に合わない危険な過電流、短絡または重大な異常発熱も、低消費電力動作可能な監視回路およびハードウェア保護によって検出・保護する。

危険な過放電、過電流またはその他の重大な電気的異常に対するハードウェア保護は連続して有効とし、異常成立時は必要に応じて制御部を復帰させるか、電源部が独立して保護動作を実行する。

安全監視の成立に必要な監視周期、検出遅延またはハードウェア経路を満たせない低消費電力モードは採用しない。

低消費電力中の監視停止は、次の四つの故障区分を区別して処理する。

| 故障区分 | 主たる検出 | 電源・省電力管理機能の処理 |
| --- | --- | --- |
| 監視バーストは起動したが測定または判定が正常完了しない | バッテリー・電気安全監視機能が、対象監視世代の失敗または正常完了未成立を検出する。応答自体が停止した場合はIWDTが期限超過を検出する | 当該世代を正常完了とせずIWDTを更新しない。監視継続要求または失敗結果を受けた時点で再入眠を禁止し、出力禁止を維持して通常監視と異常連携を開始する |
| 電気安全監視は正常完了したが、現在状態で必要な重要周期処理の正常進行を確認できない | 監視対象から独立したシステム監視経路がチェックポイント、aliveカウンタまたは同等の進行情報の停止・不整合を検出する | IWDTを更新せず、必要な安全停止または出力禁止をIWDTリセットより先に開始すべき対象では安全関連経路を直ちに起動する。異常管理へ監視異常を通知し、追加更新を行わない |
| 正常完了結果を受けたがIWDT更新または更新受付結果の確定に失敗する | 電源・省電力管理機能が、更新取引識別子、更新元区分、監視世代、システム監視進行世代、相関識別子、更新命令結果および受領確認を確認する | 更新済みと扱わず再入眠を禁止し、出力禁止を維持する。リセット前に通知可能なら電源・省電力管理機能が主通知し、IWDTリセットが先行した場合は次回起動時に起動・終了・再起動管理機能が主通知する。追加更新を行わずIWDTリセットへ移行する |
| AGT1、LOCOまたは周期復帰割込み経路が機能せず、監視バースト自体が起動しない | AGT1とは異なるIWDTCLKでSoftware Standby中も動作するIWDTが、正常完了世代の更新期限超過を検出する | IWDTからMCUリセットを発生させる。これは第8章の通常復帰とは扱わず、起動・終了・再起動管理機能がリセット要因を取得して起動シーケンスへ入り、異常管理機能へ未復旧の電源安全監視異常を引き継ぐ。安全条件を再確認するまで負荷系電源および通常操作を許可しない |

IWDT期限超過時は、`IWDTRF`等のリセット要因、保持可能な最終正常監視世代およびシステム監視の最終正常進行情報を起動処理で取得できるようにする。リセット要因、最終正常世代または必要な進行情報を確認できない場合も、監視が正常であったとはみなさず安全側に扱う。独立した危険低電圧、短絡、重大過電流および過温度保護は、AGT1、システム監視経路およびIWDTの状態にかかわらず継続する。

第3.4節、第7.1節および本節で定める、異常検出後に追加のIWDT更新を行わずリセット経路へ移行する規則は、当該異常を検出した起動中の失敗処理に適用する。実行可能な必要電源遮断がある場合は、IWDTリセットの発生を待つ理由としない。

リセット後の新しい起動では、前回の失敗情報を保持したまま第3.4節に従って現在の監視・更新処理を確立し、起動・終了・再起動管理基本設計の第4.7節に従って通電復旧待ちの可否を判断する。前回の追加更新禁止を、現在の正常監視世代および正常進行確認結果に対する無条件の更新禁止として引き継がない。一方、同基本設計の第7.5節に定める遮断優先条件が成立した場合は、監視・更新処理の再確立を繰り返さず、遮断を優先する。

### 7.6 表示

状態表示部は、主電源が投入されており低消費電力状態であることを識別できる表示を行う。基本方針は電源LEDの点滅とし、不要なRGB LEDおよび7セグメント表示は消灯する。

緊急停止、電源危険、異常停止その他の上位優先度の表示が必要となった場合は、必要な表示機能を選択的に復帰させ、状態表示・利用者通知機能が表示優先度を決定する。

## 8. 低消費電力状態からの復帰

### 8.1 復帰要因

システム状態を低消費電力状態から遷移させる復帰要因は、次のとおりとする。

- 操作端末からのBLE接続要求
- 本体の通常終了要求
- 本体の緊急停止要求
- 通常動作の継続を禁止する異常または電気安全事象

強制電源遮断は復帰要因ではなく、電源部が直接処理する。

低消費電力監視期限の超過も通常の復帰要因ではなく、IWDTがMCUリセットを発生させる異常経路である。この場合は復帰シーケンスを継続せず、リセット初期状態から起動処理と未復旧異常の引継ぎを実行する。

復帰要因はビット集合または同等の方法で複数保持できるようにし、先着した一要因だけで上位優先度の要因を失わない。処理順は第2.7節に従う。

### 8.2 復帰シーケンス

| 順序 | 処理 | 完了確認 |
| --- | --- | --- |
| 1 | 復帰入力をラッチし、制御部のクロックと復帰処理に必要な最小機能を開始する | 復帰要因と発生順を保持 |
| 2 | 通常操作禁止、左右モータ停止、走行出力無効およびサーボPWM停止を再確認する | 安全出力状態 |
| 3 | バッテリー・電気安全監視機能へ通常監視モードへの変更を要求し、低消費電力状態中の安全関連事象を引き継ぐ | 監視モード変更完了、実監視モード、`監視利用可否`が利用可能、および事象引継ぎ |
| 4 | 復帰要因に必要な機能だけを定義された順序で復帰させる | 対象機能ごとの使用可能結果 |
| 5 | 設定データ、状態情報および電力状態の整合性を確認する | 復帰後処理に必要な情報が有効 |
| 6 | BLE接続要求の場合はBLE接続・認証機能を通常動作可能にする | 接続継続または再アドバタイズ可能 |
| 7 | 復帰要因、復帰結果、所要時間および縮退情報を保持・記録し、表示情報を提供する | 記録要求と表示要求の受付 |
| 8 | 電源・省電力管理機能が復帰結果を通知する | 第8.4節の要因別完了条件 |
| 9 | システム状態管理機能が、関連機能の結果を確認して遷移先を確定する | BLE接続待機、終了処理、緊急停止または異常停止 |

復帰中は、低消費電力移行前の操作指令を再送または再実行しない。復帰中に新たに受信した通常操作も、BLE接続待機状態、認証、操作権限および操作可能状態が成立するまで実行しない。

### 8.3 復帰要因別の選択的復帰

| 復帰要因 | 復帰する主な機能 | 原則として復帰しない機能 | 電源・省電力管理機能の結果通知先 |
| --- | --- | --- | --- |
| BLE接続要求 | 制御部、通常安全監視、BLE接続・認証、必要な状態表示 | Wi-Fi、走行駆動電源、サーボ駆動電源 | システム状態管理機能 |
| 通常終了要求 | 制御部、通常安全監視、終了処理に必要な保存、必要な状態表示 | Wi-Fiとアクチュエータは終了処理で必要な場合を除き復帰しない | システム状態管理機能、起動・終了・再起動管理機能 |
| 緊急停止要求 | 制御部、緊急停止処理に必要な制御機能、安全監視、必要な状態表示 | Wi-Fiとアクチュエータ駆動電源 | システム状態管理機能、停止・緊急停止管理機能 |
| 通常動作禁止異常 | 制御部、異常処置に必要な監視・診断、必要な状態表示 | 異常処置に不要な通信とアクチュエータ駆動電源 | システム状態管理機能、異常管理機能 |

緊急停止または異常への対応において、すでに走行駆動電源とサーボ駆動電源が停止している場合は、停止状態を確認するためだけにこれらを再投入しない。

### 8.4 復帰完了条件

BLE接続要求による通常復帰は、次の条件をすべて満たした場合に正常完了とする。

- 制御部が通常処理を実行できる。
- 復帰要因と低消費電力状態中の安全関連事象が後続処理へ引き継がれている。
- 通常動作に必要な安全監視が有効である。
- 左右モータ停止と走行駆動出力無効が維持されている。
- 砲塔・砲身のサーボPWM停止が維持されている。
- BLE接続および認証に必要な機能が使用可能である。
- 復帰に必要な設定データと状態情報が有効である。
- Wi-Fi通信部を不要に復帰させていない。

正常完了後の遷移先はBLE接続待機状態とする。復帰要因となったBLE接続要求を継続できる場合はBLE接続・認証機能へ引き継ぎ、継続できない場合は接続可能アドバタイズを再開する。

通常終了、緊急停止または異常による復帰は、各要因の処理開始に必要な機能が使用可能となり、アクチュエータ停止と安全監視が維持されていることをもって、電源・省電力管理機能の復帰処理完了とする。システム状態の遷移完了は、各管理機能の基本設計に定める追加条件をシステム状態管理機能が確認して決定する。

### 8.5 復帰時間

システム要求上の通常復帰時間は、BLE接続要求を復帰要因として検出した時点から、システム状態管理機能がBLE接続待機状態への遷移を正常完了した時点までとする。

電源・省電力管理機能は、BLE接続要求を復帰要因として確定した時刻を保持し、当該復帰処理結果および復帰要因と対応付けてシステム状態管理機能へ提供する。再試行または重複要求によって、この検出時刻を後の時刻へ更新しない。

電源・省電力管理機能は、システム状態管理機能による状態遷移完了判定を含む全体時間が上限内となるよう、制御部、BLE通信部、安全監視および状態情報の復帰を完了して結果を提供する。

目標完了時間を3秒以内、許容最大時間を10秒以内とする。Wi-Fi復帰、VPS接続、ログ送信または表示完了は通常復帰の完了条件に含めない。

緊急停止、電気的異常またはその他の安全関連事象は、通常復帰の全手順を待たず、当該安全処理に必要な最短経路で処理を開始する。

## 9. 失敗、縮退および中断時の処理

### 9.1 必須処理と任意処理

| 区分 | 主な処理 | 失敗時の扱い |
| --- | --- | --- |
| 必須 | 通常操作禁止、アクチュエータ安全停止、走行出力無効、サーボPWM停止 | 低消費電力移行を中止する |
| 必須 | 復帰要求検出、安全関連入力検出、継続が必要な安全監視 | 低消費電力移行を中止する。低消費電力中に喪失した場合は必要な機能を復帰させて異常管理へ通知する |
| 必須 | 制御部の低消費電力モード移行、通常復帰に必要な制御機能 | 移行または復帰を失敗とする |
| 任意 | Wi-Fiスリープ | Wi-Fi・VPS通信を安全に終了または中断し、実状態既知、自動再接続禁止、電源容量・電気安全監視・復帰能力維持をすべて満たす場合だけ、覚醒通電待機で縮退継続できる。通信の安全な終了または中断自体に失敗した場合は低消費電力移行を中止する |
| 任意 | BLEの低頻度化 | 通常頻度の接続可能アドバタイズと復帰通知を維持できる場合は縮退継続できる |
| 任意 | 低消費電力表示、任意ログの永続化 | 安全と復帰に影響しない場合は異常情報を保持して縮退継続できる |

### 9.2 低消費電力移行失敗

必須処理の失敗または許容最大移行時間の超過を検出した場合は、低消費電力移行を失敗とする。

電源・省電力管理機能は、失敗理由、移行識別子、完了済み処理、現在の電力状態および安全維持可否をシステム状態管理機能へ通知し、アクチュエータ停止、走行出力無効およびサーボPWM停止を維持する。状態遷移としての中断および復元先はシステム状態管理機能が決定する。

システム状態管理機能からBLE接続待機状態への復元要求を受けた場合は、要求された移行識別子が現在処理と一致することを確認してから、BLE接続待機状態に必要な制御部、BLE通信部、安全監視および表示を復元する。高優先度要求に対応する中断要求を受けた場合は、当該要求の処理に必要な機能を優先して維持または復帰させる。

復元に成功し、指定された遷移元状態または高優先度処理を安全に維持できる場合は、中断結果、復元結果および移行失敗結果をシステム状態管理機能と異常管理機能へ通知する。

安全にBLE接続待機状態を維持できない場合は、現在の電力状態、利用可能な機能および移行失敗結果を異常管理機能およびシステム状態管理機能へ提供する。必要な異常処置は異常管理機能が判断し、システム状態遷移はシステム状態管理機能が決定する。

同じ条件のまま移行失敗を繰り返さないよう、失敗した移行世代を記録する。新たな有効操作後に再び長時間未操作となった場合、明示的な復旧が完了した場合、または再起動後に健全性を確認した場合に、再度の移行を許可する。

### 9.3 復帰失敗

次のいずれかが成立した場合は復帰失敗とする。

- 復帰要因に必要な機能を使用可能にできない。
- 安全監視を通常動作へ引き継げない。
- アクチュエータ停止、走行出力無効またはサーボPWM停止を確認できない。
- 復帰要因または安全関連事象を後続処理へ引き継げない。
- 必要な設定データまたは状態情報の有効性を確認できない。
- 許容最大復帰時間内に復帰完了条件を満たせない。

復帰失敗時は通常操作禁止を維持し、BLE接続待機状態または操作可能状態へ遷移させない。アクチュエータ停止を維持したまま異常管理機能へ通知し、システム状態管理機能が異常停止状態への遷移を管理する。

標準低消費電力中に監視バーストの測定失敗または正常完了未成立を検出した場合は、通常復帰失敗として再試行せず、第7.1節および第7.5節の安全監視異常経路を優先する。周期復帰自体が起動せずIWDT期限超過となった場合は、第7.5節のリセット経路を優先し、低消費電力状態を継続または自動再開しない。

緊急停止要求、通常動作禁止異常または通常終了要求を復帰中に検出した場合は、通常復帰の再試行またはタイムアウトを待たず、上位優先度の処理へ切り替える。

### 9.4 再試行

再試行による回復を期待できる処理は、BLE通信部の復帰、BLEアドバタイズ開始、BLE接続・認証機能の準備、および一過性の応答待ちに限定する。

試行回数は初回を含めて最大3回とし、再試行は最大2回とする。全試行を含む処理が第6.5節または第8.5節の許容最大時間を超えないようにする。

一回の試行が失敗した場合は、上位優先要求がなく、安全監視、アクチュエータ停止および復帰要因保持を維持でき、同じ入力条件で再試行して結果が変化する可能性があり、かつ残り時間内に次の一回を開始して結果を確定できる場合に限り、次の再試行を行う。これらの条件が成立しており時間上限内に次試行を完了可能である場合、詳細設計上の任意な待機や実装都合だけを理由として再試行を打ち切らない。一方、残り時間内に結果を確定できない場合は次試行を開始せず、当該移行または復帰を失敗として扱う。

アクチュエータ停止、安全監視または復帰要因保持を維持できない場合は、再試行の完了を待たず失敗とする。電源・省電力管理機能は、異常管理機能が決定した復旧方針を超えて独自に再試行しない。各試行の内部安定待ち、応答待ち、タイマおよび必要なbackoffは、前記の再試行条件と全体時間上限を変更しない範囲で詳細設計に定める。

### 9.5 電力状態不明

対象機能から結果を取得できない、要求と実状態が一致しない、または電源状態確認手段が矛盾する場合は、当該機能を電力状態不明として扱う。

ただし、低消費電力移行のための`PWR_DRIVE`または`PWR_SERVO`遮断要求が失敗しても、独立した確認手段によって実状態がONと一意に確認され、第3.4節の出力禁止、零電流、対象別監視およびハードウェア保護条件がすべて成立する場合は、要求と実状態の不一致をそのまま不明とはせず、目標を既知ONの通電維持縮退へ再設定し、通電維持監視モードを選択して移行を継続する。再設定結果、元の遮断失敗および縮退理由は保持・通知する。いずれかを確認できない場合、または確認手段同士が矛盾する場合は本例外を適用せず、低消費電力移行を失敗とする。

危険過電流、停止失敗その他の電気的保護を目的とする対象系統遮断の失敗には、前段落の低消費電力移行用例外を適用しない。電源・省電力管理機能は遮断失敗または実状態不明を、同じ電力状態変更要求識別子および電気安全事象識別子または異常識別子により、要求元であるバッテリー・電気安全監視機能と異常管理機能へ提供する。バッテリー・電気安全監視機能は、必要と確定した遮断が失敗した場合または実状態が不明の場合、その後の測定電流低下だけで保護成功へ読み替えず、本体電源遮断必要を確定して起動・終了・再起動管理機能へ直接提供し、異常管理機能へ同じ判断結果を通知する。電源・省電力管理機能は本体電源遮断必要を中継せず、対象系統遮断の再試行または異常管理機能の追加判断によってこの直接要求を遅延させない。

電力状態不明となった機能について、電源・省電力管理機能は当該機能の電力状態、利用可否および取得できた失敗情報を異常管理機能へ提供する。

当該異常に対する通常操作継続可否、縮退継続、異常停止その他の処置は異常管理機能が判断し、必要なシステム状態遷移はシステム状態管理機能が管理する。

ただし、当該電力状態が低消費電力移行または復帰の必須条件である場合、電源・省電力管理機能は当該移行または復帰を失敗として扱う。

## 10. ログ、診断および状態表示

### 10.1 ログ

電源・省電力管理機能は、少なくとも次の情報をログ・診断機能へ提供する。

- 電力状態変更の対象、変更前状態、目標状態および結果
- 低消費電力移行の開始理由、開始時刻、完了時刻および所要時間
- 長時間未操作条件の成立時刻
- 移行中断要因、失敗した処理、対象機能および取得できた失敗原因
- 縮退して継続した処理と、その時点で維持できていた安全機能・復帰機能
- 復帰要因の集合、優先して処理した要因、復帰結果および所要時間
- 電力状態不明、タイムアウト、再試行回数および連続失敗
- 低消費電力安全監視世代の開始・正常完了・失敗、最終正常完了時刻および失敗理由
- システム監視の進行世代、重要処理の進行停止およびIWDT更新条件への反映結果
- IWDT期限超過、リセット要因、リセット時の選択済みモードおよび最終正常監視世代

安全関連の記録は、低消費電力状態中に永続化できない場合でも保持領域またはハードウェア状態として失わず、復帰後に記録できるようにする。ログ保存だけを理由として安全処理、強制電源遮断または許容最大時間を遅延させない。

### 10.2 診断情報

診断機能へ、少なくとも次の現在値および統計値を提供できるようにする。

- 各機能の現在電力状態、目標電力状態および変更中状態
- 未操作時間と長時間未操作条件の成立有無
- 直近の低消費電力移行・復帰理由と結果
- 移行時間、復帰時間および最大値
- 対象機能ごとの変更失敗回数と連続失敗回数
- 低消費電力状態の累積時間と移行・復帰回数
- 縮退状態の有無と、通常状態より消費電力が増加する要因
- 復帰入力、安全監視入力およびハードウェア保護の利用可否
- AGT1周期復帰、IWDT期限監視、低消費電力安全監視世代、システム監視の最終正常進行世代および直近の更新期限の状態

### 10.3 状態表示への情報提供

状態表示部へ、次の論理状態を提供する。

- 低消費電力移行中
- 低消費電力状態
- 復帰中
- 低消費電力移行正常完了（縮退なしまたは縮退あり）
- 復帰正常完了
- 低消費電力移行失敗または復帰失敗

具体的なLED色、点灯・点滅周期および表示優先度は状態表示・利用者通知の設計が決定する。表示の失敗はログおよび異常情報として管理するが、表示完了を安全処理、移行完了または復帰完了の必須条件にしない。

## 12. 後続設計および評価で具体化する事項

### 12.1 基本設計上の成立性確認事項

次の事項は、本書で基本方針と必須条件を決定済みであるが、評価基板の回路構成確定後に成立性を確認する。

1. `PWR_CTRL`の3.3 V電源変換回路を共有する`PWR_BLE`、`PWR_WIFI`および`PWR_DISPLAY`を、独立ロードスイッチによって安全に停止・復帰でき、`PWR_SAFETY`への給電を継続できるか。
2. RYZ012A1のBLE接続要求、通常終了入力、緊急停止入力、電気安全監視出力およびAGT1アンダーフローを、RA8M2の標準モードの復帰要因として同時に使用できるか。
3. 標準モードで`T_LP_SAFETY_MONITOR`を1秒とした場合に、バッテリー電圧、バッテリー表面温度およびモータドライバ温度の安全監視要求を満たせるか。また、通電維持監視モードで、`PWR_DRIVE`では走行駆動系電流およびモータドライバ温度、`PWR_SERVO`ではサーボ駆動系電流、バッテリー表面温度および5 V電源変換部の保護状態を、定めた周期で継続監視できるか。
4. IWDTの最悪側クロック許容差、監視バースト時間、システム監視経路による重要周期処理の進行確認時間、通常監視への切替時間、割込み遅延および更新処理時間を含めても、正常な1秒周期監視および候補確認中の通常監視で誤リセットせず、バッテリー・電気安全監視基本設計で定める更新停止判定期限内に周期復帰停止、通常監視更新停止または重要処理進行停止を検出できるか。
5. IWDT更新命令の実行前、実行中、更新受付結果通知中および受領確認前の各時点でリセットが発生した場合に、更新主体、移管識別子、更新トランザクション情報、電気安全監視世代、システム監視進行世代、異常通知取引識別子、異常識別子および主通知状態を次回起動で矛盾なく取得できるか。
6. IWDTリセット後に、前回の原因分類用情報と今回の更新情報を分離して保持でき、前回異常が未復旧であっても、現在の有効な正常監視世代およびシステム監視の正常進行結果に基づくIWDT更新を成立させられること。また、現在の監視故障、重要処理進行停止または更新経路故障が継続する場合に、待機条件成立と誤判定しないこと。
7. 起動・終了・再起動管理基本設計の第4.7節、第6.3節および第7.5節に定める通電復旧待ち、再起動の反復防止および本体電源遮断について、起動初期の要求提供、リセットを越えた要求保持、電源部の遮断動作および再投入禁止が成立すること。遮断要求の受理前後にIWDTリセットが発生しても、通常の起動確認を繰り返して遮断を延期しないこと。
8. 低消費電力移行および通常終了で、停止・緊急停止管理機能が同じ移行識別子または終了識別子に対応する一つの停止取引として走行・砲塔・砲身の局所停止を集約し、電源・省電力管理機能から同一の物理停止を重複要求せずに`PWR_DRIVE`および`PWR_SERVO`の実電力状態変更へ進めること。

Renesasの一次資料により、AGT1とIWDTを用いる基本方式に必要な周辺機能および動作選択肢が存在することを確認した。これは、採用するRA8M2型式、具体的なOFS設定、クロック許容差、同時復帰要因、固定ブート・復旧中から本体アプリケーションへの更新実行権移管、最終回路の安全出力および実消費電流を含むシステムとしての成立性を確認済みとするものではない。これらは詳細設計および評価で確認する。

上記の成立性確認によって、第3.3節の独立制御条件、第3.4節のMCU低消費電力モード選択、`T_LONG_IDLE`の工場出荷値・設定範囲、BLE低頻度アドバタイズ間隔または`T_LP_SAFETY_MONITOR`を変更する必要が生じた場合は、詳細設計だけで変更せず、本基本設計を改訂する。

### 12.2 詳細設計事項

後続の詳細設計では、本書で定めた電力状態、移行・復帰の開始条件と完了条件、失敗条件、優先順位、再試行上限と実行条件、縮退継続条件、通常操作禁止、自動再開禁止、5秒／10秒の移行時間および3秒／10秒の通常復帰時間を変更しない。詳細設計で新たな縮退継続条件、再試行打切り条件、通常操作再開条件または外部から見た成功・失敗条件を追加しない。正常なユースケースでは到達しない内部状態矛盾、デッドロックその他の実装上の防御と、これらを実現する内部タイマ・排他・チェックポイント等は、本書の安全側方針を変更しない範囲で詳細設計の対象とする。

1. 各電源ドメインに使用するレギュレータ、FET、ロードスイッチ、EN端子、電源状態確認信号、保護回路、回路定数および逆給電防止回路。
2. RA8M2の標準モードおよび通電維持監視モードへ移行するレジスタ設定、各モードで停止・維持するクロックと周辺機能、保持RAMの配置および復帰後のクロック初期化手順。標準モードでは、AGT1のLOCO選択・周期・復帰割込みと、IWDTのOFS、分周、タイムアウト、ウィンドウ、Software Standby中カウント継続、リセット動作およびリセット要因取得を含む。ただし、バッテリー・電気安全監視基本設計で定める低消費電力監視期限および本書の外部振る舞いを満たす設定とし、詳細設計だけで期限を緩和しない。
3. BLE接続要求、通常終了、緊急停止、電気安全異常およびAGT1周期監視に使用する端子、割込み番号、極性、ラッチ方法およびチャタリング対策。
4. `T_LONG_IDLE`および`T_LP_SAFETY_MONITOR`のタイマ実装、時刻分解能、カウンタ幅、オーバーフロー処理、各監視モードの監視世代、システム監視の進行世代、IWDT更新実行権移管識別子、更新取引識別子、異常通知取引識別子、更新状態・主通知状態の保持ならびに現在状態で必要な電気安全監視とシステム監視の双方が正常な場合だけIWDTを更新する排他方式。
5. RYZ012A1に1,022.5 msのアドバタイズ間隔を設定するコマンド、接続要求通知方式および通常アドバタイズへの復帰手順。
6. DA16200MODのスリープ・復帰コマンド、通信を安全に終了または中断する具体的な方式、電源遮断可否および応答確認方式。スリープ失敗時は第6.3節、第7.3節、第9.1節および第9.5節で定めた覚醒通電待機縮退の成立条件と失敗条件をそのまま使用し、詳細設計で新しい縮退許可条件や低消費電力状態中の通常Wi-Fi・VPS通信を追加しない。
7. 第4章、第6章および第8章の順序を実現する具体的な信号操作、安定待ち時間、処理時間配分、内部タイムアウトおよび内部打切りの実装。本書の5秒目標・10秒上限の低消費電力移行、3秒目標・10秒上限の通常復帰、第9.4節の再試行条件ならびに安全関連の時間条件を変更しない範囲に限る。個別タイムアウトまたは打切りによって移行・復帰の成功／失敗、縮退可否、再試行可否、通常操作可否、安全処理開始または利用者・他機能から見た結果が変わる場合は、詳細設計で決定せず、本書または担当機能の基本設計へフィードバックして確定する。
8. 復帰要因、安全関連事象、移行識別子、縮退情報、IWDT更新主体、更新実行権移管情報、更新トランザクション情報、システム監視進行世代、異常通知取引識別子、異常識別子、主通知状態および未記録ログをIWDTリセット後に取得可能な状態で保持するデータ形式、保持領域、完全性確認および原子的更新方式。
9. 電源・省電力管理機能と各関連機能のAPI、電力状態変更要求識別子、停止・緊急停止管理機能が管理する停止要求識別子と移行識別子・終了識別子・停止目的の対応付け、監視モード変更要求識別子、システム監視進行世代、更新取引識別子、イベント、応答、データ型、排他制御、同一物理停止の重複実行防止および遅延応答の破棄方法。
10. 第6.3節のコミット処理に使用するクリティカル区間、状態更新、メモリ同期、割込み保持および失敗時ロールバックの実装方式。
11. 正常なユースケースでは発生しない重要周期処理の停止・デッドロック等を検出するため、重要周期処理が正常な1周期または定めた処理区間を完了したことを示すチェックポイント、aliveカウンタまたは同等の進行情報、監視対象から独立したシステム監視経路、現在状態ごとの必須監視対象、内部判定時間、異常管理への通知およびIWDT更新許可条件への反映方式。各監視対象機能が単独でIWDTを直接更新しない構成とし、処理停止を検出した場合の通常操作禁止および安全側処理という基本設計上の振る舞いは変更しない。

### 12.3 評価設計で具体化する事項

1. 通常動作、BLE接続待機、Wi-Fi使用中、低消費電力移行中、低消費電力状態および復帰中の平均電流、ピーク電流、待機可能時間およびバッテリー駆動時間の測定方法。
2. 低消費電力移行が目標5秒・上限10秒、通常復帰が目標3秒・上限10秒を満たし、MCU低消費電力モード移行が測定範囲に含まれることの確認方法。
3. 電源状態変更中の電圧変動、突入電流、アクチュエータ誤動作、通信端子の不定出力、逆給電およびMCUリセットの評価方法。
4. 1,022.5 msのBLE低頻度アドバタイズによる消費電力と、操作端末からの発見・接続開始時間の評価方法。
5. 標準モードおよび通電維持監視モードにおける各復帰要因、安全監視周期、復帰要因の多重発生、安全関連事象の保持、AGT1周期復帰、IWDT期限監視、システム監視経路による重要処理の正常進行確認、および選択したモード以外の通常処理が停止していることを確認する方法。
6. 電源スイッチ、モジュール応答、BLE復帰通知、安全監視、システム監視、状態表示およびログ保存の失敗注入試験。低消費電力監視については、監視バースト起動後のADC・DMA・妥当性確認失敗、候補確認中の通常監視更新停止、重要周期処理のチェックポイント停止、監視処理固着、AGT1停止、LOCO停止、周期復帰割込みマスク、個別機能または無関係な実行経路からIWDTを更新できないこと、IWDT更新命令実行中・結果通知中・受領確認前のリセット、IWDT期限超過時のリセット要因・監視世代・システム監視進行情報および更新トランザクション情報取得、リセット直後の出力禁止ならびに未復旧異常引継ぎを個別に確認する。デバッガ接続がIWDT動作へ与える影響を分離し、デバッガ非接続の単体条件でも実施する。
7. 低消費電力移行・復帰の繰返し試験、同時要求の優先順位試験、および復帰後に操作・権限・設定が自動再開されないことの確認方法。
8. `T_LONG_IDLE`の下限値、上限値および設定変更時に、未操作監視の開始・再設定・無効値フォールバックが設計どおり動作することの確認方法。
9. IWDTリセット後の現在の正常監視世代およびシステム監視の正常進行結果に基づく更新、前回の原因分類用情報との分離、通電復旧待ち中の更新条件、待機条件喪失時の遮断および再起動の反復防止を確認する。具体的な故障条件および確認項目は、バッテリー・電気安全監視基本設計の第15.3節に定めるIWDTリセット後の試験と合わせて実施する。
10. 低消費電力移行および通常終了について、同じ移行識別子または終了識別子に対応する停止取引が一度だけ実行され、走行・砲塔・砲身の局所停止結果と`PWR_DRIVE`・`PWR_SERVO`の実電力状態が別々に確認されること。局所停止完了だけで電源OFF完了へ進まず、同一物理停止を複数経路から重複実行しないことを確認する。
