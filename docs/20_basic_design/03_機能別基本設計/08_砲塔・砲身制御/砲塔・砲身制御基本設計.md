## 1. 本書の目的

### 1.1 目的

砲塔旋回用と砲身上下用の2軸について、受信した操作を、安全可動範囲内の指令位置とPWMへ変換する方式を定める。停止、起動、電源、設定、異常管理から要求された処理について、受付・開始・完了・失敗を識別できる設計とする。

### 1.2 対象範囲

実位置の追従精度を保証する位置制御器や、射撃・照準・自律追尾の機能は扱わない。本書の対象は、公開要求で定義された屋内用ロボットの機構操作である。

#### 設計と実機評価の位置付け

本書は、砲塔・砲身制御の方式と機能間の取り決めを具体化する基本設計である。**基本方式を定めたことと、実機で機構安全、PWM再開、拘束検出の成立を確認したことは同じではない。** 確定した設計判断と実機評価事項を第19章、他文書へのフィードバック事項を第20章に示す。

特に、実位置を取得しない構成での最初のPWM開始方法は、既存資料だけでは決定されていない。この不足を基本設計で具体化し、本書では第9章の`MANUAL_DATUM_ARM`（手動基準合わせ後のARM＝サーボ動作許可）を開始・再開方式として採用する。実機評価は別方式を選ぶためではなく、この採用方式の安全成立性と実機依存値を確認するために行う。

採用サーボの詳細バリアント、メーカーが保証する無信号時挙動、最終回路図、機構寸法および実機評価記録は、本書の参照資料だけでは確定できない。型式からパルス幅、可動角度、停止時トルク等を推測して補わない。

## 2. 設計方針と適用範囲

### 2.1 維持する既定事項

| 項目 | 維持する内容 | 根拠 |
| --- | --- | --- |
| 構成 | RA8M2からDS3218×2をPWM制御する | システム構成 |
| 操作 | 砲塔は左・右・旋回停止。砲身は数値目標 | 公開用システム要求仕様「08. 砲塔・砲身制御」 §8.3 |
| 制御情報 | 指令位置を保持するが、実位置には読み替えない | 公開用システム要求仕様「08. 砲塔・砲身制御」 §8.3、8.5～8.6 |
| フィードバック | 実位置フィードバックによる本体側閉ループ制御を採用しない | 公開用システム要求仕様「08. 砲塔・砲身制御」 §8.1 |
| 起動 | PWM停止で初期化し、自動基準移動をしない | 公開用システム要求仕様「08. 砲塔・砲身制御」 §8.6 |
| 安全・緊急停止 | 両軸PWMを停止。保持動作・安全位置移動で代用しない | 製品目的・製品目標（公開用） §2.5、公開用システム要求仕様「09. 停止・緊急停止」 |
| 通常停止ボタン | 走行だけを停止。砲塔の旋回停止指令とは別 | 公開用システム要求仕様「09. 停止・緊急停止」 §9.3、停止・緊急停止管理 |
| 終了・省電力 | 操作を終了し、動作停止条件の成立後にPWM停止 | 公開用システム要求仕様「08. 砲塔・砲身制御」 §8.9 |
| 同時動作 | 各軸の安全範囲内の任意の組合せで危険な干渉を起こさない | 公開用システム要求仕様「08. 砲塔・砲身制御」 §8.1、8.4 |
| 電流監視 | 2軸合計電流を使用。軸別電流は採用済みとしない | 公開用システム要求仕様「10. バッテリー・電気安全」 §10.6、バッテリー・電気安全監視基本設計 §6.1 |
| 通信依存 | BLE操作、安全監視、停止をWi-Fi・VPSの成否に依存させない | 製品目的・製品目標（公開用）、システムアーキテクチャ |

サーボ内部にどのような制御器があるかと、RA8M2が実位置を取得して閉ループ制御するかは別の問題である。本書はサーボ内部状態を観測できるものとして設計しない。

### 2.2 今回選択する基本方式

本案では、各軸の指令座標を0～1000に正規化する。砲塔は方向指令から範囲端に向かう有限の位置軌道を生成し、砲身は数値目標に向かう有限の位置軌道を生成する。

位置変化率とその変化率を制限した台形または三角形の速度軌道を使用する。急な反転では一度減速し、速度零を経由する。指令値を毎回PWMへ直結する方法は採用しない。

通常の旋回停止および砲身目標への指令軌道終了後は、通常操作条件が有効である間、最終のPWM目標を保持する。これは**正常時の制御上の保持**であり、安全停止・緊急停止時の保持には使用しない。

両軸の同時動作は標準動作とする。電圧や温度による多段階速度低減、片軸だけの異常運転、動的な禁止領域回避は追加しない。本基本設計では、定義する安全可動範囲、通常速度・位置変化率、電源条件および機構条件の範囲で、両軸同時動作が安全に成立するものとして設計する。実機評価はこの成立性を確認するために行い、成立しないことが判明した場合は本基本設計へフィードバックして改訂する。

### 2.3 設計成立に必要な前提

本案の通常動作は、以下の成立を条件とする。

| 成立条件 | 未成立の場合 |
| --- | --- |
| 機構・サーボ個体に適合した安全プロファイルがある | PWM開始禁止 |
| PWM開始・停止を安全に実行できる回路・タイマ方式である | PWM開始禁止、実機評価を先行 |
| 初回PWMの開始手順が採用され、開始誤差・危険が許容内である | 第9章の経路を無効のまま維持 |
| 合計電流による過負荷・拘束検出が評価範囲で成立する | 一般操作を許可しない |
| 無信号・電源断でも危険な機構移動が起きない | ソフトウェア停止だけで適合扱いにしない |

これらは「後で適当な値を入れる」という意味ではない。判定方法、必要な情報および失敗時の禁止動作は本書で定める。合否を決める実測情報が不足している部分を第19章に残す。

## 3. 責任分界と共通条件

### 3.1 決定主体

| 対象 | 管理元・最終判断主体 | 砲塔・砲身制御の担当 |
| --- | --- | --- |
| システム状態・全体操作可否 | システム状態管理 | 状態を参照し、局所条件を追加確認 |
| 起動・終了・再起動の全体完了 | 起動・終了・再起動管理 | 自機能の初期化・準備結果を返す |
| 操作セッション・通信受信情報 | BLE通信・認証 | 機能固有の形式・値域・実行可否を検証 |
| 端末の登録・権限 | 所有者・操作端末管理 | 提供された現行権限を確認 |
| タイムアウト・停止種別・停止全体完了 | 停止・緊急停止管理 | 継続操作状態、PWM停止結果を提供 |
| 電力状態・電源ON/OFFの実行管理 | 電源・省電力管理 | PWMを安全化し、電力変更準備結果を提供 |
| 電圧・電流・温度・電気保護 | バッテリー・電気安全監視 | 合計電流を使った機能固有過負荷判定 |
| 異常処置・復旧方式・最終復旧完了 | 異常管理 | 検出、一次安全化、原因解消・診断結果 |
| 設定パッケージの全体適用 | 設定管理 | 自機能の候補検証と局所反映・切戻し |
| 指令位置・軌道・PWM要求値 | 砲塔・砲身制御 | 本書で一意に管理 |
| 表示・ログ・不揮発保存 | 各担当機能 | 状態・事象・保存対象を提供 |

責任分界はシステムアーキテクチャの機能分割・連携原則を基準とし、現在は機能別基本設計01～07、BLE接続・認証基本設計および設定管理基本設計の関連契約とも照合している。本機能はシステム状態、電源実状態、他機能のキュー、異常管理の解除状態を直接書き換えない。

### 3.2 共通の通常実行条件 `C_RUN`

以下をすべて満たす場合だけ、通常の位置更新を実行できる。

| 条件 | 判定に使用する情報 |
| --- | --- |
| 操作可能状態である | システム状態管理の現在状態 |
| 状態遷移・管理変更による禁止がない | 現在の操作許可と禁止理由 |
| 現行の認証・砲塔砲身権限がある | 現在セッション、認証・権限世代 |
| 安全停止・緊急停止・全体禁止がない | 停止管理と異常管理の現在条件 |
| 自機能の制限・復旧中・設定切替中でない | 自機能の状態と禁止ラッチ |
| サーボ系統が既知の使用可能状態 | 電源・省電力管理の電源実状態、電気安全の使用可否 |
| PWM経路と監視が使用可能 | PWM診断、制御周期監視、電流有効性 |
| 現行設定と安全プロファイルが有効 | 設定generation、校正・機構版 |

通常停止ボタンに伴う**走行だけの通常停止中**は、それだけでは`C_RUN`を偽にしない。システム状態管理・停止・緊急停止管理で定義済みの責任分界に従い、走行の通常停止と、砲塔・砲身を含む全体の通常操作禁止とを区別する。

開始時に成立した条件を動作中ずっと有効とは扱わない。通常制御周期ごととPWM有効化直前に再確認する。条件不明は不成立とする。

### 3.3 PWM新規開始条件 `C_ENABLE`

`C_RUN`に加え、電気安全監視が新しい動作開始を許可していること、開始手順が有効であること、未処理の停止要求がないことを確認する。

電源系統がONであること、通常操作を継続できること、新しいPWMを開始できることは区別する。OFF→ONの電源投入は電源・省電力管理が行い、電気安全の通常操作開始可能条件を確認する。本機能が独自の電圧しきい値で代行しない。

### 3.4 通常終了・省電力準備条件 `C_QUIESCE`

通常操作は既に禁止されていてよい。代わりに、現在の終了・移行要求が正当で、PWM継続が安全であり、軌道状態、現行設定、制御周期および電流監視が有効であることを確認する。

`C_QUIESCE`は停止のための限定条件であり、通常操作の許可ではない。条件が失われた場合は減速・保持を継続せず、第10.4節のPWM停止へ切り替える。

### 3.5 禁止・失効処理 `INVALIDATE`

禁止が成立した場合、次の順序を一つのローカルな安全処理として行う。

| 順序 | 処理 |
| --- | --- |
| 1 | 対象軸の新規実行禁止をラッチする |
| 2 | `actuationEpoch`を更新し、以前の許可に結び付く処理を失効させる |
| 3 | 通常指令スロット、未反映PWM予約、開始確認を破棄する |
| 4 | 要求種別に従う停止処理へ進む |
| 5 | 禁止結果と破棄結果を要求元へ返す |

禁止受付だけでPWM停止完了とはしない。減速中は、通常指令を破棄した後も、停止専用の最小軌道情報だけを保持する。停止専用軌道を通常操作へ復元しない。

安全停止・緊急停止、PWM停止、リセット、セッション変更、認証・権限失効、設定確定・切戻し、終了・省電力準備、機能制限で実行資格を失効させる。

### 3.6 優先処理

電気的な即時保護および強制電源遮断を妨げない。ソフトウェアで処理可能な範囲では、緊急停止、安全停止、終了・省電力準備、局所旋回停止、通常指令の順に扱う。

優先順位の全体判断は停止・状態・電気安全の各管理機能に従う。本機能が通常の電源遮断や異常状態遷移を独自に開始したことにはしない。

## 4. 操作指令の受付

### 4.1 論理指令の定義

値域0～1000は本基本設計で具体化した値であり、公開要求に既に0～1000が規定されているという意味ではない。

| 指令 | 値と意味 | 送信契機・本設計 |
| --- | --- | --- |
| `TURRET_DIRECTION` | `LEFT=1`、`STOP=0`、`RIGHT=2`の排他的な列挙 | 押下・解除時は即時送信し、押下継続中は停止・緊急停止管理で確定した基本送信周期50 msで周期送信する。スマートフォンアプリおよびBLEはこの周期を満たすよう設計する |
| `BARREL_TARGET` | 符号なし整数0～1000 | 入力変更時。連続変更時は最新値を優先し、送信最小間隔はBLE通信・認証およびスマートフォンアプリ側の性能配分で確定する |
| `AXIS_ARM` | 第9章のARM（サーボ動作許可）要求。軸指定と開始確認識別子 | 明示的なサーボ動作許可操作時だけ有効 |

砲塔は正面を向いた機体を上から見て、機体の左側へ向かう方向をLEFT、右側へ向かう方向をRIGHTとする。砲塔指令座標は左端0、右端1000とする。

砲身は安全範囲の下端0、上端1000とする。これらは安全プロファイルの両端であり、度、百分率の実位置、サーボの公称全ストロークを意味しない。

砲身には、本初版で通常操作用の新しいSTOP値を追加しない。同じ目標の再送は追加移動を生まないが、「現在位置で停止」と同じ意味でもない。途中で停止が必要な安全事象は停止管理の要求で扱う。

### 4.2 受渡しヘッダ

BLEから次の論理情報を受け取る。通信上のバイト配置、UUIDおよびCharacteristicはBLE側で定めるが、情報の意味はここで固定する。

| 情報 | 用途 |
| --- | --- |
| `protocolVersion`、`commandType`、`axisMask` | 形式と対象の識別 |
| `sessionId`、`authorizationRevision` | 現行接続・権限との照合 |
| `commandSeq` | 同一セッション内の新旧・重複識別 |
| `rxMonotonicTime` | 本体でメッセージ受信を完了した時刻 |
| `actuationEpoch` | 当該操作許可期間との対応。BLE接続・認証の共通の指令データ仕様へ反映済みで、アプリは通知された現在の操作世代を新しい砲塔・砲身指令へ含める |
| 対象軸の値 | 方向列挙または砲身目標 |

`commandSeq`は、同一操作セッション内で新旧・重複を一意に判定できる順序情報としてBLE通信・認証から受け取る。BLE接続・認証ではuint32、1開始、wrap禁止、再認証で新しいセッションへ移る規則が確定している。本機能はその通信側判定結果と順序情報を使用し、通信連番の管理元を別に設けない。

`rxMonotonicTime`はBLEの受信時点の値を維持する。機能間の転送時刻で上書きして古い指令を新しく見せない。ただし、本体受信時刻だけではアプリ側で長時間滞留した指令を識別できない。この対策は第4.7節に分ける。

### 4.3 検証と受付の順序

| 順序 | 確認・処理 | 不成立時 |
| --- | --- | --- |
| 1 | BLEで接続、認証、権限、メッセージ枠を検証 | 通常指令として渡さない |
| 2 | 対象、形式、必須値、列挙・数値範囲を局所検証 | `INVALID_COMMAND` |
| 3 | 現行セッション・権限世代・実行世代と一致 | `STALE_CONTEXT` |
| 4 | 連番が新しく、受信後100 ms以内である | `DUPLICATE_OR_EXPIRED` |
| 5 | `C_RUN`および軸の受付状態が成立 | `INHIBITED`または`NOT_ARMED` |
| 6 | 最新指令スロットを不可分に置換 | 旧未実行指令を`SUPERSEDED` |
| 7 | 機能固有検証結果をBLEへ返す | 最終有効受信情報の確定に使用 |
| 8 | 制御周期で再度禁止・世代を確認し実行 | 失効なら実行せず破棄 |

砲塔と砲身を一つのメッセージで渡す場合、両対象の検証と実行資格確認をまとめて行う。一方が無効ならそのメッセージの通常操作部分は全体を拒否する。独立したメッセージは独立に受け付ける。緊急停止をこの一括検証へ混在させない。

砲塔STOPは、送信元・形式・鮮度を確認した後、通常の位置更新とは別の停止経路へ渡す。未準備または既に出力禁止の軸では停止状態を維持するだけであり、`C_RUN`やARMを成立させる操作として扱わない。安全停止中のSTOPで上位停止を取り消さない。

列挙の不正値、LEFTとRIGHTの同時指定、砲身の負数・小数・1001以上はクランプして有効化しない。外部指令の値域違反は拒否する。内部の砲塔目標の範囲端制限とは区別する。

### 4.4 旧指令の処理

各軸に未実行の通常指令を1件だけ保持する。通常指令をFIFOで順に再生しない。

停止要求と砲塔STOPは、通常指令スロットとは別のラッチで受け付ける。STOPを受けた後に未処理のRIGHTが残っているという理由で、STOPを消してはならない。STOP処理中の新しい左右指令は拒否し、停止完了後に到着した新しい指令を必要とする。

砲身の目標変更に伴う内部減速は、外部STOP処理と区別する。内部減速中も、同じ許可期間の最新の砲身目標1件を置換できる。安全停止・終了・機能禁止中には、その保留を認めない。

### 4.5 無効指令の影響

不正指令を拒否でき、既存の有効な制御状態を安全に継続できる場合、指令異常を記録して後続正常指令を受け付ける。無効指令で継続監視の受信時刻を更新しない。

認証済みの現行砲塔操作について相反する方向が渡された場合は、その操作意図が不明なため、砲塔STOP相当の局所停止を開始する。軌道状態や出力状態まで不整合である場合、または局所停止の安全性を確認できない場合は両軸の安全停止を要求する。

指令メッセージ異常と、生成済みPWMが安全範囲外となる制御異常は別の異常として扱う。後者を単なる入力拒否だけで継続しない。

### 4.6 更新監視

砲塔がLEFTまたはRIGHTの継続操作中であることを停止管理へ提供する。範囲端で指令位置が変化しなくても、押下継続が有効な間は継続操作中とする。無指令のまま許可を残さない。

砲塔STOPを有効受付した時点で継続操作を終了し、その後の減速・停止確認は局所停止期限で監視する。砲身の目標移動および正常時PWM保持に、砲塔の継続指令タイムアウトを適用しない。

本機能は、砲塔が継続操作中か否か、対象セッション、`actuationEpoch`および機能固有検証結果を提供する。通信側の`sessionId`、`commandSeq`、`requestId`、受信時刻、重複・旧指令判定を含む最終有効受信情報の正式な管理元はBLE通信・認証とし、本機能が同じ受信時刻や通信連番を複製して独自に管理しない。本機能は検証成功を当該BLE指令へ対応付けて返し、BLE通信・認証がその指令の最終有効受信情報を確定する。

停止・緊急停止管理は、砲塔が継続操作中であることとBLE通信・認証が保持する最終有効受信情報を組み合わせて操作指令タイムアウトを判定する。タイムアウト条件および最終的な判定値は停止・緊急停止管理が所有し、本機能へ同じタイムアウト判定器を重複実装しない。

押下継続中の砲塔方向指令は、停止・緊急停止管理で確定した基本送信周期50 msに従う。操作指令タイムアウトは最後の有効受信から300 msとし、最終判定主体は停止・緊急停止管理とする。本機能はこれらと異なる独自周期・独自タイムアウトを判定基準として持たない。走行、砲身、状態照会その他の通信によって、砲塔の最終有効受信情報を更新しない。

### 4.7 送信遅延と新しい操作意図

アプリは未送信の継続指令を最新1件に置換し、停止・切断・再認証・操作世代変更で破棄する。BLEへの投入後も古い通常指令を無期限再送しない。

本体受信前の滞留時間を端末時刻の単純比較で判定しない。本機能からは、古い操作意図を再実行しないために必要な条件として、送信待ち期限、BLE下位送信の取消し・破棄、および新しい`actuationEpoch`後の新規操作を要求する。BLE接続・認証では継続操作の未送信最新1件、セッション・権限・操作世代の変更時の旧指令破棄を反映済みである。スマートフォンアプリ側でも同じ規則を適用し、F-01の残件として画面入力・送信キュー・取消し方式を具体化する。

この送信側契約が未実装の場合、再許可直後の遅延指令を完全に排除できるとは判定しない。BLE・アプリとの結合試験を通常操作の開始条件とする。

### 5.1 機能全体の状態

| 状態 | 意味 | PWM |
| --- | --- | --- |
| `UNINITIALIZED` | 初期化未完了 | 禁止 |
| `INITIALIZING` | 無出力で設定・経路を確認中 | 禁止 |
| `AVAILABLE` | 制御処理・設定・監視を使用可能 | 各軸条件による |
| `QUIESCING` | 終了・省電力・設定準備中 | 停止専用処理だけ |

これはシステム状態ではない。`AVAILABLE`でも、BLE接続待機状態では通常動作しない。

### 5.2 各軸の状態

| 状態 | 入口 | 出口・完了 |
| --- | --- | --- |

| `READY_HOLD` | ARM（サーボ動作許可）完了、通常停止確認完了 | 新規操作、禁止、終了準備 |

| `BRAKING_REPLAN` | 反転・近傍目標へ再計画 | 速度零から最新目標へ再計画 |
| `LOCAL_STOPPING` | 砲塔STOP、終了準備 | 指令減速・停止確認の完了 |
| `SETTLING` | 指令速度零・最終PWM反映 | 停止確認時間の満了 |
| `PWM_DISABLING` | 安全停止または停止条件成立 | PWM制御側停止確認 |

`READY_HOLD`は実際の軸位置が測定済みという意味ではない。`SETTLING`の時間満了も実位置到達の観測ではない。

各軸状態での通常指令受付は、次のとおりとする。いずれも送信元検証と共通条件を省略しない。

| 軸状態・停止目的 | 新しい方向・数値目標の扱い |
| --- | --- |
| `OFF_UNREFERENCED`、`ARMING`、`OFF_INHIBITED` | 拒否する。ARM（サーボ動作許可）後の自動実行用には残さない |
| `READY_HOLD`、`TRACKING` | `C_RUN`成立時に受け付ける |
| `BRAKING_REPLAN` | 最新の方向・数値目標を1件だけ置換する |
| 砲身目標終了または砲塔範囲端に伴う`SETTLING` | `C_RUN`成立時、新しい目標または内側方向を受け付け、旧停止確認を終了する |
| 砲塔STOPに伴う`LOCAL_STOPPING`・`SETTLING` | STOP処理の完了まで左右指令を拒否する |
| 終了・省電力準備に伴う停止状態 | 両軸の通常指令を拒否する |
| `PWM_DISABLING` | 新しい通常指令を拒否する |

STOPは通常指令スロットの空きを必要としない。ARMING（サーボ動作許可処理中）の砲塔STOPはその軸の開始準備取消しとして扱い、第9.5節の安全側中断へ進む。

### 5.3 管理する位置情報

| 変数 | 意味 | PWM停止後 |
| --- | --- | --- |
| `q_goal` | 最新の有効な指令上の目標 | 実行資格を破棄 |
| `q_ref` | 速度・加速度制限後の連続指令位置 | 診断履歴だけ。再開には使用しない |
| `v_ref` | 指令位置の時間変化率 | 零に初期化 |
| `q_applied` | 最後にハードウェアへ反映した指令相当値 | 過去値としてのみ表示可 |
| `p_applied` | 最後に反映したパルス幅 | 現在有効な出力とは扱わない |
| `actualPosition` | 本構成では取得しない | 常に`UNKNOWN` |

`q_applied`もサーボが受信・追従したことの証明ではない。表示上の「現在角度」「実位置」「到達済み」へ変換しない。

### 5.4 識別情報と排他

起動単位、セッション、指令連番、実行世代、設定generation、ハードウェア版、校正版を保持する。異なる種類の識別子は別フィールドとし、数値が同じでも同じ取引とは扱わない。

停止要求識別子、終了識別子、低消費電力移行識別子、異常処置要求識別子、異常識別子集合は外部の管理元が提供する値をそのまま対応付ける。内部の`axisOperationId`を付与しても外部識別子を置換しない。

同一時点のPWM書込み主体を出力処理一つに限定する。安全経路は出力を禁止できるが、有効化は通常の出力処理だけが行う。禁止後に割込み前の処理が再開してPWMを再有効化しないよう、世代と禁止ラッチを出力コミットの直前で照合する。

## 6. 目標位置と軌道の生成

### 6.1 座標とPWM変換

各軸で、正規化座標`q=0`と`q=1000`に対応する校正済みパルス幅を`p0`、`p1000`とする。取付方向が逆なら`p1000 < p0`を許す。

```text
p_cont(q) = p0 + (p1000 - p0) * q / 1000
p_out(q)  = タイマ分解能に丸めた p_cont(q)
```

位置補正は、校正時に`p0`・`p1000`へ反映する。運用中に別のオフセットを後付け加算して安全端を広げない。非線形補正テーブルは本初版の必須機能にしない。E-03で2点対応が本設計前提を満たすことを確認する。設計前提に反する結果が判明した場合は、当該評価項目内で別方式へ切り替えず、本書または関係設計へフィードバックして改訂する。

丸め後も、校正されたPWM安全範囲およびタイマの表現範囲を確認する。丸め誤差で外へ出る場合は安全範囲内の隣接カウントへ内側丸めする。内部計算が大きく範囲外となった異常を、通常の丸めとして隠さない。

### 6.2 速度軌道の基本

各軸に最大指令位置変化率`V`と最大指令加速度`A`を設定する。単位はそれぞれ正規化単位/s、正規化単位/s²である。これらは実位置の速度・加速度の測定値ではない。

本案は加速度一定の区間を連結した台形軌道を基本とし、移動距離が短い場合は三角形軌道とする。ジャーク制限は採用しないが、加速度の切替えを含めて機構への衝撃をE-03で確認する。

停止距離と停止時間は、指令軌道上で次とする。

```text
D_brake = v_ref² / (2*A)
T_brake = abs(v_ref) / A
q_brake = q_ref + sign(v_ref) * D_brake
```

`q_brake`が安全範囲外となる内部状態は正常として扱わない。正常な軌道は、常に範囲内で減速停止できるよう生成する。状態破損等でこの条件を失った場合は、軌道を強制クランプして通常継続せず安全停止を要求する。

### 6.3 目標までの軌道の決定

現在の指令位置を`q`、速度を`v`、最新目標を`g`とする。次の順序で計画する。

| 条件 | 計画 |
| --- | --- |
| `g=q`かつ`v=0` | 新しい軌道を作らない |
| 現在速度が目標と逆向き | 現在方向へ減速して速度零、次に目標へ |
| 同方向でも目標が停止距離より近い | 安全範囲内の`q_brake`で一度停止、次に目標へ |
| それ以外 | 目標で速度零になる台形・三角形軌道 |

近い目標を受けた場合、指令位置を瞬時に目標へ飛ばさない。新目標を一時的に通過してから戻る場合があるため、状態は`BRAKING_REPLAN`とし、目標へ到達したとは通知しない。危険な干渉は、任意の位置組合せで安全な機構範囲によって防ぐ。

同方向で停止距離が収まる場合、`s=sign(g-q)`、`d=abs(g-q)`、`u=s*v`としてピーク速度を次で求める。

```text
v_peak = sqrt(A*d + u²/2)
```

`v_peak <= V`なら、`u`から`v_peak`まで加速し、`v_peak`から零まで減速する。`v_peak > V`なら、`V`まで加速し、残距離を等速、その後減速する。

各区間の位置は`q(t)=q0+v0*t+a*t²/2`、速度は`v(t)=v0+a*t`から求める。周期内に区間終端を通過する場合は、終端までの時間と残時間を分けて計算する。最後の区間終端を`g, v=0`と一致させる。毎周期の粗いオイラー積分後に端点で急停止する方式は採用しない。

### 6.4 砲塔方向指令

RIGHTでは`g=1000`、LEFTでは`g=0`として、前節の軌道を使用する。有効な同方向の継続指令では軌道を毎回初期化せず、継続操作の有効性だけを更新する。

範囲端に近付くと、同じ方向が押され続けていても、端点で速度零になるよう減速する。端点の外側へ積分値を蓄積しない。端点で反対方向の有効指令を受けた場合は、零速度から内側へ動かせる。

反転時は速度零を経由して新方向へ移る。反転途中にさらに方向が変わった場合は、現在の`q_ref`・`v_ref`から最新方向へ再計画する。過去の方向列を順に実行しない。

### 6.5 砲塔STOP

STOPを有効受付した時点で、左右への継続操作を終了する。通常方向の目標生成を停止し、現在軌道から`q_brake`で速度零となる停止専用軌道へ切り替える。

この減速に必要な位置変化は停止処理の一部であり、左右指令の継続ではない。通常停止確認後は最終PWMを保持する。PWMが既に停止している場合は、STOPによって開始・再開しない。

### 6.6 砲身数値目標

砲身の`g`は受信値とする。最新目標を、現在の`q_ref`・`v_ref`から前記方式で処理する。入力を大きく変更しても、PWM目標を一度に飛ばさない。

新しい目標が来なくても、認証・権限・電源等の`C_RUN`が成立する間は、受け付けた数値目標まで指令軌道を進める。BLE切断・安全停止等が成立した場合は、目標到達を待たず停止する。

指令軌道が終端となり最終PWM反映を確認した後、`COMMAND_TARGET_APPLIED`を通知する。第10章の停止確認時間を満了した場合は、通常保持へ移る。いずれの通知も実位置測定による到達保証ではない。

### 6.7 両軸の同時動作

2軸の指令位置、速度、軌道区間、PWM比較値を分離する。両軸を同じ制御周期で処理し、同時に有効な操作を一方ずつの動作へ直列化しない。

サーボ合計電流監視は2軸をまとめて行う。異常時に軸を特定できるとは扱わず、両軸の安全停止を要求する。

実機評価で同時動作の設計前提に反する結果が判明した場合、「一軸ずつなら動く」だけでSYS-TURRET-016を満足とはせず、関係設計へフィードバックして本基本設計を改訂する。

### 6.8 周期遅延と数値異常

位置計画は単調時刻を使用する。大きな周期遅延後に経過時間分を一括進行させ、PWM目標を飛ばして追い付かせない。第16章の期限違反を検出した場合は通常更新を止めて安全停止する。

平方根の定義域、零除算、NaN、無限大、整数オーバーフロー、許容外速度および無効な区間時間は制御異常とする。計算失敗を零位置への移動で代替しない。

## 7. 安全可動範囲と機構・配線条件

### 7.1 安全プロファイル

機構版、サーボの具体的仕様・取付方向、校正データ版ごとに安全プロファイルを管理する。プロファイルは単なるアプリの目標上限ではなく、PWM範囲、停止余裕、初回開始、無信号・無通電時の機構条件をまとめた設計上の組合せとする。

最低限必要な情報は、第14.2節に示す。実機で未確認のプロファイルを`validated`として登録しない。VPSの管理設定によって未評価プロファイルを有効化する仕組みは設けない。

### 7.2 範囲端の決め方

機構の公称可動限界から、取付誤差、軸・ギヤの遊び、弾性変形、サーボの指令追従誤差、停止後の移動、配線変形および測定誤差を差し引いて安全端を定める。

評価は、電源電圧範囲、使用姿勢、両軸同時動作、最大搭載物および外力条件を含める。安全余裕の量が未確定のため、本初版では実角度の下限・上限を数値確定しない。

安全端を通常動作中の機械的ストッパ接触位置と一致させない。ソフトウェア端点への保持で常にストッパを押し続ける構成は不適合とする。

### 7.3 2軸の干渉

設計上の安全領域を`[Tmin,Tmax] × [Bmin,Bmax]`の直積とする。四隅だけでなく、範囲内の移動経路、砲身・外装の掃引領域、配線の変形を確認する。

本基本設計では、砲塔・砲身の各安全可動範囲の直積全体を安全領域として成立させる。動的禁止領域制御は採用しない。安全可動範囲は、必要な操作範囲を確保しつつ、範囲内の任意の組合せおよび移動経路で干渉しないよう機構・配線・安全余裕を含めて決定する。実機評価はこの設計前提の成立確認であり、成立しないことが判明した場合は機構設計または本基本設計へフィードバックして改訂する。

### 7.4 配線と機械的保護

砲塔の多回転を前提にしない。電源線・信号線について、両端姿勢と中間姿勢で余長、最小曲げ、コネクタ近傍の固定、捻れの蓄積、筐体との擦れを確認する。

巻込み・挟込みを防ぐカバー、ストッパ、抜け止め等は、必要性と取り付け先を機構設計で確定する。電流増加による事後停止だけを干渉防止策としない。

### 7.5 PWM停止後の機構安全

PWM停止およびサーボ電源停止のいずれでも、砲身の落下、砲塔の急回転、突出部の衝突、挟込み、配線損傷等を発生させないことを必要条件とする。

PWM停止およびサーボ電源停止後の機構安全は、電気的な位置保持に依存せず、機械構造によって受動的に成立させる。具体的な構造は機構設計で具体化し、E-02では当該構造が本書の安全条件を満たすことを確認する。

ファームウェアが「機構安全」を返せるのは、対象プロファイルの評価が有効で、既知の破損・校正不整合・停止異常がなく、対応する停止条件が成立している場合に限る。運転中に機構の健全性をセンサで実測しているという意味ではない。

安全プロファイルがない場合、未確認の機構に対する通常終了・省電力準備の正常完了を返さない。ただし、緊急停止、危険電流保護、強制電源遮断を機構確認待ちで遅延させない。

## 8. PWM出力の管理

### 8.1 出力構成

PWM波形はMCU内蔵ハードウェアタイマで生成する本案とし、通常タスクがGPIOを周期的に反転して波形を作る方式は採用しない。2軸の周期は共通でもよいが、比較値と出力有効・無効を軸別に管理できることを必要条件とする。

タイマ・チャネル・端子番号は、既存の他機能との資源割付けを含む詳細設計で確定する。過去の試作端子割付けを本書へ転用しない。詳細設計では、本章で定める軸別独立制御、周期境界反映、停止および読戻しを実現できるタイマ・チャネル・端子を割り当てる。実機・回路確認でこの前提に反する事実が判明した場合は、本基本設計へフィードバックして改訂する。

本案の周期は20 ms（50 Hz）とする。ただし、これはDS3218の任意のバリアントに対するメーカー保証値として引用したものではない。E-03で採用現物・資料と照合する。

### 8.2 出力ゲート

本機能は、通常PWMの有効化権を一つの出力処理に限定する。電源投入要求と電気安全の安全許可は、既存の電源・省電力管理・電気安全設計が管理する。

```text
通常PWMを出力できる条件
 = 軸のローカル出力許可
 AND 電源・電気安全から提供された現行の使用許可
 AND 停止・機能禁止ラッチが解除済み
 AND 当該PWM予約のactuationEpochが現行と一致
```

これは論理上の条件である。すべてが単なるソフトウェア変数でよいという意味ではない。電源異常・リセット時のハードウェア初期値と安全ゲートは電源・省電力管理・バッテリー・電気安全監視の方式を使用し、具体的なPWM端子との関係をF-02で確認する。

本書は、本体側緊急停止からサーボPWMまでの独立ハードウェア停止経路が、既に採用・実装済みであるとは扱わない。既存の独立経路で明示されている走行停止と区別する。

### 8.3 PWM開始シーケンス

| 順序 | 処理 | 正常条件 |
| --- | --- | --- |
| 1 | 第9章の開始手順・`C_ENABLE`を確認 | 全条件が現在有効 |
| 2 | 出力禁止のまま周期・極性・初期比較値を設定 | 安全プロファイル内 |
| 3 | 設定をハードウェアから読戻す | 要求した周期・比較値・禁止状態と一致 |
| 4 | 保留中の更新・古いDMA要求等を消去 | 過去の出力予約がない |
| 5 | 電源実状態、電気安全許可、禁止ラッチ、実行世代を再確認 | 確認後の失効がない |
| 6 | 定義した周期開始点から初回の完全なパルスを有効化 | 途中位相から出力しない |
| 7 | 初回反映結果を取得し、時刻と比較値を記録 | 出力開始の制御側確認が成立 |
| 8 | ARMING（サーボ動作許可処理中）の待ち・電流監視へ移る | 第9章の完了条件へ |

設定完了前に端子のタイマ機能だけを先行して有効化しない。タイマの計数が既に途中である場合は、出力禁止のまま周期を同期させる。

開始要求への受付応答は、初回PWM反映の確認でも、サーボ位置到達の確認でもない。開始失敗時は両軸の安全停止要求と制御異常通知を行う。

### 8.4 PWM更新

通常更新では、計算した比較値を次の安全な周期境界で反映する。パルス途中で比較値を書き換え、予定外のパルス幅を生む方式は採用しない。

出力予約には軸、比較値、予定反映周期、設定generation、`actuationEpoch`を付ける。反映前に失効した予約は破棄する。反映結果には実際に使用した比較値と周期番号を対応付ける。

変化率は連続指令軌道に対して確認し、PWM量子化後は次も確認する。

```text
abs(今回比較値 - 前回比較値)
 <= ceil(abs(p1000-p0) * V * 反映間隔 / 1000) + 1カウント
```

上式の`p0`・`p1000`と比較値は、同じタイマカウント単位へ変換して使用する。反映間隔は秒とする。

1カウントは丸めによる差分の許容であり、大きな位置飛びを認める余裕ではない。初回PWMは過去値との連続性を保証できないため、この式だけで開始安全を判定しない。

### 8.5 PWM停止

ソフトウェアからの停止では、次回以降の新しいパルスを禁止し、既に出力中の正常パルスがある場合は、そのパルスの正常な下降端までに限り完了させる。その後、非駆動レベルに維持する。

これは安全停止時に機構の減速完了を待つ処理ではない。待つ対象は出力中パルスの最大幅だけであり、機械的整定時間や次の20 ms全周期ではない。要求からの処理時間上限は第16章に定める。

本基本設計では、選定するタイマ・ゲート方式がこの停止方法を実現し、不定な短パルスを発生させないことを成立条件とする。E-03ではその成立性を確認する。確認結果が本設計前提と一致しない場合は、F-02として関係設計へフィードバックし、本基本設計を改訂する。

危険な電気状態、ハードウェア保護または強制電源遮断は、パルス完了を待たず優先される。この場合の信号切断・電源低下中に意図しない動作を起こさない回路・サーボ挙動は別途確認が必要であり、通常のソフトウェア停止が成立するだけでSYS-TURRET-045を達成済みとはしない。

### 8.6 PWM停止確認の範囲

以下の制御側確認を満たす場合、`pwmOffControlConfirmed=true`とする。

| 確認対象 | 確認内容 |
| --- | --- |
| 通常出力許可 | 対象軸の出力許可が無効である。安全停止・緊急停止は両軸を確認する |
| 波形生成経路 | タイマ出力または確実な出力ゲートが禁止状態である |
| 残留出力 | 停止前のパルスが完了し、新しいパルス開始がない制御状態である |
| 予約更新 | DMA、割込み、バッファの旧予約が出力を再開できない |
| ハードウェア状態 | 可能な出力制御レジスタを読戻し、要求状態と一致する |
| 維持 | 禁止ラッチと現行実行世代により再開できない |

ドライバAPIが成功したこと、あるいはソフトウェア上の`enabled=false`だけでは確認済みとしない。

この確認は、ケーブル先端波形やサーボ内部トルクを独立に測定した結果ではない。結果には`evidence=CONTROL_READBACK`を付ける。外部PWM観測回路、サーボ角度センサ、トルクセンサは採用済み構成へ追加しない。

本基本設計におけるPWM停止確認は、上表の制御側確認を正式な確認方式とする。配線短絡、外部ゲート故障、サーボ内部故障など、制御側読戻しでは直接観測できない故障まで常時独立監視する方式は採用しない。これらについて要求上または評価上の不足が判明した場合は、本基本設計または上位設計へフィードバックして改訂する。

### 8.7 無信号と駆動電源

PWM停止、サーボ駆動電源OFF、内部駆動停止およびトルク消失は別の状態である。無信号でサーボがどのように動作するかは、採用現物に対してE-03で確認する。

本機能はサーボ電源を直接遮断しない。停止不能・停止維持不能は停止管理へ、残留電流は電気安全監視へ提供する。追加の系統遮断は、既存の停止・異常・電気安全・電源・省電力管理の責任分界によって実行する。

PWM停止後に危険な挙動が残る状態は、安全停止完了として扱わない。本基本設計では、第7.5節に定める機構安全と既存の電源・電気安全設計を組み合わせることで、PWM停止後も安全状態が成立するものとして設計する。実機評価でこの前提に反する事実が判明した場合は、関係設計へフィードバックして本基本設計を改訂する。

## 9. 起動とPWM再開

### 9.1 無出力で行う初期化

| 順序 | 処理 | 失敗時 |
| --- | --- | --- |
| 1 | リセット初期値から出力禁止を維持 | ハードウェア初期値不成立は実機使用不可 |
| 2 | 通常指令・軌道・PWM予約・開始確認を初期化 | 初期化失敗 |
| 3 | 設定、ハードウェア版、校正・安全プロファイルを確認 | 使用不可として返す |
| 4 | 出力禁止のままタイマ設定と読戻しを確認 | 制御経路異常 |
| 5 | 電気安全監視の利用可否と必要な現在情報を確認 | 未確認・失敗を明示 |
| 6 | 停止禁止ラッチと処理監視を有効化 | 起動失敗対象 |
| 7 | 自機能の初期化結果を起動管理へ返す | 受付だけを正常完了にしない |

初期化でサーボを振る、中央へ戻す、ストッパへ当てる、過去の位置を出力する診断は実施しない。PWMが出る試験は、許可された開発・評価作業に限定する。

安全プロファイルが未確認であることと、初回操作前の位置基準が未準備であることを区別する。前者は安全な機能提供が未成立であり、初期化結果または機能利用可否へ反映する。後者は`OFF_UNREFERENCED`であり、出力を停止したまま管理できる。

起動管理は自機能の結果を他機能と集約する。本機能が独自にシステムを起動失敗状態へ遷移させない。

### 9.2 なぜ初期値だけでは開始できないか

PWM停止中の実位置は取得できない。`q_ref=500`と初期化して少しずつパルス幅を変化させても、実際の軸が反対の端にあれば、最初のパルスで大きな移動を要求することになる。

停止前の目標をRAMや不揮発メモリに残しても、停止中に外力で動いた可能性は消えない。また、LEFTに対して固定の初期パルスを出す方法では、初動が逆方向となる可能性を排除できない。

したがって、初期値設定、低い指令変化率、長い待ち時間のいずれも、それだけでは初回PWMの安全な開始方式にならない。このため、本基本設計では第9.3節の`MANUAL_DATUM_ARM`を開始方式として採用し、E-01でその成立性を確認する。

### 9.3 開始方式 `MANUAL_DATUM_ARM`（手動基準合わせ後のサーボ動作許可）

本基本設計では、初回PWM開始およびPWM停止後の再開方式として`MANUAL_DATUM_ARM`を採用する。本書でいう**ARM（アーム）**とは、無駆動で基準位置を合わせた後、安全条件を確認してサーボPWM出力を有効化し、通常操作を開始可能な状態へ移す**サーボ動作許可処理**をいう。実位置を測定して自動調整・自動校正する処理ではない。追加するのは、実位置センサではなく、無駆動での基準合わせ手順と明示的なサーボ動作許可操作である。

無通電時に安全に基準合わせできる機構を設計前提とする。サーボのギヤを無理に逆駆動する、通電中に可動部を手で押さえる、ストッパへ力を加える方法は認めない。E-01では、この基準合わせ方法と初回PWM開始が安全に成立することを確認する。

基準位置は各軸の校正済み`q_seed`とし、機構の識別可能な合わせ位置、許容ずれおよび手順を対応付ける。本基本設計では、一般操作者が専用治具を追加しなくても定義された基準位置へ安全に合わせられる機構とする。具体的な形状・表示方法は機構設計で具体化し、E-01で再現性を確認する。

| 段階 | 操作者・関連機能 | 本機能 |
| --- | --- | --- |
| 1 | 主電源OFFで、定義された安全な基準合わせを行う | 出力なし |
| 2 | 起動、接続、認証、状態取得を完了する | 初期化してもPWM停止のまま |
| 3 | アプリで基準合わせ済み・周囲安全を明示確認する | 現行セッション・軸・実行世代に対応する確認を受ける |
| 4 | 操作者が対象軸の開始準備を明示要求する | `C_ENABLE`を再確認し、`q_seed`のPWMを開始 |
| 5 | 可動部へ触れず開始準備結果を確認する | 初期パルス反映後、開始確認時間と電流監視を実行 |
| 6 | 正常完了通知後に新しく左右・目標操作を行う | 新しい通常指令だけを実行 |

段階4の操作は、起動処理による自動移動ではない。ただし、実位置の小さなずれを修正する移動が起こり得るため、「動かない確認ボタン」とは表示しない。

通常指令を先に受け付けてARM（サーボ動作許可）完了後に自動実行しない。未準備状態のLEFT、RIGHT、砲身目標は`NOT_ARMED`で拒否する。STOPはPWMを再開せず、停止状態を維持する。

### 9.4 開始確認情報

開始確認情報には、確認識別子、起動単位、セッション、対象軸、`actuationEpoch`、校正版および確認時刻を含める。本案では5秒以内・一回限り有効とし、対象外の軸に流用しない。

これは操作者の手順確認であり、機構の現在位置を測定した証拠ではない。誤った基準合わせ・確認忘れ・確認後の外力を含めた合理的な誤使用に対して、危険を許容範囲へ抑えられることをE-01で確認する。確認ダイアログだけに安全を依存させない。

### 9.5 ARM（サーボ動作許可）の開始・完了・失敗

| 区分 | 条件 |
| --- | --- |
| 開始可能 | E-01で成立確認済みのプロファイル、現行の開始確認、`C_ENABLE`成立 |
| 開始 | 出力禁止で初期値設定後、初回パルスを有効化した時点 |
| 制御側完了 | 初回PWM反映確認、`q_seed`を変更しない開始確認時間の満了、監視正常 |
| 結果 | `ARMED_COMMAND_BASIS`。実位置測定・原点センサ検出成功ではない |
| 失敗 | 出力開始失敗、過負荷、監視不能、禁止成立、全体期限超過 |
| 中断 | 操作者取消し、上位停止・終了・電源保護要求 |

開始確認時間`T_ARM_SETTLE`は仮値500 ms、全体期限は2秒とする。値はE-01で決定する。E-01では、基準合わせ誤差を含む条件で初回PWM開始が安全に成立し、この時間内に開始確認を完了できることを確認する。

開始失敗・中断では両軸PWM停止と通常指令破棄を行い、開始確認を無効化する。同じ確認識別子で自動再試行しない。取消しだけでは新しい故障要因を追加せず、PWM停止を正常確認できた場合は未準備状態へ戻す。他の禁止・未復旧異常は維持し、停止失敗を伴う場合は第12章の異常処理を行う。

### 9.6 PWM停止後の再開

PWM停止、サーボ電源喪失、リセット、低消費電力からの復帰、緊急停止解除または異常復旧後は、過去の指令値によるPWMを自動復元しない。

PWM停止、サーボ電源喪失、リセット、低消費電力からの復帰、緊急停止解除または異常復旧後の再開には、同じ基準合わせと明示的なARM（サーボ動作許可）を必要とする。通常の砲塔STOP・砲身目標終了後にPWMを維持している間は、毎回ARMし直す必要はない。

主電源OFFでの基準合わせとARM（サーボ動作許可）は、本基本設計における再開手順の一部とする。短時間の安全停止後であっても、過去値を無条件に再使用してPWMを自動再開しない。

操作指令タイムアウト等の安全停止後にシステム状態が操作可能状態を維持している場合でも、本機能の両軸は`OFF_UNREFERENCED`のままであり、砲塔・砲身の通常操作は許可しない。再開には、主電源OFFでの基準合わせを含む本節の手順をあらためて実施し、起動後に新しいARM（サーボ動作許可）を完了する必要がある。システム全体の「操作可能状態」と、本機能の「サーボ動作許可済み」を同一状態として扱わない。

## 10. 動作終了・安全停止・緊急停止

### 10.1 停止に関する情報の区別

| 情報 | 成立の意味 | 成立しても意味しないこと |
| --- | --- | --- |
| `commandMotionEnded` | 通常方向生成終了、指令速度零、旧目標への継続なし | 実機が静止したという測定 |
| `motionStopConditionMet` | 指令終了、最終PWM反映、停止確認時間、監視正常 | 実位置到達の観測 |
| `pwmOffControlConfirmed` | 第8.6節の制御側停止確認 | 電源OFF、トルク零 |
| `offMechanicalSafetyQualified` | 対象機構の停止後安全プロファイルが有効 | 現物の破損を常時測定していること |
| `powerDownReady` | 終了・省電力の必要条件がすべて成立 | 系統遮断の完了 |
| `actualPosition` | 本構成では`UNKNOWN` | 指令値から値を補わない |

各確認項目は、成立、不成立、確認不能および適用外を区別する。`true`の表記は、その項目が適用対象であり、成立を確認した場合だけに用いる。

「停止完了」という一つの真偽値だけを関連機能へ渡さない。停止種別、対象軸、確認範囲、対応する要求識別子を必須とする。

### 10.2 停止方式の選択

| 要求・事象 | 砲塔・砲身の処理 | PWMの終状態 |
| --- | --- | --- |
| 砲塔STOP | 砲塔を減速し、局所停止確認 | 正常条件内で保持 |
| 砲身目標軌道終了 | 最終指令を反映し、局所停止確認 | 正常条件内で保持 |
| 走行用通常停止ボタン | 本機能の動作は変更しない | 既存状態 |
| 通常終了準備 | 両軸の現操作を終了、減速・停止確認 | 停止 |
| 低消費電力移行準備 | 両軸の現操作を終了、減速・停止確認 | 停止 |
| 安全停止 | 減速・整定を待たず出力停止 | 両軸停止 |
| 緊急停止 | 通常操作・準備を中断し出力停止 | 両軸停止 |
| 危険な電気状態・強制遮断 | 利用可能な範囲で出力禁止。遮断を妨げない | 停止側、未確認は未確認 |

### 10.3 動作停止条件

通常の局所停止と通常終了・省電力準備では、次をすべて満たした場合に`motionStopConditionMet`を成立させる。

| 条件 | 確認内容 |
| --- | --- |
| 通常操作終了 | 左右継続、旧砲身目標への進行を終了している |
| 指令軌道終了 | 停止専用軌道が終端で、`v_ref=0`である |
| 最終PWM反映 | 停止目標に対応する最後の比較値の反映が確認済み |
| 停止確認時間 | 最終PWM反映から`T_SETTLE`以上経過している |
| 制御と監視 | PWM更新、周期、電流および電気安全条件が正常 |
| 機構条件 | 現行の停止挙動プロファイルと一致している |

`T_SETTLE`は、指令追従の遅れと機械的な残留動作について、定義した最悪条件で確認した時間に余裕を加えて決定する。仮値は300 msとするが、実機評価前に安全な停止時間として採用しない。

停止確認中に過負荷、拘束、出力異常または電気安全条件喪失があれば、保持を続けて時間を待たず安全停止へ移る。

砲身が遠い目標へ移動中に終了要求を受けた場合、旧目標への到達を待たない。現在の指令速度を減速して停止可能な位置で止める。

**要求前からPWMが停止している軸**は、PWMを再開して上記手順を形式的に実行しない。次を満たす場合に、`stopBasis=PREEXISTING_OFF`として電力変更準備へ使用する。

- 実行中・未実行の操作がなく、軌道の実行資格がない。
- 現時点でPWM制御側停止と再開禁止を確認できる。
- 無信号・無通電時の残留動作を含む機構安全プロファイルが有効で、既知の停止安全異常がない。

この場合、通常の「PWM停止前の動作停止確認」は`NOT_APPLICABLE`とし、実施したことにしない。新たに終了させる操作がないための分岐である。過去の停止失敗が未復旧である場合、この分岐で正常化しない。

初期化後一度もPWMを開始していない軸についても同じ分岐を使用できる。機構安全プロファイルが無効なら、出力停止の事実は返すが電力変更準備の正常完了を返さない。

### 10.4 安全停止・緊急停止

| 順序 | 本機能の処理 | 応答 |
| --- | --- | --- |
| 1 | 停止要求識別子・種別・関連事象を保持 | 受付結果 |
| 2 | 両軸へ`INVALIDATE`を適用 | 新規実行禁止・指令破棄結果 |
| 3 | 停止前軌道と保持要求を実行不可にする | 旧指令再開不能 |
| 4 | 第8.5節のPWM停止を開始 | 開始時刻 |
| 5 | 両軸のPWM制御側停止を確認 | 軸別結果、確認方法、維持可否 |
| 6 | 停止管理へ結果を返す | 完了、失敗、確認不能を区別 |

安全停止と緊急停止では、`motionStopConditionMet`や`T_SETTLE`を待たない。安全位置移動、位置保持用のPWM継続、出力復帰試験も行わない。

一方の軸だけ停止確認できた場合、両軸完了を返さない。確認できた軸の停止を維持しながら、他軸の停止異常を通知する。確認済み部分を、他軸の失敗によって再有効化しない。

停止管理は、走行制御が返す走行側`DriveStopResult`と本機能の`ServoStopResult`を、同じ停止取引・目的へ対応付けて集約し、全体完了を判断する。走行側の局所完了も、左右の適用出力0・新規出力禁止・保留指令破棄・ドライバ反映結果等の制御側証拠であり、エンコーダを持たないため車体実速度0を観測した結果とは扱わない。砲塔・砲身側も同様に、証拠範囲を維持して全体結果へ渡す。

本機能が返す`ServoStopResult`の停止証拠は、第8.6節で定めるPWMの制御側停止確認である。位置センサを持たない本構成では、これを砲塔・砲身の機械的な完全静止を観測した結果へ読み替えない。停止管理は結果に含まれる証拠範囲を維持して全体結果を集約し、PWM無信号時・電源OFF時を含む物理的安全性は第7.5節およびE-02/E-03の機構・回路・実機評価で成立させる。

### 10.5 通常終了準備

通常終了の要求経路は、起動・終了・再起動管理→停止・緊急停止管理→本機能とする。

起動・終了・再起動管理・停止・緊急停止管理で定義される通常終了に伴うアクチュエータ安全処理要求を受け、本機能では`QUIESCE_FOR_POWERDOWN`として実行する。通常終了要求と、電源・省電力管理・停止・緊急停止管理で定義される低消費電力移行準備要求は、要求元・識別子によって区別するが、本機能内部の減速、動作停止条件確認、PWM停止および機構安全確認は共通シーケンスを使用する。これらを安全停止・緊急停止の即時PWM停止へ暗黙変換しない。

| 順序 | 処理 | 完了条件 |
| --- | --- | --- |
| 1 | 現行終了識別子と準備要求を受け付ける | 終了準備として受付 |
| 2 | 通常指令を禁止・破棄する | 旧指令が残らない |
| 3 | `C_QUIESCE`に従い両軸を減速する | 停止専用軌道の終了 |
| 4 | 第10.3節の動作停止条件、または既停止分岐を確認する | 選択した分岐の全条件成立 |
| 5 | 両軸PWMを停止する | 第8.6節の確認成立 |
| 6 | 停止後の機構安全条件を確認する | 有効なプロファイルと既知異常なし |
| 7 | `powerDownReady`を停止管理へ返す | 同じ終了識別子に対応 |

サーボ電源OFFは、全アクチュエータの準備結果を確認した後、起動管理が電源・省電力管理へ要求する。本機能の返答は電源遮断済みを意味しない。

準備中に安全停止・緊急停止・電気保護が成立した場合、減速・停止確認待ちを中断する。元の準備要求には`PREEMPTED`を返し、上位停止の結果を別に返す。既に安全停止でPWMがOFFなら、その有効な結果を添えて再確認できるが、未達の機構安全を自動的に補完しない。

### 10.6 低消費電力移行準備

低消費電力移行では、電源・省電力管理が停止・緊急停止管理へ、移行識別子と停止目的「低消費電力移行準備」を伴うアクチュエータ停止・電力変更準備要求を提供する。停止・緊急停止管理が同じ移行識別子と停止目的を保持した要求を本機能へ提供し、本機能はこの経路を低消費電力移行に伴う物理停止の唯一の通常要求経路とする。

本機能は、通常終了と同じ`QUIESCE_FOR_POWERDOWN`を使用する。同じ移行識別子について、電源・省電力管理から走行・砲塔・砲身へ重複して物理停止要求を出す構成とはせず、停止・緊急停止管理から受けた一つの停止取引だけを実処理へ対応付ける。重複要求または再送を受けた場合は、同じ停止取引の進行中または確定済み結果を返し、物理的な停止を二重に開始しない。

準備完了は、両軸について動作停止条件、PWM制御側停止、指令破棄および機構安全条件が成立した場合に限る。要求前からPWM停止の軸は、第10.3節の`PREEXISTING_OFF`分岐で確認する。準備結果は同じ移行識別子で停止・緊急停止管理へ返し、停止・緊急停止管理が他アクチュエータ結果と集約する。実際の`PWR_SERVO`電源状態変更と最終の低消費電力移行コミットは、電源・省電力管理およびシステム状態管理がそれぞれの責任範囲で行う。

移行が取り消された場合、準備の予約は解除できるが、PWMを復元しない。制御処理だけを使用可能へ戻し、軸は`OFF_UNREFERENCED`とする。上位の安全停止による禁止ラッチを、低消費電力移行の取消しで解除しない。

### 10.7 復帰・OTA・設定適用の停止維持

低消費電力からの復帰時は、出力禁止のままタイマ、現在設定、制御周期および監視経路を確認する。復帰正常完了のためにPWMを出す必要はない。

OTA・設定適用の準備では、通常操作が存在せずPWM停止を維持できることを提供する。OTAや設定処理が、本機能の内部フラグだけを書き換えて停止を成立させる方式は採用しない。

省電力のため通常制御を休止する場合の監視引継ぎは、第16.6節に従う。低消費電力中に10 ms制御が進行しないことを通常運転の周期異常にせず、復帰時には出力禁止のまま監視を再確立する。

### 10.8 停止失敗と停止後の異常

PWM停止開始から第16章の期限内に制御側停止を確認できない、停止確認後に出力許可が復帰した、または確認情報が不正となった場合は、停止異常として停止管理へ直ちに通知する。

停止管理・異常管理が必要とする追加停止、電源・省電力管理のサーボ系統遮断、電気安全の保護を妨げない。追加遮断が成功しても、当初のPWM停止処理失敗を正常へ書き換えない。

停止後の合計電流監視と保護用遮断の成功判定は電気安全・電源・省電力管理が担当する。危険過電流後に必要と確定した系統遮断が失敗・確認不能となった場合は、本体電源遮断へ進む既存方針を維持する。省電力時の任意な通電維持縮退へ読み替えない。

## 11. 過負荷・拘束の監視

### 11.1 判定対象と検出限界

本機能は、サーボ駆動系の**過負荷・拘束疑い**を機能単位で検出する。合計電流だけから砲塔・砲身のどちらが拘束したかを断定しない。

実位置が取得できないため、「目標と実位置の偏差」「指令を出したのに実位置が変わらない」といった判定を使用しない。使用する位置変化は`q_ref`・`q_applied`の変化であり、指令側の動作区分を決める情報である。

高い保持負荷、2軸の正常な同時負荷、一方の拘束が同じ電流域へ入る場合がある。検出条件を記述しただけでSYS-TURRET-060の実現を確定しない。E-04で識別性と検出期限を確認する。

### 11.2 電気安全監視から受け取る情報

本機能は、バッテリー・電気安全監視が正式な管理元として提供するサーボ駆動系合計電流の**監視値スナップショット**を使用する。値だけを複製して本機能独自に管理する最新電流値とせず、値と同じスナップショットに対応付けられた品質・鮮度・世代・時間窓情報を合わせて判定する。

| 情報 | 必須の扱い |
| --- | --- |
| 電流値・派生値 | 現在の電流状態、`I_RMS20`、必要な場合の`I_RMS500`・`I_RMS2000`、最大値を用途ごとに区別する |
| 計測更新世代 | 同じ世代の再読を新しい測定または新しい継続時間として扱わない |
| 取得・確定時刻 | 古い値を最新値へ読み替えず、鮮度判定に使用する |
| 品質状態・有効性 | 無効、欠測、更新停止、範囲外等を正常な零電流へ置換しない |
| 時間窓情報 | 名目窓長、取得済み有効区間、有効サンプル数、必要サンプル数、全窓成立可否を識別する |
| 電流状態・保護状態 | 電気安全側の危険判定・保護を本機能の機能保護判定で解除または緩和しない |
| `PWR_SERVO`実状態・使用可否・新規出力禁止 | 電源・電気安全条件が不成立なら新規出力を作らない |

バッテリー・電気安全監視の通常取得周期1 msと、通電中の電流値が50 msを超えて更新されない場合の監視異常方針を使用する。本機能が周期ごとに同じスナップショットを読めても、計測更新世代または取得・確定時刻が進行していなければ鮮度回復とはしない。サーボ系統が既知のOFFで、電気安全監視が停止を許可した電流経路については、意図した取得停止を通電中の更新停止異常と混同しない。再投入・PWM開始前には通常監視の有効な情報を改めて必要とする。

同じ計測更新世代の値を再読しただけでは、過負荷の観測継続時間を新たに加算しない。連続時間は、品質が有効で取得・確定時刻および計測更新世代が進行している監視結果に対応付ける。欠測期間を正常電流や過負荷の確定観測で補間しない。

過負荷・拘束監視の短窓電流として`I_RMS20`を使用する。バッテリー・電気安全監視が提供する名目20 ms窓の全窓成立可否、有効サンプル数および必要サンプル数を確認する。全窓成立前の値を「完全な20 ms窓で成立した過負荷」として扱わず、取得済み有効区間を識別した開始時監視と既存の電気保護を継続する。欠けた区間を零値または直前値で補完しない。

### 11.3 動作区分

| 区分 | 指令・出力上の条件 |
| --- | --- |
| `POWERED_NO_PWM` | 電源ONで両軸PWM停止 |
| `ARM_TRANSIENT` | 有効なPWM開始に対応する短時間区間 |
| `ONE_AXIS_MOVING` | 一方の指令位置が変化し、他方は保持またはOFF |
| `TWO_AXES_MOVING` | 両方の指令位置が変化 |
| `REVERSAL_TRANSIENT` | 実際の指令軌道の方向反転に伴う短時間区間 |
| `HOLDING` | 出力中の指令位置が一定 |
| `STOP_SETTLING` | 停止専用減速・停止確認中 |

これは物理的な動作観測ではない。同じPWMを出しているのに外力によって位置が変わった状態を、本機能が直接把握できるとはしない。

### 11.4 基本判定方式

動作区分ごとに、通常負荷上限`I_NORMAL_MAX[c]`、機能過負荷しきい値`I_FUNC_TRIP[c]`、ヒステリシス`H_I[c]`を安全プロファイルへ持つ。

10 ms周期で、有効な短窓電流を用いて次を判定する。

```text
I_RMS20 >= I_FUNC_TRIP[c] が T_FUNC_OVER 以上連続
  → 過負荷・拘束疑い成立

I_RMS20 <= I_FUNC_TRIP[c] - H_I[c] が T_CLEAR_CANDIDATE 以上連続
  → 過電流候補の継続時間を解除可能
```

しきい値以上の連続時間を`overDwell`、ヒステリシス付き候補の有無を`candidateActive`として別に管理する。実測値が現在使用する判定しきい値未満となった場合は`overDwell`を零に戻す。低下が短時間で候補を解除できない場合でも、しきい値未満の時間を「以上の連続時間」に加算しない。

候補継続中に動作区分だけが切り替わっても、継続時間を零へ戻さない。現在値が切替前後のしきい値の低い方以上である間は、同じ候補として積算する。大きいしきい値への切替えだけで候補を消さない。

区分別しきい値とは別に、全区分に共通する機能過負荷上限`I_FUNC_ABS`を設ける。有効な`I_RMS20 >= I_FUNC_ABS`を一回確認した時点で成立させ、`T_FUNC_OVER`を待たない。区分判定の誤りによって、この上限を超え続ける状態を見逃さない。既存の電気的危険過電流判定とは別の、より早い機能保護として扱う。

`T_FUNC_OVER=100 ms`、`T_CLEAR_CANDIDATE=100 ms`を評価開始用の暫定基本値とする。`I_NORMAL_MAX[c]`、`I_FUNC_TRIP[c]`、`I_FUNC_ABS`および`H_I[c]`は、現資料では正常負荷と片軸拘束を安全に区別できる実測根拠がないため、基本設計で管理し、評価結果を基に確定する値とする。これらの電流値と継続時間・解除候補時間は、過負荷・拘束の成立時点、安全停止要求の開始および通常操作可否を決めるため、詳細設計専用値として扱わない。

E-04で正常負荷と拘束・過負荷を分離できる正式値を評価し、`I_NORMAL_MAX[c]`、`I_FUNC_TRIP[c]`、`I_FUNC_ABS`、`H_I[c]`、`T_FUNC_OVER`および`T_CLEAR_CANDIDATE`を本基本設計へ反映して正式値として確定する。評価記録だけ、または詳細設計内の定数変更だけで正式値へ移行しない。正式値の反映が完了するまでは、未設定値を「しきい値最大」等として運転せず、本機能の一般操作を許可しない。

### 11.5 始動・反転時の一時増加

短時間区間の最大長は、バッテリー・電気安全監視の方針に合わせて200 ms以下とする。本機能の基準時刻は、指令の受信時刻ではなく、PWM開始または実際の指令軌道反転が出力へ反映された時刻とする。

同一サーボ系統の一時増加区間は重ねない。周期的な同方向指令、短いPWM OFF/ON、相反指令の連打で開始時刻を更新しない。新区間は、前区間が終了し、通常負荷へ戻ったことを確認してから許可する。

一時増加区間では、評価済みの一時増加しきい値を適用する。ただし、機能過負荷共通上限、電気安全の高速保護、ハードウェア保護を無効化しない。一時増加として認めない増大や区間満了後の持続は停止対象とする。

バッテリー・電気安全監視のRMS長窓の扱い、直近2秒の過剰電流積算および区間延長防止は、電気安全監視側で維持する。本機能は同じ電気保護を別のリセット可能な積算器で置換しない。

### 11.6 しきい値の決定と成立確認

E-04では、各動作区分について、通常負荷最大値・ばらつきと、検出対象とする拘束・過負荷の最小持続値を測定する。

```text
正常負荷の最大値 + 測定誤差・ばらつき余裕
    < I_FUNC_TRIP[c]
    <= 検出すべき拘束・過負荷の最小値 - 測定余裕
```

本基本設計では、上式を満たす`I_FUNC_TRIP[c]`を実機評価によって設定できることを前提とする。E-04では、通常動作を不要に停止させず、検出対象とする拘束・過負荷を必要時間内に検出できる分離が成立することを確認する。評価結果がこの前提と一致しない場合は、しきい値だけで要求を満たしたことにせず、関係設計へフィードバックして本基本設計を改訂する。

バッテリー・電気安全監視基本設計 §6.3にあるサーボ系統の暫定通常連続電流3.6 Aを、そのまま拘束判定しきい値にしない。既存文書もロック電流を安全な連続運転電流とは扱っていない。本書では電気保護値を再定義せず、機能保護との整合だけを確認する。

### 11.7 過負荷成立時

| 順序 | 処理 |
| --- | --- |
| 1 | 両軸の新規実行を禁止し、旧指令を破棄する |
| 2 | 停止管理へ過負荷・拘束を理由とする安全停止を要求する |
| 3 | 危険を増やさない一次処理として両軸PWM停止を開始する |
| 4 | 異常管理へ検出区分、電流、時間、指令状態、電気安全事象との相関を通知する |
| 5 | PWM停止結果を停止管理と電気安全監視へ提供する |
| 6 | 異常管理が定める制限と復旧待ちを維持する |

異常管理の登録応答またはログ保存を待って停止を遅延させない。一方、本機能が走行出力を直接停止・再開することもしない。

### 11.8 停止後の原因解消

PWM停止後に電流が下がっても、機械的な拘束原因が解消したとは判定しない。無通電の零電流、センサ欠測および外力による機構移動を原因解消の証拠にしない。

本機能固有の過負荷・拘束は、異常管理基本設計の所有者による明示的復旧方針に従う。ただし、電気的危険過電流、短絡または停止異常を併発した場合は、その異常に必要な開発・保守者の復旧条件を緩和しない。

現物確認と診断を含む復旧条件は第12.4節に定める。

## 12. 異常処理と復旧

### 12.1 異常の管理単位

下表の名称は異常管理基本設計 §5.1.6の管理単位を使用する。右欄は本機能の検出・結果生成を具体化したものであり、最終処置を本機能へ移すものではない。

| 管理単位 | 本機能の検出例 | 既存の基本処置・復旧 |
| --- | --- | --- |
| 砲塔・砲身指令異常 | 形式、値域、矛盾、無効な指令 | 拒否して継続可能。安全継続不能なら安全停止要求 |
| 砲塔・砲身制御設定異常 | 無効な安全範囲、PWM設定、校正版不整合 | 機能制限。正常設定復元、不能なら開発・保守 |
| 砲塔・砲身制御異常 | 範囲外生成、PWM開始・更新異常、周期違反 | 安全停止後に機能制限。開発・保守復旧 |
| 砲塔・砲身停止異常 | PWM停止不能、維持不能、必要な停止安全不成立 | 異常停止・追加安全処理。開発・保守復旧 |
| 砲塔・砲身過負荷・拘束 | 第11章の持続電流条件 | 安全停止後に機能制限。所有者の明示的復旧 |

機能制限が成立した後に走行を継続できるかは、異常管理と状態管理が他の条件も含めて判断する。本機能は「サーボが止まったので走行再開可」を直接通知しない。走行制御も走行制御の局所利用可否・出力禁止を管理し、システム全体として走行を許可するかはシステム状態管理・異常管理の判断に従うため、この責任分界は走行制御完成後も変更しない。

### 12.2 一次処理と主通知

局所検出で安全な動作継続を保証できない場合、まず新規出力禁止と安全停止要求を行う。既に停止管理から要求を受けている場合は、その停止要求識別子に対応付けて結果を返し、多重な停止を開始しない。

異常通知には、異常通知取引識別子、発生元、検出状態、対象軸または両軸、設定generation、取得できた電流・出力状態、推奨処置を含める。異常管理の受付結果で確定異常識別子を取得する。

同じ通知の再送では同じ取引識別子を使う。異常管理からの応答を受けられない場合は通知未完了として保持し、正常扱いに戻さない。

電流サンプル取得異常の主通知は電気安全監視とする。本機能は、その影響による実行禁止、PWM停止、未確認状態を提供する。同じ電気安全事象を別の危険過電流として重複確定しない。

### 12.3 周期監視・処理停止

通常制御は、指令検証、軌道処理、出力予約、監視結果更新を正常に完了した場合だけ`controlProgressSeq`を更新する。関数入口で更新して、処理途中の停止を正常に見せない。

`controlProgressSeq`、最終正常完了時刻、現在の制御有効・意図的休止状態を、システムアーキテクチャで定める独立したシステム監視経路へ提供する。本機能自身がこの情報を読み返して正常性を自己認定する構成とはしない。システム監視経路は、現在のシステム状態で本機能の周期制御が監視対象である場合に進行を確認し、停止・デッドロック・処理期限超過を検出した結果を異常管理およびIWDT更新許可条件へ連携する。

本機能に必要な安全停止・出力禁止をIWDTリセットより早く開始する必要がある場合、システム監視経路からシステムアーキテクチャで定める安全関連経路へ直接停止・出力禁止要求を提供できる構成とする。本機能は、その安全要求を通常処理やログ・異常通知の完了待ちで遅延させない。

共通SystemMonitor契約は本体ソフトアーキテクチャ基本設計の定義に従い、SystemMonitor周期10 ms、10 ms重要ProcessがMONITORED中に30 ms以上正常完了更新なしとなった状態を処理の進行停止による異常候補とする。本機能は`controlProgressSeq`、最終正常完了時刻、制御有効・意図的休止状態および正常完了を示すチェックポイントの意味を定め、共通監視値を独自に再定義しない。チェックポイント表現の具体的なデータ配置および監視実装は本体ソフトアーキテクチャ基本設計/インターフェース・通信基本設計の契約の範囲で詳細設計する。砲塔・砲身固有で30 msより厳しい期限が必要となる場合は詳細設計だけで追加・緩和せず、本基本設計へフィードバックして確定する。本機能がIWDTを独自に更新したり、自機能だけの生存を理由としてIWDT更新を許可したりしない。

CPU全体が停止した場合は、既存のIWDT・リセット時出力禁止・電気的独立保護の組合せで安全側へ移行する。

### 12.4 原因解消条件

| 異常 | 原因解消を判断するための条件 |
| --- | --- |
| 指令異常 | 無効指令を排除し、内部状態が正常。後続正常指令は新規として検証 |
| 設定異常 | 設定管理による有効な全体設定の復元と、自機能の再検証成功 |
| 制御・PWM異常 | 開発・保守による原因特定・是正、無出力診断成功、必要な評価再実施 |
| 過負荷・拘束 | 障害物・配線拘束等の除去、機構損傷なしの現物確認、電気安全正常、停止維持正常 |
| 停止異常 | 出力・ゲート・配線原因の是正、停止・維持確認、停止試験の再実施 |
| 監視値異常の影響 | 電気安全監視からの正常な原因解消・復旧結果と現行監視情報 |

現物確認を必要とする項目は、操作者・所有者・開発保守者が実施した確認情報として受け取る。センサ検出と同じ信頼度には扱わない。所有者確認で許可する範囲を超える破損・原因不明・再発は、開発・保守へ引き継ぐ。

確認のために自動的にサーボを動かし、障害物へ再度押し付ける診断は採用しない。

### 12.5 復旧処理

原因解消、復旧開始可能、明示的復旧要求、局所診断完了、異常管理の最終復旧完了を区別する。

| 順序 | 処理 |
| --- | --- |
| 1 | 原因解消結果を異常管理へ提供する |
| 2 | 異常管理から、認証・権限・対象を確認済みの復旧開始要求を受ける |
| 3 | PWM停止のまま、設定・出力経路・監視・禁止ラッチを診断する |
| 4 | 同じ復旧要求識別子で、局所結果と残存異常を返す |
| 5 | 異常管理の最終復旧正常完了を確認する |
| 6 | 異常に対応する局所制限だけを解除し、`OFF_UNREFERENCED`へ移る |

他の停止理由、緊急停止、電気保護の禁止をまとめて解除しない。復旧が完了してもPWMは開始しない。第9章の開始手順と、新しい通常指令を必要とする。

復旧中の異常、要求対象不一致または期限超過は失敗とする。復旧可能というレベル情報だけで復旧を開始しない。

### 12.6 再起動・電源断越しの扱い

明示的復旧を必要とする異常を、再起動やPWM初期化だけで消去しない。

異常状態として保持すべき情報の正式な管理元は異常管理とする。本機能は必要な根拠を提供し、起動時に異常管理から未復旧状態を取得して制限へ反映する。最後の位置指令や出力波形を、再開用の永続データとして保存しない。

異常通知・保持状態を確認できない場合は、未復旧異常がないと推定せず、安全な使用可否を返さない。

| IF-11 | ログ・診断 | 現在診断、評価用トレース制御 | 現在値・品質、トレース可否・欠落 |
| IF-12 | OTA・設定等の管理機能 | 停止状態の参照・準備状態の確認 | 確認時点付き停止状態。必要な停止は停止管理へ |

IF-05とIF-06は停止・緊急停止管理が管理する停止取引を使用する。本機能は第10.5～10.6節の共通停止準備シーケンスを適用し、要求元、停止目的、停止要求識別子、終了識別子または移行識別子との対応を失わない。電源・省電力管理から同じ物理停止を直接重複要求する経路は設けない。

### 13.3 提供する結果

| 結果 | 内容 | 受信側が行う判断 |
| --- | --- | --- |
| `CommandValidationResult` | 連番、機能検証の成否、理由、受信時刻との相関 | BLEが最終有効受信情報を確定 |
| `CommandExecutionResult` | 受付、置換、実行開始、目標反映、拒否 | アプリの表示。実位置には変換しない |
| `TurretLeaseState` | 継続旋回中か、対象セッション・実行世代 | 停止管理がタイムアウト対象を判断し、BLEの最終有効受信情報と組み合わせる |
| `ServoStopResult` | 軸別PWM確認、維持可否、証拠範囲、失敗 | 停止管理が制御側停止結果を集約。機械的静止の観測結果には読み替えない |
| `ServoPowerDownResult` | 動作停止条件、PWM停止、機構安全プロファイル適合、指令破棄 | 停止管理が終了・省電力のアクチュエータ準備結果を集約 |
| `ServoActivity` | 軸別PWM状態、開始・停止時刻、指令動作区分 | 電気安全が電流状態と関連付ける |
| `ServoAvailability` | 機能利用可否、局所禁止、未準備状態 | 状態管理が全体条件と合わせる |
| `ControlProgressCheckpoint` | `controlProgressSeq`、正常完了時刻、実行世代、制御有効・意図的休止状態 | システム監視経路が重要周期処理の正常進行を確認し、異常管理・IWDT更新条件へ連携 |
| `FaultObservation` | 検出区分、取引識別子、測定・内部状態 | 異常管理が処置・復旧を判断 |

`ServoStopResult`は第10.1節の区分を保持する。安全停止では動作停止条件の事前成立を待たないため、当該項目が未確認でもPWM停止結果は返す。ただし、未確認を正常成立へ書き換えない。

### 13.4 要求と結果の共通情報

| 項目 | 規則 |
| --- | --- |
| 要求元・要求種別 | 同じ数値の識別子でも要求元が違えば別取引 |
| 要求識別子 | 発行元のものを保持。応答で必ず返す |
| 起動・セッション・設定の世代 | 必要な対象範囲だけを付け、別起動の結果を流用しない |
| 対象軸 | 砲塔、砲身、両軸。安全停止は両軸 |
| 相関識別情報 | 停止、終了、移行、電気安全事象、異常処置の対応 |
| 処理結果 | `ACCEPTED`、`IN_PROGRESS`、`COMPLETED`、`FAILED`、`CANCELLED`、`PREEMPTED`、`UNKNOWN` |
| 時刻・順序 | 受信、実行開始、反映、完了を区別 |
| 理由・確認範囲 | 失敗理由、未確認項目、制御側確認かを明示 |

外部の異常処置要求に対応する停止結果は、固定された対象異常識別子集合との関係を保持する。処理中に別異常が追加された場合、追加要求の識別子にも対応付けるが、以前の結果を未指定の異常へ無条件に流用しない。

### 13.5 重複、遅延および確認不能

同じ要求識別子を再受信した場合、進行中なら進行状態を、完了済みなら保持した同じ結果を返す。異なる停止要求が同じ物理的なPWM停止へ集約される場合でも、要求と結果の対応は失わない。

タイムアウト後に古い完了通知が届いても、新しい要求の完了に使わない。取消し済み要求の正常完了を後から受信した場合は、その時点の実状態を再確認するが、PWMを再開して帳尻を合わせない。

結果を取得できない場合、受信側は当該処理を正常完了として扱わない。本機能が要求を受けたものの結果を送れなかった場合は、保持可能な範囲で同じ識別子の結果照会に応答する。

### 13.6 受付と処理期限

通常指令は待ち行列を作らず、所定周期で最新値を処理する。停止要求は通常指令処理より優先し、通信・保存待ちを含まない経路で受け付ける。

初期化・停止・準備・設定・復旧のローカル処理期限は第16章にまとめる。上位管理機能がより短い期限を指定した場合、通常の準備・設定処理は期限不成立を返す。安全停止・緊急停止・電気保護は、指定期限を満たせない場合でも実行可能な安全処理を直ちに開始・継続し、期限不成立と確認できた結果を報告する。上位の全体期限を、自機能の再試行で更新しない。

期限違反を検出したときは、実行中の処理を正常完了として返さず、失敗理由と出力の現在確認範囲を返す。

### 13.7 電気安全連携の優先性

電気安全上の新規出力禁止を受けた時点で実行資格を失効させ、その受付結果を返す。停止管理からの停止要求をまだ受信していなくても、新しい通常出力を作らない。

電気安全から提供される「安全停止・終了制御継続可能」が失われた場合、停止のための保持・減速を続けず、PWM停止側へ移る。危険状態の解消判定、系統遮断結果、保護ラッチの解除は本機能で代行しない。

バッテリー・電気安全監視の「PWM停止後50 ms以内の残留電流確認」は電気安全側の判定である。本機能は最後のパルスが終了した制御側時刻を提供し、応答送信の遅れで監視開始時刻を後ろへずらさない。

## 14. 設定と校正情報

### 14.1 管理単位と変更権限

VPS管理設定は、一つの設定パッケージ全体として検証・保存・適用する既定方式に従う。本機能の設定部分だけを独立した正常設定として確定しない。

通常管理設定の登録・変更・配信はシステム管理者・開発者が行う。所有者・一般操作者へ、安全範囲、PWM範囲、過負荷しきい値または停止時間の直接変更を提供しない。

機構版、サーボ仕様、校正値、評価済み上限および評価承認状態は製品・校正情報として扱い、通常のVPS設定で自由に拡大しない。本機能が必要とする情報と受渡し条件は本章で定め、F-05として設定管理・製品情報管理の関連設計へ反映する。

### 14.2 設定項目

数値未確定の項目も、型、単位、必須性および未設定時の扱いを定める。

| 項目 | 型・単位 | 本案の扱い | 未設定・不正時 |
| --- | --- | --- | --- |
| `hardwareProfileId`、`mechanismRevision` | 識別子 | 製品情報と一致必須 | 利用不可 |
| `servoVariantId[2]` | 識別子 | 採用現物の仕様を識別 | 利用不可 |
| `calibrationRevision` | 版番号 | 2軸と機構の組合せを識別 | 利用不可 |
| `p0[2]`、`p1000[2]` | 正整数、µsまたはタイマカウント | 校正済みの安全端 | 利用不可 |
| `pHardwareMin/Max[2]` | 正整数、µs | 部品・回路上の許容範囲 | 利用不可 |
| `pwmPeriod` | 正整数、µs | 仮値20000。E-03確認必須 | 利用不可 |
| `V[2]` | 正数、正規化単位/s | 仮値100。評価済み最大値以下 | 利用不可 |
| `A[2]` | 正数、正規化単位/s² | 仮値2000。評価済み最大値以下 | 利用不可 |
| `q_seed[2]` | 整数0～1000 | 採用済み`MANUAL_DATUM_ARM`の校正済み開始位置 | ARM（サーボ動作許可）不可 |
| `seedAlignmentTolerance[2]` | 機構の評価単位 | 初回PWM安全評価で確定 | ARM（サーボ動作許可）不可 |
| `T_SETTLE[2]` | 正整数、ms | 仮値300。停止挙動の評価値 | 準備正常完了不可 |
| `T_ARM_SETTLE[2]` | 正整数、ms | 仮値500。開始挙動の評価値 | ARM（サーボ動作許可）不可 |
| `I_NORMAL_MAX[c]` | 非負値、mA | 評価済みの正常負荷上限 | 通常操作不可 |
| `I_FUNC_TRIP[c]`、`I_FUNC_ABS` | 正数、mA | 動作区分別・共通の機能保護値。一時増加区分も定義必須 | 通常操作不可 |
| `H_I[c]` | 非負値、mA | 電流判定のヒステリシス | 通常操作不可 |
| `T_FUNC_OVER` | 正整数、ms | 仮値100。検出時間の評価が必要 | 通常操作不可 |
| `T_CLEAR_CANDIDATE` | 正整数、ms | 仮値100。候補取消し用 | 通常操作不可 |
| 機構安全・停止・開始の評価適合情報 | 版付き情報 | 現行構成と一致、保守管理 | 対応する操作・完了を禁止 |

仮値は出力を許可する安全な工場出荷設定ではない。初版の未評価状態をそのまま量産・一般操作の初期値にしない。

この表のうち、`pwmPeriod`、`V`、`A`、`T_SETTLE`、`T_ARM_SETTLE`、`I_NORMAL_MAX[c]`、`I_FUNC_TRIP[c]`、`I_FUNC_ABS`、`H_I[c]`、`T_FUNC_OVER`および`T_CLEAR_CANDIDATE`は、最終値がPWM動作、操作応答、停止確認、異常成立または安全停止開始を決めるため、評価確定待ちを含む本基本設計で管理する値として扱う。各E-xxで評価した後、正式値を本基本設計へ反映してから一般操作用の安全プロファイルとして有効化する。

`p0`、`p1000`、`q_seed`および`seedAlignmentTolerance`のように機構・個体・校正に依存する値は、個々の実値を製品・校正情報として正式に管理することを許容する。ただし、本基本設計はそれらの意味、安全側の制約、未設定時の禁止動作、検証方法および評価済みプロファイルだけを使用する規則を定める。評価結果によって安全可動範囲、開始手順、停止条件その他のユースケース上の振る舞いが変わる場合は、製品・校正情報だけを更新して済ませず、本基本設計も改訂する。

### 14.3 相互整合性検証

| 検証対象 | 条件 |
| --- | --- |
| PWM端 | `p0 != p1000`、両端がハードウェア許容範囲内 |
| PWM周期 | すべての安全パルスが周期より短く、停止時間配分にも収まる |
| 方向 | 0・1000と左・右、下・上の対応が現物校正と一致 |
| 変化率 | `V>0`、`A>0`、有限値、評価済み上限以下 |
| 通常旋回停止 | `V/A <= 50 ms`を本案の応答予算条件とする |
| 軌道時間 | 全安全範囲と、移動中の反転・再計画を含む最大計画時間が本案の60秒上限内 |
| 開始位置 | 採用された基準合わせ方式と`q_seed`が一致 |
| 電流 | `I_NORMAL_MAX[c] < I_FUNC_TRIP[c] <= I_FUNC_ABS`、`0 <= H_I[c] < I_FUNC_TRIP[c]`。一時増加区分も評価し、電気保護の優先関係を維持 |
| 待ち時間 | 実測最悪値以上で、全体の終了・省電力予算内 |
| 評価情報 | 機構・サーボ・校正・電源条件が評価対象と一致 |

安全プロファイルの端点に対する補正は、PWM最終範囲を再検証する。方向反転設定とPWM端点の並びを二重に反転させない。

候補設定の不正値を暗黙に補正して採用しない。現在有効な設定に異常がなければ、候補拒否だけで現在の通常動作を停止しない。

### 14.4 適用シーケンス

| 段階 | 本機能の処理 | 全体確定の扱い |
| --- | --- | --- |
| 候補検証 | 無出力の候補領域で型・範囲・相互条件を検証 | 現行設定を変更しない |
| 安全準備 | BLE接続待機、通常操作禁止、PWM停止、現行準備識別子を確認 | 準備結果を返す |
| 局所反映 | 対象パッケージの自機能部分を切替え、無出力で読戻し | まだ通常操作へ使用しない |
| 局所結果 | 新設定generation、受入成否を返す | 設定管理が他機能と集約 |
| 全体確定 | 全体確定通知を受けた後に現行generationとする | 原子的な全体確定に従う |
| 切戻し | 保存した旧設定へ戻して再検証 | 切戻し成否を返す |

通常適用では、砲塔・砲身の範囲を変える前にPWMを停止する本案とする。設定適用に伴う中央合わせ・端点合わせは実施しない。

切替え・切戻し後は`actuationEpoch`を更新し、開始確認と旧指令を破棄する。新設定の0～1000対応へ旧目標を再解釈して出力しない。

### 14.5 代替設定と失敗

代替候補の選択とパッケージ全体の復元は設定管理が行う。本機能は、渡された直前正常設定または工場出荷設定についても、現在の機構・校正版との整合を再確認する。

過去に有効だった設定でも、サーボ交換・取付変更後に安全とは限らない。整合しない代替を受け付けない。

局所切戻しに失敗した場合はPWM停止と機能利用不可を維持し、設定管理と異常管理へ失敗を返す。片軸だけ新設定のまま通常運転しない。

## 15. 状態通知・ログ・永続情報

### 15.1 利用者向け状態

本機能は、次の状態と理由を状態表示・利用者通知へ提供する。

| 提供状態 | 表示で伝える意味 |
| --- | --- |
| 未準備 | 起動は完了していても、PWM開始準備が必要 |
| 開始準備中 | 操作者が開始した準備処理中。接触しない |
| 操作可能・保持中 | 新しい指令を受け付けられる |
| 指令移動中 | 指令目標へ進行中。実位置測定ではない |
| 指令端到達 | ソフトウェア上の目標が安全端に達した |
| 局所停止中 | 砲塔STOPまたは準備用の停止処理中 |
| PWM停止 | 制御側停止確認の範囲とともに提供 |
| 機能制限 | 制限理由、復旧方式、開始不可理由 |
| 確認不能 | PWM状態・監視・機構条件等が不明 |

実位置値は提供しない。指令位置を表示する場合は「指令目標」「出力指令値」と明示し、情報取得時刻または順序を付ける。

本機能はRGB LEDや7セグ表示を直接制御しない。緊急停止表示と局所故障表示の優先順位は表示管理へ委ねる。

### 15.2 イベントログ

| 事象 | 種別・優先度の本案 | 事象固有情報 |
| --- | --- | --- |
| 初期化・ARM（サーボ動作許可）の開始と結果 | 動作。失敗は異常 | 起動段階、対象軸、禁止理由 |
| 通常動作開始・局所停止 | 動作・通常 | 軸、セッション参照、処理結果 |
| 安全停止・緊急停止の局所結果 | 異常・重要 | 停止識別子、PWM結果、確認範囲 |
| 過負荷・拘束疑い | 異常・重要 | 電流、時間、動作区分、設定版 |
| PWM開始・更新・停止異常 | 異常・重要 | 要求値、読戻し、周期、失敗理由 |
| 周期・監視異常 | 異常・重要 | 最終正常時刻、欠落・遅延 |
| 設定受入・切戻し | 動作。失敗は異常 | パッケージgeneration、検証項目 |
| 機能制限・復旧 | 動作または異常 | 対象異常、要求識別子、結果 |

共通情報には発生元、起動単位、時刻または順序、設定generationおよび関連要求識別子を含める。表の種別・優先度は本機能が提供する事象の意味と重要性を示すものであり、ログ全体の記録優先度、保存方式および容量管理はログ・診断が決定する。具体的なログ識別子はログ機能が付与する。

毎周期の同じ異常や、毎回の同方向継続指令を通常イベントとして大量記録しない。初回、状態変化、解消、回数・最終発生を区別する。

### 15.3 評価用トレース

評価時には、`q_goal`、`q_ref`、`v_ref`、比較値要求・反映値、PWM有効状態、制御周期、電流の品質付き短窓値、動作区分、停止要求と結果を取得する。

本機能は、上記の制御情報を評価用トレースの取得元としてログ・診断へ提供可能とする。通常制御周期10 msに対応して取得可能な情報を提供するが、評価用トレースのバッファ方式、保持件数、1レコード容量、総容量および保存先はログ・診断が管理し、後続のログ・診断基本設計で具体化する。電気安全の1 ms生波形トレースは電気安全側の取得情報とし、本機能が同じ生データを重複して常時保持しない。

異常前後の捕捉はログ・診断からの明示的な評価開始で有効化する。バッファ満杯、記録失敗またはVPS未接続で制御を待たせない。トレース有効時も実行時間を測定し、安全処理への影響がないことを確認する。

### 15.4 永続情報と保存責任

| データ | 管理元・保存要求元 | 本機能の扱い |
| --- | --- | --- |
| 設定パッケージ | 設定管理 | 現行の検証済み設定を使用 |
| 機構・校正・安全プロファイル | 製品情報・校正管理との契約対象 | 妥当性と版を確認 |
| 未復旧異常 | 異常管理 | 検出・原因解消根拠を提供 |
| 緊急停止状態・要因 | 停止管理 | 現在の禁止条件へ従う |
| イベントログ | ログ・診断 | 非同期で事象を提供 |
| 操作指令・軌道・PWM予約 | 本機能のRAMのみ | 再起動・PWM再開用には保存しない |
| ARM（サーボ動作許可）確認情報 | 本機能のRAMのみ | 電源断・停止・失効で破棄 |

本機能固有に、新しい「最後のサーボ位置」の終了時必須保存を追加しない。必要な異常根拠は異常管理の保持対象へ対応付ける。保存主体を未確定のまま安全ログだけで代用しない。

終了時の保存要否問い合わせに対しては、上記分担に従って本機能独自の必須データの有無を返す。他機能が未保存の安全情報を持つ場合、その機能の保存完了まで本機能が代行保証しない。

### 15.5 ログ・通知障害

ログまたは通知が失敗しても、停止・禁止・異常監視を継続する。欠落情報はカウンタで識別し、記録失敗だけで制御状態を正常へ戻さない。

秘密鍵、認証応答、Wi-Fi情報など、本機能に不要な秘密情報をログへ含めない。操作元は必要な内部参照に限定する。

### 16.2 通常操作の配分

砲塔STOPについて、本案では「減速を始めた時刻」だけを操作終了の反映完了としない。**指令軌道が停止し、停止目標の最終PWMが反映された時点**を終了反映の終点として、150 ms以内を確認する。

| 区間 | 配分 | 所有・扱い |
| --- | --- | --- |
| アプリの入力終了検出と即時送信準備 | スマートフォンアプリ側の性能配分で確定 | 本機能は固定値を所有しない |
| BLE送信から本体の検証済み指令引渡し | BLE通信・認証側の性能配分で確定 | 本機能は固定値を所有しない |
| 本機能の次回制御開始まで | 10 ms以内 | 本機能の設計値 |
| 最大指令減速 | 50 ms以内 | 本機能の設計値 |
| 最終PWM反映待ち | 20 ms以内 | 本機能の設計値 |
| 合計 | 150 ms以内 | 公開用システム要求仕様「22. 性能・品質・耐久性」の総合上限 |

STOPは周期送信の次回時刻まで待たず、入力終了で送信する。アプリ・BLE側の具体的な内部配分値は本機能が確定せず、公開用システム要求仕様「22. 性能・品質・耐久性」の150 ms総合要求を満たすようF-01として関係設計で配分し、E-06の結合評価で総合成立性を確認する。

機械的な停止確認時間`T_SETTLE`は、この指令終了反映とは別の確認区間である。実機が許容不能に動き続ける場合、指令応答が150 ms以内であることだけで停止安全を満足とはしない。

通常操作開始は、PWMが開始準備済みの軸について、入力から最初の軌道更新反映までを測定する。D-01の新しいARM（サーボ動作許可）処理を通常操作の応答測定へ隠して含めたり、逆に未準備の操作を実行成功として測定対象から除外したりしない。未準備は明示拒否である。

### 16.3 局所処理の期限

| 処理 | 開始点 → 終点 | 本案の期限 |
| --- | --- | --- |
| 安全・緊急停止の禁止開始 | 本機能への有効要求到着 → 出力禁止処理開始 | 1 ms以内 |
| PWM停止 | 同要求到着 → 最後のパルス終了・次パルス禁止 | 10 ms以内 |
| PWM停止結果 | 同要求到着 → 制御側確認結果の提供 | 20 ms以内 |
| 電気安全の新規出力禁止 | 禁止情報取得 → 新規実行禁止 | 1 ms以内 |
| 初期化・無出力診断 | 必要な設定・電源・監視情報受領 → 局所結果 | 500 ms以内 |
| ARM（サーボ動作許可） | 有効ARM受付 → 制御側完了または失敗 | 2秒以内 |
| 終了・省電力の局所準備 | 有効要求受付 → `powerDownReady`または失敗 | 1秒以内 |
| 設定候補の局所検証・反映 | 各段階要求受領 → 各段階結果 | 各100 ms以内 |
| 局所復旧診断 | 現物確認済み復旧要求 → 無出力診断結果 | 1秒以内 |
| 最大数値目標移動 | 実行開始 → 指令軌道終了 | 計画時間＋余裕、かつ60秒以下 |

位置目標の監視期限は、軌道を計画した時点の所要時間に、次回制御・最終PWM反映・100 msの計算監視余裕を加えて定める。停止確認時間は別に監視する。新しい正常な目標への置換では新しい操作として期限を設定できるが、同じ指令の周期再送で期限を延長しない。

1秒の準備期限は、仮値の50 ms減速、PWM反映、300 ms停止確認、停止・確認を十分に含む内部予算として置く。評価で必要な停止確認時間がこの予算を超えることが判明した場合は、その評価項目内で別の配分へ変更せず、本書または関係設計へフィードバックして改訂する。

これらの期限は、必要なソフトウェア実行が成立する条件での設計値である。CPU全体停止、電源喪失、ハードウェア保護の動作時間を同じ測定として混同せず、独立経路をE-06で評価する。

### 16.4 処理実行と負荷

#### 処理の優先順位

次の順に処理を優先する。

1. 安全イベントによる出力禁止
2. 制御・電流情報の局所監視
3. 通常指令の取込み
4. ログ・通知

実装がRTOSか周期スケジューラかにかかわらず、この先行関係を維持する。

#### 共通の実行時間と本機能内の配分

10 ms周期の通常制御には、本体ソフトアーキテクチャ基本設計の8.5節で定める、共通の`Process`実行時間を適用する。

| 区分 | 実行時間 |
| --- | --- |
| 通常の設計目標 | 0.5 ms以下 |
| 原則上限 | 1.0 ms以下 |

これらは、本機能独自の仮の時間配分ではなく、本体ソフトウェアの実行方式に共通する条件である。
軌道計算、監視、PWM出力の確定など、本機能内の処理への時間配分は、この共通の範囲内で詳細設計する。

詳細設計だけで、1.0 msの原則上限を緩和しない。
実行時間を超過した場合も、単純に次周期へ繰り越して指令を溜めない。

#### 正常進行の確認に使用する情報

通常制御に必要な一周期、または定めた処理区間を正常に完了した時点で、`controlProgressSeq`を更新する。
単にタスクが起動されたことや、関数の入口へ到達したことを、正常完了とはしない。

システム監視経路は、次の情報を用いて、現在のシステム状態で必要な砲塔・砲身制御が正常に進行していることを確認する。

- `controlProgressSeq`による進行情報
- 正常完了時刻

#### 共通の進行監視と安全処理への連携

進行監視には、本体ソフトアーキテクチャ基本設計の14.5節で定める次の共通値を適用する。

| 項目 | 共通値 |
| --- | --- |
| システム監視の周期 | 10 ms |
| 10 ms周期の重要な`Process`について、正常進行の停止を異常候補とする時間 | 30 ms |

安全要求を開始する経路は、本体ソフトアーキテクチャ基本設計の`SystemMonitor`／`Safety`経路と、停止・緊急停止管理および異常管理の連携方式に従う。
本機能だけで、これらと別の共通監視値を設けない。

砲塔・砲身の出力をIWDTリセットより早く禁止する必要がある場合は、システム監視から安全関連経路へ、出力禁止・停止要求を直接開始できる構成とする。
共通の30 msより厳しい砲塔・砲身固有の期限が必要となった場合に限り、本書の基本設計値として追加する。

#### PWM出力の確定中に行う処理

PWM制御の世代確認と書込みを一体として扱う区間（不可分区間）は、最小限にする。
ログ整形、通信、保存および軌道計算を、停止入力を遮断する区間へ含めない。

平方根を含む軌道計算は、PWM出力を確定する不可分区間より前に行う。
軌道計算の途中でも、停止要求によって割り込める構成とする。

### 16.5 資源と滞留防止

通常指令は軸別1件、停止・禁止はラッチと要求結果表で管理する。軌道は定数個の区間だけを持ち、操作時間に比例して記憶量が増える構成にしない。

要求結果は、未完了の安全要求を容量不足によって黙って破棄せず、要求識別子との対応を維持できる有界な静的資源で管理する。容量不足が発生しても安全出力禁止を優先し、結果相関を維持できない場合は停止管理へその事実を報告する。

要求結果表の具体的な保持件数、制御データのメモリ上限、保持期限、再利用方式および静的メモリ配置は詳細設計で定める。操作時間や受信件数に比例して無制限にメモリ使用量が増える構成にはしない。容量不足を理由として既に完了した停止状態を解除しない。

### 16.6 低消費電力移行時の制御・監視引継ぎ

通常の10 ms制御と、その制御を対象とするシステム進行監視を通常動作対象から外せるのは、電源・省電力管理の移行コミットに同期した、次の条件がすべて成立する場合だけとする。

| 条件 | 確認内容 |
| --- | --- |
| 操作終了 | 両軸指令・軌道・出力予約が失効している |
| PWM停止 | 現時点で禁止・停止維持を確認できる |
| 電源 | `PWR_SERVO`が既知のOFFである |
| 安全維持 | クロック停止・復帰中もPWM端子・ゲートが禁止を維持する |
| 監視引継ぎ | 電源・省電力管理・電気安全・停止管理の必要な低消費電力監視と入力経路が成立している |
| 相関 | 制御休止の準備結果とコミット許可が現在の移行識別子に対応する |

移行準備中は通常制御と、その正常進行を対象とするシステム監視を継続する。本機能は制御休止準備結果を電源・省電力管理へ返し、電源・省電力管理の移行コミットと整合する時点で、周期制御を意図的休止へ切り替え、その状態をシステム監視経路へ同じ移行識別子とともに提供する。単に制御が進まなくなったことを「省電力のはず」と推定しない。

サーボ系統を通電維持する縮退では、この休止条件は成立しない。必要な電流監視、出力禁止維持確認および通常の処理監視を続ける。必要な実行資源を残せない場合は、本機能から当該縮退モードの準備正常完了を返さない。

復帰時は、PWM禁止を維持したままタイマ・設定・局所監視を再初期化する。通常制御が一回正常完了して新しい`controlProgressSeq`を提供した時点を新しい進行監視の起点とし、休止前の進行世代や最終正常時刻を復帰後の期限判定へ流用しない。この再確立を確認するまでPWM開始を許可しない。

引継ぎが取り消された場合は休止せず、既に休止した場合は無出力で再確立する。どちらの場合も過去のPWMを復元しない。引継ぎ結果が不明な場合は安全な休止成立とせず、電源・省電力管理へ失敗を返す。具体的な実行基盤への割付けはF-04として関係設計へ反映する。

### 17.5 拘束検出時間の評価

過負荷成立から停止要求までだけでなく、**物理的な拘束開始から最後のPWMおよび必要な電源遮断まで**を測定する。測定には電流フィルタの遅れ、機能判定時間、制御位相、停止通知、サーボ内部の無信号時挙動を含める。

始動・反転の200 ms区間で拘束が発生した場合、区間終了後の判定100 msだけを検出時間として報告しない。機構・サーボ・配線の損傷や危険な押付けが発生するより前に保護できる時間配分であることを確認する。

許容時間を確保できないことが判明した場合は、当該評価項目内で別方式へ切り替えず、関係設計へフィードバックして本基本設計を改訂する。既存電気保護があることだけで、機械的拘束への応答が十分とはみなさない。

### 17.6 評価記録と判定

試験ごとに、基準コミット、ファームウェア版、設定generation、サーボ現物、機構・校正版、電源条件、姿勢、負荷、計測器、測定点、試験手順および結果を記録する。

結果は合格、不合格、条件付き成立、未確認を区別する。暫定値での合格は、その構成と条件に限る。一般使用を許可する安全プロファイルには、未確認の基本安全項目を残さない。

## 19. 設計判断・後続事項

### 19.1 設計判断

基本方式は本基本設計で決定し、未確定の数値は実機評価によってその方式が成立する値として確定する。評価で設計前提に反する事実が判明した場合は、評価項目の中で別方式へ逃がさず、本基本設計または関係設計へフィードバックして改訂する。

未確定の数値のうち、安全可動範囲、PWM開始・停止、通常動作速度、停止確認、ARM完了、過負荷・拘束判定、操作可否その他のユースケース上の振る舞いを決める値は、「基本設計で管理し、評価結果を基に確定する値」とする。E-01～E-08で値を測定・評価しただけでは基本設計確定とせず、採用する正式値または評価済み許容範囲を本基本設計へ反映した時点で確定とする。詳細設計では、これらの意味・判定・外部挙動を変えない内部実装だけを具体化する。

#### D-01 初回PWMと再開の方式【採用済み】

**設計判断：** 第9章の`MANUAL_DATUM_ARM`（手動基準合わせ後のARM＝サーボ動作許可）を、初回PWM開始およびPWM停止後の再開方式として採用する。

主電源OFFで安全に基準合わせできる機構と、アプリからの明示的なARM（サーボ動作許可）操作を使用する。起動処理では位置合わせのための自動移動を行わず、ARM完了後も新しい通常指令を待つ。

**成立確認方針：** E-01で、採用サーボ・機構について無駆動の基準合わせ、基準合わせ誤差、初回PWM開始、ARM確認時間および誤操作時の挙動が安全に成立することを確認する。固定中央パルスや過去位置を開始位置として自動出力する方式は採用しない。

**影響：** スマートフォンのARM（サーボ動作許可）操作、機構の合わせ位置、校正情報、再接続・復帰の操作手順。これらはF-06として関連設計へ反映する。

**未確定事項：** 方式そのものは確定済みとする。`q_seed`、基準合わせ許容差、`T_ARM_SETTLE`などの実機依存値はE-01・E-08で確定する。

### 20.5 F-04 制御進行監視と停止実行経路

**対象：** 異常管理の処理停止・期限監視、電源・省電力管理のIWDT更新条件、システムアーキテクチャの安全処理・システム監視、停止・緊急停止管理の停止要求受付・完了監視、および本書第12・16章。

**問題・確認点：** 制御処理自身が自身の停止だけを監視する構成では、その処理が停止した場合の検出を説明できない。
一方、本機能だけでシステム監視周期・停止判定時間を固定すると、他の重要周期処理やIWDTとの全体設計を分断する。

**影響：** 制御周期異常の未検出、通常処理の滞留によるPWM停止遅延、個別機能のIWDT更新によるシステム故障の隠蔽。

#### 基本設計へ反映済みの方式と共通条件

異常管理と電源・省電力管理には、次の方式を反映済みである。

1. 重要周期処理は、正常な処理区間を完了した時点で、チェックポイント／alive／進行情報を更新する。
2. その処理とは独立したシステム監視経路が、更新された情報を確認する。
3. 確認結果を、IWDT更新許可条件へ連携する。

共通条件は、本体ソフトアーキテクチャ基本設計で、次のとおり確定済みである。

| 項目 | 確定済みの共通条件 |
| --- | --- |
| `SystemMonitor`の周期 | 10 ms |
| 10 ms周期の重要な`Process`について、正常進行の停止を異常候補とする時間 | 30 ms |
| `Process`が連続してCPUを使用する時間 | 0.5 msを目標、1.0 msを原則上限とする |

関連する設計の役割は、次のとおりとする。

| 設計 | 役割 |
| --- | --- |
| 本体ソフトアーキテクチャ基本設計 | 共通の実行時間・監視条件を定める |
| インターフェース・通信基本設計 | 機能間で共通して守る連携方式を定める |
| 性能・品質・検証基本設計 | 最大負荷、最悪実行時間（WCET）および正常進行の停止検出が成立することを評価する |

#### 本機能が提供する情報と守る条件

本機能は、正常完了時だけ`controlProgressSeq`を更新し、`ControlProgressCheckpoint`としてシステム監視へ提供する。
本機能へIWDTの更新権限を追加せず、共通値を独自に再定義しない。

低消費電力中は、第16.6節で定める意図的な制御休止と、復帰時の制御・監視の再確立を、移行識別子と対応付ける。

#### 詳細設計・評価で確認する残作業

本体ソフトアーキテクチャ基本設計／インターフェース・通信基本設計／性能・品質・検証基本設計への基本設計反映は完了しているが、次は詳細設計・評価事項として残る。

- チェックポイントの具体的なデータ配置
- 10 ms周期の実行時刻のばらつき
- 処理の進行を意図的に停止させ、30 msの異常候補判定を確認する試験
- 最大負荷時にも安全処理が成立することの確認

### 20.6 F-05 安全プロファイルと設定パッケージ全体確定

**対象：** 設定管理基本設計・製品情報／校正情報管理設計。根拠は公開用システム要求仕様「13. 設定管理」 §13.4～13.8・13.11とシステムアーキテクチャの情報の管理原則。

**問題・確認点：** 運用設定だけでは、採用サーボ・機構・校正・評価済み限界の組合せを判定できない。局所受入れと設定パッケージ全体確定の応答も区別する必要がある。

**影響：** 未評価のPWM範囲拡大、交換後の旧校正使用、部分適用、設定変更時の意図しない再移動。

**反映内容・状況：** 設定管理では設定パッケージ全体のPREPARE→APPLY→永続ACTIVE確定→GLOBAL_COMMITと、失敗時ROLLBACK、部分適用禁止を反映済みである。schemaVersion 1には本機能の未評価な仮値・校正値を含めず、砲塔・砲身REMOTE_MANAGED項目は実機評価で正式factory valueと評価済み変更範囲が確定した場合だけ新schemaVersionとして追加する。本書側は第14章の安全プロファイル、拡大禁止範囲、PWM停止後の適用、全体確定通知、切戻しで旧目標・開始確認を失効する契約を維持する。製品・校正情報の具体的な管理元と保存方式は関連設計で残る。

### 20.7 F-06 ARM（サーボ動作許可）の操作・機構設計への反映

**対象：** 将来のスマートフォンアプリ基本設計、システム構成の機構・サーボ構成、必要に応じて公開用システム要求仕様「04. スマートフォンアプリ」 §4.8および公開用システム要求仕様「08. 砲塔・砲身制御」 §8.6・8.11。

**問題・確認点：** 第9章でARM（サーボ動作許可）を開始方式として採用したため、画面・操作手順・機構上の基準位置を、砲塔・砲身制御の内部実装だけでなく関連設計へ反映する必要がある。

**影響：** 基準合わせの作業、開始確認、再起動・省電力・安全停止後の再操作手順、対象軸の表示。

**反映内容：** 無駆動で安全に合わせる手順、開始時に動き得ることの表示、一回限りのARM確認、新しい通常指令待ちをスマートフォンアプリおよび機構設計へ反映する。公開要求への追記が必要かは要求とのトレーサビリティ確認で判断し、必要な場合は要求変更として正式にフィードバックする。
